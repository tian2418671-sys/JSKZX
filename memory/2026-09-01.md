## 一、导入时忽略卡片自带标签（sanitizeImportedTags）被绕过

### 问题现象
开启「导入时忽略卡片自带标签」后，被忽略的杂乱原生标签仍在**部分界面/搜索**中出现，功能"时灵时不灵"。

### 根因
开关只在导入路径生效，但**显示/搜索点未接入**——配置在某处生效、其他消费点被绕过：
- `SidebarPanel.vue`（列表标签显示）直接合并原生 `data.tags`
- `App.vue` `activeCardTags`（激活卡标签）直接合并原生 `data.tags`
- `useSearch.js`（标签搜索）`extractCardTags` 不过滤原生 tags
- `searchIndex.js`（搜索索引构建）`indexTagsFn` 不过滤原生 tags

### 修复
统一 4 个绕过点：显示/搜索/索引全部 `ignoreNative` 判定。
- `useSearch.js` `extractCardTags(item, { ignoreNative = false })`
- 4 处调用点全部传入 `sanitizeImportedTags.value`

### 防再犯要点（排查清单）
> **凡是「配置开关」，必须全链路排查所有消费点**（显示 / 搜索 / 索引 / 统计 / 导出），
> 不能只看定义和开关 UI。grep 开关名 → 逐个验证消费点。

## 二、向量模型无效（阈值 0.65 长文 vs 短标签命中率≈0）

### 问题现象
本地向量匹配（第二层）几乎 0 命中，等于没启用。

### 根因（实测）
- `paraphrase-multilingual-MiniLM-L12-v2` 下，**长卡片文本 vs 1-2 词短标签**的余弦相似度被压到 0.2~0.5，永远够不到原阈值 0.65
- 短标签直接嵌入方向差大 → 绝对相似度低

### 修复
1. 默认阈值 **0.65 → 0.35**（三处对齐：`useAITools.js` / `AITagModal.vue` / `vectorManager.js DEFAULT_THRESHOLD`）
2. **标签展开**：短标签展开为描述句再嵌入 —— `LABEL_TEMPLATE = '这是一个关于{label}的故事'`
   - 展开文本同时作为**缓存 hash 输入**（模板变化 → hash 变 → 缓存自动重建，不会用旧向量）
3. 实测：展开后 0.35 命中率 80%（强相关），误报基线最高 0.307，0.35 安全

### 防再犯要点
> **语义匹配的阈值必须按"真实文本形态"验证**：长文 vs 短词的绝对相似度远低于长文 vs 长文。
> 改阈值/改模板后必须重跑 `scripts/vector-model-test.cjs` 确认命中率与误报基线。
> 相关参数（阈值 / TopK / 模板）在 **前端组件、composable、主进程 manager 三处必须对齐**。

## 三、三层漏斗互斥（规则命中跳过向量层）

### 问题现象
「实际使用时一直规则命中」——规则层命中后直接跳过向量层，向量模型永远用不上，规则和向量不协同。

### 根因
漏斗逻辑把两层做成**互斥**：`ruleHitIds`（规则命中）不进向量层。

### 修复（useAITools.js）
- 规则命中卡 **仍进向量层**做语义补充：`vectorTargetIds = [...rulePassedIds, ...ruleHitIds]`
- 规则 + 向量都未命中 → 才交 LLM 兜底
- 向量层清空 `llmTargetIds` 后重建时，用 `rulePassedSet` 精确判定「规则未命中且向量未命中」才进 LLM

### 防再犯要点
> **多阶段漏斗应是「协同」而非「互斥短路」**：前一阶段命中 ≠ 后续阶段跳过，
> 除非业务明确要求短路。排查所有 `if (命中) { ... return; }` 是否真的该短路。
> 关键验证点：`vectorManager.batchMatch` 对**每张传入卡都返回 result**（未命中返回 `tags: []`），
> 因此前端按 results 重建 llmTargetIds 不会丢卡——这个契约不能破坏。

## 四、字号滑块卡顿（全局响应式每帧更新）

### 问题现象
「界面 UI 字号 / 工作区编辑字号」两个滑块拖动时整个界面卡顿、不丝滑。

### 根因
滑块直接 `v-model` 绑定全局 `appSettings` → 每个 `input` 事件：
1. 触发 `App.vue` 两个 `watch(appSettings, {deep:true})` → 每帧写 `localStorage`
2. 更新 `documentElement` 的 `--ui-fs` / `--workspace-fs` CSS 变量
3. 全局大量 `font-size: var(--ui-fs) !important` → **整个界面每帧 reflow/repaint**

### 修复（HeaderBar.vue）
**草稿值 + 松手提交**模式：
- 滑块绑定本地 `uiFontSizeDraft` / `fontSizeDraft`（拖动只更新滑块 + 旁边数字，零全局副作用）
- `@change`（松手）才提交到全局 `appSettings` → 全局字号生效 + 持久化各只触发一次
- `watch` 外部变更（重置按钮）同步草稿值

### 防再犯要点
> **凡绑定到「全局响应式 + 影响全页面样式/布局」的输入，禁止直接 v-model 到全局 ref**。
> 用草稿值 + 松手提交（或防抖）。排查 `v-model` 绑定 `appSettings/viewOptions/...` 的高频控件。
> 已确认安全的：`AITagModal.vue` 阈值滑块是受控组件（`:value` + `@input` emit）✅；
> `snapshotConfig` 是 `<select>` 低频 ✅。

## 五、子文件夹卡片覆盖层恢复被跳过（标签重启消失）★核心

### 问题现象
AI 打标/手动打标完成后**重启应用，标签消失**。

### 根因（层层定位）
库目录下大量卡片在**子文件夹**（分组 = 物理子文件夹，如剧情卡/科幻/恋爱/修仙/NTR…）。
加载时 `useCardCrud.js` `processAutoTagsAndCategory`：
```js
if (cardInfo.subFolder) {
    cardInfo.category = ...;  // 只设分类
    return;                    // ⚠️ 直接 return，跳过覆盖层恢复
}
```
`subFolder` 分支只处理分类就返回 → **`customTags` 永不恢复**。
标签确实已写入覆盖层（`app_config.json` 实测 66 条有标签数据），但重启后按新 path 找不到 → 丢失。
若再开「导入时忽略卡片自带标签」，连原生 tags 显示都被滤掉 → 完全看不见。

### 修复（useCardCrud.js）
- `subFolder` 分支不再裸 return：**物理文件夹只管分类，标签仍按覆盖层恢复**（与根目录分支同口径）

### 加固（防"防抖没落盘"类丢失）
1. `persistCardUpdate`：`saveCard` 物理写盘失败（快照失败/PNG 异常/文件缺失）时，
   **立即强制 `syncConfigToDisk()`**（不走 500ms 防抖）落盘覆盖层
2. `useAITools.js`：AI 打标全部完成（扫尾）时**强制立即 `syncConfigToDisk()`** 一次
   —— 不依赖 500ms 防抖 + `beforeunload`（注释自认"尽力而为，极端可能来不及"）

### 防再犯要点
> **加载/恢复函数里的每一个早期 `return` 都要问：它是否跳过了本应执行的恢复逻辑？**
> `processAutoTagsAndCategory` 的优先级链：subFolder → 覆盖层 → importedConfig → localCategoryMap → 自动规则，
> 每层都要完整恢复「分类 + 标签」两个维度（除非该层确实只管一个维度）。
> **凡是用户主动打标的数据，必须三保险**：内存 + 覆盖层（app_config.json）+ PNG 物理写回。

## 六、分组重命名覆盖层 key 不迁移（标签丢失）★同类排查新增

### 问题现象（排查"类似问题"时发现）
分组重命名 = 物理重命名文件夹 → 子卡 `path` 变化（`...\旧组名\xxx.png` → `...\新组名\xxx.png`），
但覆盖层 key 仍是旧路径 → `refreshLibrary()` 后按新 path 找不到覆盖层 → 子文件夹卡标签丢失。
与 bug 五**完全同源**（覆盖层恢复失效）。

### 根因
`migrateOverlayKey` 只在 `moveCardToGroup`（单卡移动）时调用；`renameCurrentCategory`（分组重命名）
**没有批量迁移**该分组下所有卡的覆盖层 key。

### 修复（useCardGroups.js）
`renameCurrentCategory` 物理重命名成功、`refreshLibrary()` 之前：
- 遍历 `appConfig.cardOverlays`，把 `旧目录前缀` 的 key 批量迁移到 `新目录前缀`（`key.startsWith(oldPrefix + '\\')`）
- 迁移后立即 `syncConfigToDisk()`

### 防再犯要点
> **凡"物理路径会变"的操作（移动/重命名分组/移动文件），必须同步迁移覆盖层 key**：
> - 单卡移动 → `migrateOverlayKey` ✅
> - 分组重命名 → 批量前缀迁移（本次修复）✅
> - 世界书重命名 → `migrateWbCategoryKey` ✅
> - 分组删除 → 不移动文件，无需迁移 ✅
> 排查清单：grep `cardOverlays[` 的所有写入/读取，确认 key 的来源与变更点一致。
