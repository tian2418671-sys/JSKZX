## 0. 前置：一条命令自查（每次发版第一件事）

```powershell
node scripts/release-check.mjs                                  # 语法 + 单测 + 构建 + 文档一致性 + git 状态（约 30s）
node scripts/release-check.mjs --e2e dev  --port 9338           # 另加：大库重复卡 + 正则探针 + 测卡引擎（需 dev 实例）
node scripts/release-check.mjs --e2e prod --port 9333           # 另加：测卡侧栏端到端（需生产构建实例）
```

**判定**：必须看到 `✅ 无阻塞项，可进入打包`（⚠️ 只算提醒，例如工作区未提交、端到端数据条件跳过）。

### 端到端实例怎么起（配置用隔离 profile，**卡库用真实库**）

> ⚠️ **只隔离配置，不隔离卡库** —— 见 [`AI交接指导.md`](../../AI交接指导.md) 铁律 9：
> **读操作**（扫描 / 搜索 / 索引 / 渲染 / 统计）必须跑**真实库**；**写操作**（改标签 / 删卡 / 保存 / 移动）才用隔离库。

```powershell
# ① dev 实例（大库，端口 9338）
npx vite --port 5173
$p="$env:TEMP\jsk-rel-profile"; Remove-Item $p -Recurse -Force -EA SilentlyContinue; New-Item -ItemType Directory -Force -Path $p | Out-Null
Copy-Item "$env:APPDATA\sillytavern-card-manager\app_config.json","$env:APPDATA\sillytavern-card-manager\tavern_manager_config.json" $p
# 把 lastFolder 改成 I:\03\角色色卡（或用你当前库）—— 这一步指向的就是**真实库**
$env:VITE_DEV_SERVER_URL='http://localhost:5173'
.\node_modules\electron\dist\electron.exe . --disable-gpu --remote-debugging-port=9338 --user-data-dir=$p

# ② 生产构建实例（端口 9333）：去掉 $env:VITE_DEV_SERVER_URL，改用 npm run build:web 的产物
```

> 📌 **为什么配置要隔离**：`app_config.json` 里是用户的收藏夹 / 分组 / 标签 / 打标规则 / 覆盖层配置 ——
> 用真实配置会让端到端脚本的写入污染用户数据。**卡库目录只读**，不受影响。

> 端到端脚本对**数据有依赖**，属正常：
> - 库里有带世界书徽标（🌍）的卡才会跑世界书注入断言；否则打印「世界书注入断言无对象，已跳过」而**不算失败**；
> - 卡片内容里的外链图片会被应用 CSP 拦截（`img-src` 不放行 http(s)，防追踪像素）——脚本单列 `cspImgBlocked`，不计入错误。

## 2. 打包

```powershell
npm run build:web        # 只构建渲染层（web/）
npm run build            # = build:web + electron-builder -w
```

**本项目实发推荐（避开两个已知坑）**：

```powershell
# ① 先杀掉占用打包旧产物的进程（否则 EPERM rmdir onnxruntime-node\lib）
Get-Process | Where-Object { $_.Path -like '*win-unpacked*' -or $_.Path -like '*dist_new*' -or $_.ProcessName -eq 'electron' } | Stop-Process -Force -EA SilentlyContinue

# ② 离线打包到独立输出目录（复用本地 Electron，避免重复下载）
$env:ELECTRON_BUILDER_OFFLINE='true'
npx electron-builder -w --config.electronDist="$PWD\node_modules\electron\dist" --config.directories.output=dist_new
```

产物在 `dist_new/`：

| 文件 | 用途 | 核对点 |
|---|---|---|
| `sillytavern-card-manager-<ver>.exe` | 安装包 | 大小与上一版接近（±10MB 正常） |
| `latest.yml` | **OTA 必需** | `version:` 必须是本次版本；`sha512` / `size` 与 exe **完全一致** |
| `<ver>.exe.blockmap` | 差分更新（可选但有更好） | 与 exe 同名同版本 |
| `<ver>.zip` | 绿色版 | 体积通常大于 exe |
| `win-unpacked/` | 中间产物，**不必上传** | 可随时删 |

> ⚠️ 打包脚本务必**写日志文件**（终端输出可能被吞）并在结束时打印产物清单；
> 临时 `.ps1` 一律**纯 ASCII**（BOM-less 脚本含中文会乱码），用通配符定位中文文件名。

## 3. 产物校验（OTA 静默失败的唯一防线）

| 校验 | 判据 |
|---|---|
| `latest.yml` 版本号 | `version:` == 本次版本 |
| `latest.yml` 的 `size` / `sha512` | 与 exe **实测值完全一致**（sha512 为 base64） |
| blockmap | 与 exe 同名同版本，存在 |
| asar 内容 | 含**本次构建的哈希文件名**（如 `web/assets/index-<hash>.js`） |

```powershell
# sha512 → base64 的正确算法
$h   = (Get-FileHash -LiteralPath $exe -Algorithm SHA512).Hash
$b64 = [Convert]::ToBase64String((0..($h.Length/2-1) | ForEach-Object { [Convert]::ToByte($h.Substring($_*2,2),16) }))
```

⚠️ **打包内容验证别用函数名当探针** —— 渲染进程 bundle 会压缩混淆掉函数名。
要用**压缩后仍保留的字符串字面量 / 动态属性名**（如 `[slim]`、`jsHeapSizeLimit`、`_descShort`、`_hasBook`），
或直接比对 asar 内是否含**新构建的哈希文件名**。

## 4. 装包自测（必做）

在**干净 profile**（`--user-data-dir=%TEMP%\jsk-smoke-profile`）与**真实 profile**各试一次：

| 检查 | 期望 |
|---|---|
| 启动 | 无 `[Vue 错误]`，`crash.log`（`userData/crash.log`）无新增 |
| 打开大库（11,186 卡） | 卡片数正确；首屏在合理区间（16~43s，机器负载敏感）；无崩溃 |
| 升级场景（装过旧版） | 启动日志出现一次 `[embed-cache] 已回收遗留缓存 N 个文件 / X MB`（v2.2.3 遗留缓存的一次性迁移，属预期） |
| `%APPDATA%\sillytavern-card-manager\` | **无** `embed_cache_*`；用过测卡后有 `chat_store.json` / `memory_store.json` |
| 测卡 | 开卡 → 聊天测试：7 分区都能打开；「设置」分区记忆库显示条数（首装 0），可刷新 / 二次确认清空 |
| 正则 / 状态栏 | 新增一条 → 列表**立即** +1（无需切 Tab）；删除 → 弹**原生**确认框，取消不删、确定立即消失 |
| 刷新 / 搜索 | 连点刷新 5~10 次：卡片数不变，列表与库层都不出现重复卡 |
| 内存 | 连点刷新后堆峰值 < 3.5GB；`crash.log` 无新增行 |

> ⚠️ **不要从 VS Code 终端直接启动打包后的 GUI 应用**：它会继承该终端控制台，终端一旦 `^C` 应用被连坐杀死。
> 要验证存活状态请**另起一条命令**；`Start-Process` 的 stdout / stderr **不能重定向到同一文件**。

## 5. 提交与打 tag

```powershell
git status --porcelain            # 应为空（release-check 会提醒）
git add -A
git commit -m "release: vX.Y.Z …"  # 中文提交信息建议用 -F 消息文件，避免长单行命令被终端 ^C
git tag vX.Y.Z
git push origin master --tags
```

**本机网络注意**：直连 GitHub 会**间歇性**失败（`Empty reply from server` / `Could not connect …:443`），
且**tag 推成功不代表 master 也推成功**（两次独立事务）。做法：

```powershell
git -c http.proxy= -c https.proxy= push origin master    # 清空代理
# 失败就重试（循环 6 次、间隔 8s），最后用 git status -sb 确认不再 ahead
```

## 6. GitHub Release（`tian2418671-sys/JSKZX`）

上传**全部**：`sillytavern-card-manager-<ver>.exe` + **`latest.yml`** + `<ver>.exe.blockmap`（+ zip 绿色版）。

```powershell
gh release create vX.Y.Z --title "vX.Y.Z" --notes-file "$env:TEMP\jsk-notes-X.Y.Z.md" `
  "dist_new\sillytavern-card-manager-X.Y.Z.exe" "dist_new\latest.yml" `
  "dist_new\sillytavern-card-manager-X.Y.Z.exe.blockmap" "dist_new\sillytavern-card-manager-X.Y.Z.zip"
```

- **正文用 `--notes-file` 从 `RELEASE_NOTES.md` 抽取该版本段**（不要手抄）。
  抽取脚本要点：用**仅 ASCII 的正则**（`^## `）定位版本段，写到 `%TEMP%` 下的 ASCII 路径。
- 标题沿用**纯版本号**（`vX.Y.Z`），避免中文参数的编码问题。
- 覆盖发布：`gh release delete-asset` 删旧 → `gh release upload --clobber`。
- **`gh release` 无输出 = 正在后台上传**（大文件），不要中断。
- `--jq` **只接受一个输出表达式**；`gh release view --json` **没有 `isLatest`**，用 `gh release list` 看。

## 7. OTA 验证

| 检查 | 命令 / 判据 |
|---|---|
| 该版本是 Latest | `gh release list --limit 3` → 本次版本标注 `Latest` |
| 更新清单可达 | `Invoke-WebRequest https://github.com/tian2418671-sys/JSKZX/releases/latest/download/latest.yml -UseBasicParsing` → **200** 且 `version:` 为本次版本、`size`/`sha512` 与本地一致 |
| 安装包可达 | 对 `releases/latest/download/sillytavern-card-manager-X.Y.Z.exe` 发 `HEAD` → **200** + `Content-Length` 与本地一致 |
| 真机 | 在**上一版客户端**点「检查更新」应提示新版本 |

> PS 5.1 的 `Invoke-WebRequest` 必须加 `-UseBasicParsing`（否则弹安全确认）；`Content` 可能是 `byte[]`，需 `[Text.Encoding]::UTF8.GetString()`。

## 8. 回滚

| 时机 | 做法 |
