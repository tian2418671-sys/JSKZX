### 3.3 管线顺序（逐条对照，勿漏）

1. `fullMacros` = `mergePluginMacros(插件宏, buildMacroContext(卡, 用户名, 人设, lastUserActivity))`
2. 用户输入 → `applyMacros` → `applyRegexScripts(…, 'USER', …)` → push 为 user 消息
3. `collectActivatedWbText(最后一条用户消息)`：常驻/触发词命中 → EJS 渲染 → 宏替换 → 按 `position`/`insertion_order` 排序
4. `buildPayload`：预设模式（`buildPresetMessages` + `collectPluginSystemPrompts` + 记忆 + 人设）；无预设 → 经典兜底
5. 历史 assistant 消息走 `applyRegexScripts(…, 'AI', …, { promptOnlyExclusive: true })`
6. `requestReply`：`sendChatMessage` → `replyToSwipe` → `⚠` 占位短路 → `processAiReplyVars`(MVU) → `applyRegexScripts(…, 'AI', …)`
7. 多候选 `replyCount` 次；**MVU 只对首条候选 `applyVars=true`**（防 add 双重累加）
8. 发送后 `recordMessage` + `extractFacts`→`recordFact`；`persistMessages` 落会话
9. Swipe：`moreSwipe`(追加) / `regenerateSwipe`(整组改写) / `continueSwipe`(`[continue]` 续写)
10. 渲染：`segmentMessage` → `promoteHtmlSegments` → `ChatPanelSeg`（文本段 `renderChatHtml`；HTML 段 sandbox iframe + 高度 postMessage）
11. `{{idle_duration}}` 基准 = `lastUserActivity`（每次发用户消息刷新）

### 🐞 实测中发现并修复的三个真实缺陷

**① `ChatTestSidebar` 渲染中断（点「插件」分区时整个测卡 Tab 被卸载）**

- 现象：主进程刷屏 `[Vue 错误] ChatTestSidebar | Cannot read properties of undefined (reading 'length')`。
- 根因：模板里对来源不可信的列表直接取 `.length`；props 虽有 default，
  但 `v-for` 源为 `undefined` 不报错、而插值/`v-if` 里的 `.length` 会抛错，渲染期一抛即中断组件。
- 修复：新增 `arr(v)` / `objKeys(v)` 兜底，模板 20 处列表访问全部改用它；`varRows` 加对象类型兜底。
- 防回归：侧栏 e2e 增加「每区点击后抽屉必须存活 + 特征词必须命中」断言。

**② 读存储的 `computed` 永久缓存（选了预设，引擎永远读不到）**

- 现象：侧栏选预设后 localStorage 已写入 259KB，但引擎 `activePreset` 恒为 `null`，
  预设装配分支永远走不到（静默失效，无任何报错）。
- 根因：`computed(() => loadActivePreset())` 的 getter 读的是**同步非响应式**存储，
  Vue 认为它没有依赖 → **首次求值后永久缓存**。（`plugins` 同病。）
- 修复：`chatStorage` 每次写入/hydrate bump 响应式 `chatStorageVersion`；
  读存储的 computed 先 `void chatStorageVersion.value` 建立依赖（引擎与侧栏各一处）。
- 防回归：`test/chatStorage.test.mjs` 新增 4 例，含**反例断言**（无依赖的 computed 确实读不到变更），
  把这个坑的机理钉死在测试里。

**③ 测试自身的模块实例陷阱（记录以免后人再踩）**

- CDP 里 `import('/js/composables/chat/useChatPresets.js')` 会**另建一份模块实例**，
  其 `chatStorage` 与应用模块图里的那份是两个独立 Map →「测试里存上了、引擎读不到」。
- 诊断特征：同一实例内 `loadActivePreset()` 有值、引擎 `activePreset.value` 为 `null`。
- 正确做法：端到端测试一律**驱动真实 UI**（如从侧栏下拉选预设），不要自己 import 引擎模块。

## 六、二期落地：长期记忆通道（2026-09-13）

移动版长期记忆走 Android 原生 `MemoryPlugin`（内置 SQLite）；桌面版过去只有 `chatBridge` 的**失败桩**，
开关能存但检索恒为空（侧栏明确标注）。本次按同套契约补齐：

| 层 | 交付 |
|---|---|
| 存储 | `main/memoryStore.js`（CommonJS）：`add/update/remove/clear/list/search/stats`；数据 `{v:1, items:[{id,type,content,key,cardName,ts}]}`；`type` = message(L1) / summary(L2) / fact(L3) |
| 落盘 | `userData/memory_store.json`，走既有 `atomicWriteJson`（EPERM 重试）；存储层内部**串行化**写，不并发覆盖 |
| IPC | `memory:add / update / remove / clear / list / search / stats`（懒加载单例 + 统一异常包装） |
| 暴露 | `preload.js` 6+1 个方法；`chatBridge` 的 `MEMORY_METHODS` 同步加入 `memoryStats`（非 Electron 环境仍走桩） |
| UI | 侧栏「设置」分区：记忆库状态（总条数 + 事实/摘要/消息分类）+ 刷新 + 两段式二次确认清空 |

**策略要点**（与移动版语义对齐）
- **去重合并**：同 `(type, key, content, cardName)` 只刷新时间戳（避免「用户反复说同一句」写成几十行）；
- **按类型修剪**：每个 `type` 保留最新 500 条（默认，可配置），超出淘汰最旧；
- **长度限制**：content 4KB / key 200B / cardName 200B；
- **检索**：中文 2-gram + 英文词切分，按「命中率 × 类型权重（fact 3 / summary 2 / message 1）+ 时间新鲜度」排序；空查询退化为「最近 N 条」；
- **返回值一律是副本**（调用方改写不会污染存储）。
