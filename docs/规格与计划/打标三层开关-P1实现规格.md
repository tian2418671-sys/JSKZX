## 三、设计

### 3.1 数据模型（`app_config.json`，**顶层**，紧邻现有 `autoTagRules`）

```jsonc
{
  "autoTagRules": [ /* 现有：自定义规则 [{name,regex}] —— 不动 */ ],
  "customKeywords": [ /* 现有：不动 */ ],

  "autoTagDisabledRules": ["NSFW (限制级)", "青梅竹马"],   // 🆕 关闭的内置规则名清单（按 name 匹配）
  "tagFunnel": { "rule": true, "vector": false, "llm": true }  // 🆕 三层开关
}
```

**为什么默认 `vector: false`**：与现状 `useLocalVector = ref(false)` 一致（向量首次使用需下载 ~120MB 模型）。若默认 `true`，老用户重启后会突然开始下载模型 —— 属于"静默行为变化"，禁止。

**为什么放顶层**：与 `autoTagRules` / `customKeywords` 同域同层（R14 已验证它们在顶层），迁移与备份口径一致。**不放 `ui` 段**（那是 UI 状态收口区）。

**容错**：读取时一律过 `normalizeTagFunnel()` / `normalizeDisabledRules()`（§3.2），非法值回落默认，**不抛错**（老配置/手改坏文件都要能启动）。

### 3.2 纯函数层：`js/utils/tagFunnel.js`（新建，零 Vue / 零 Electron 依赖）

纯函数是本规格**唯一可单测**的部分（打标主流程依赖 `window.electronAPI`，难以单测），所以层决策必须抽出来。

| 导出 | 签名 | 作用 |
|---|---|---|
| `DEFAULT_TAG_FUNNEL` | `Object.freeze({ rule: true, vector: false, llm: true })` | 默认值唯一来源（UI / 持久化 / 容错都用它） |
| `normalizeTagFunnel(raw)` | `raw → {rule,vector,llm}` | 非对象 / 缺键 / 非布尔 → 逐键回落默认 |
| `normalizeDisabledRules(raw)` | `raw → string[]` | 仅保留非空字符串、`trim`、去重（保持插入序） |
| `isFunnelEmpty(funnel)` | `→ bool` | 三层全关 → `true`（UI 禁用按钮 + 引擎入口拦截共用） |
| `resolveFunnelPlan({ funnel, vectorReady, hasCandidateTags, hasApiConfig })` | `→ { rule, vector, llm, skip: { vector?: reason, llm?: reason } }` | **层决策单一来源**：UI 与引擎都调它，避免"按钮说能跑、引擎却不跑" |
| `formatFunnelSummary(stats, plan)` | `→ string` | 结果文案（含"已跳过"），可单测，避免文案在组件里手拼 |

`resolveFunnelPlan` 的判定顺序（**必须按此顺序**，否则会出现"关掉的层仍被计入"）：

1. `rule = funnel.rule`
2. `vector = funnel.vector && vectorReady && hasCandidateTags`；不成立且 `funnel.vector` 为真 → `skip.vector = '模型未就绪' / '候选标签池为空'`
3. `llm = funnel.llm && hasApiConfig`；不成立且 `funnel.llm` 为真 → `skip.llm = '未配置 API'`

> ⚠️ 注意：`vector` 的 `vectorReady` 只影响"**能不能跑**"，**不影响"①是否执行"** —— 二者不可耦合（这正是 AI-02 那类耦合改动的教训）。

### 3.3 规则编译改造（`js/utils/cardLoader.js`）

```js
// 现状：:204  export function compileAutoTagRules(customRules) {
//                    for (const r of defaultAutoTagRules) { try { out[r.name] = new RegExp(...) } catch {} }
// 改为：
export function compileAutoTagRules(customRules, disabledNames) {
    const out = {};
    const off = new Set(Array.isArray(disabledNames) ? disabledNames : []);   // 🆕
    for (const r of defaultAutoTagRules) {
        if (off.has(r.name)) continue;                                        // 🆕 关闭清单只作用于内置规则
        try { out[r.name] = new RegExp(r.regex, 'i'); } catch (e) { /* 系统预设正则非法跳过 */ }
    }
    // ② 用户自定义（追加 / 同名覆盖）—— 不受关闭清单影响（自定义用删除表达关闭）
    // ...原逻辑不变...
    return out;
}
```

**硬约束**

1. `disabledNames` 省略 / `null` / `[]` → **行为与现在完全一致**（`cardLoader.js:223` 的兜底导出继续单参数调用，既有测试不受影响）；
2. 关闭清单**只作用于内置规则**，同名自定义规则仍生效（用户"关了内置但自己加了同名"要能用）；
3. 逐条 `try/catch` 语义不变（单条非法不拖垮整表）。

### 3.5 ★ 清洗白名单解耦（防数据事故，评审点名"必须做"）

| 位置 | 现状 | 改为 |
|---|---|---|
| `App.vue:5307` | `useTags({ ..., compiledAutoTagRules, ... })` | `useTags({ ..., compiledAutoTagRules: autoTagRulesAllForClean, ... })` ← **只改注入源** |
| `useTags.js` | 不改 | 不改（继续读 `compiledAutoTagRules.value` 的键名） |
| `test/cleanForeignTags.test.mjs` | mock 传 `{ value: {...} }` | 不改结构；**新增用例**：注入完整集合、被关闭规则名对应的标签必须保留 |

**UI 义务**：规则开关旁必须写清 —— "此开关只影响打标，不影响「清洗历史外来标签」的保留词表"（评审明确要求）。
