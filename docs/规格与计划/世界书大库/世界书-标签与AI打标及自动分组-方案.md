## 一、现状盘点（全部经源码取证）

### 1.1 世界书 · 标签（A2 半成品——「能筛、不能贴、看不见」）

| 层 | 现状 | 位置 |
| --- | --- | --- |
| 数据 | `wbTagMap`（key = path‖name → string[]），**只在配置文件**（决策 A 已拍板，不写世界书文件） | `App.vue`（`jsTavern_wbTags` + `ui.wbTagMap` 双写） |
| 纯函数 | `normalizeWbTag` / `toggleWbTag` / `countWbTags` / `matchWbFilter`（分组+标签 **AND**） | `js/utils/wbGroupsTags.js` |
| 状态机 | `getWbTags` / `setWbTags` / `toggleWbTagOn` / `addWbTagsBatch` / `wbAllTags` | `js/composables/useWorldbooks.js` |
| 筛选 | ✅ 标签筛选行（chips 点击过滤，含「清除」） | `SidebarPanel.vue` 行 435~448 |
| **列表显示** | ❌ 列表项只显示「名字 + 词条数 + 按需徽标 + 操作按钮」——**不带标签** | `SidebarPanel.vue` 行 542~590 |
| **编辑入口** | ❌ **全仓库无 UI 调用**（`toggleWbTagOn` 等只有定义/透传，没有消费） | grep 取证：仅 `App.vue` 解构 + `SidebarPanel` ctx 透传 |
| 批量贴标签 | ❌ `BatchTagModal.vue` 只服务角色卡（A2 文件 9.4 留档） | — |

> 📌 **结论：用户的「没有标签位置」是准确描述** —— 数据与筛选已具备，但**看不见、也贴不上**。本方案的 S1 就是补齐这两个口子。

### 1.2 世界书 · 分组（虚拟分组已具备；物理分组为零）

| 能力 | 现状 |
| --- | --- |
| 虚拟分组 | `wbCategoryMap`（配置层）+ 右键「移动分组」+ 筛选 + 「改名/解散」右键（A2） |
| **物理分组** | ❌ 不存在——「移动分组」只改配置键，**文件不动** |
| 物理底层能力 | ✅ `wb:rename`（`{oldPath,newPath}`——改名/移动通用）+ `fs:createGroupFolder`（通用建夹，白名单校验）——**都有现成 IPC** |
| 扫描 | ✅ 深度递归穿透子文件夹（`wb:scan`）——物理分组后仍能被扫到 |

### 1.3 打标系统 · 候选池（本方案的增强对象）

| 项 | 现状（`js/composables/useAITools.js`） |
| --- | --- |
| 候选池 | `aiCandidateTags`（上限 300，超出取前 300 + 日志提示） |
| 提示词注入 | `buildPromptHead()`：池非空 → `【标签候选池】：[…]` + 自由度规则文本 |
| 自由度开关 | `enableAIExtraction`（「允许 AI 自由提取标签」）——**现状只切换规则文本**，不控制「池是否出现」 |
| 产出回池 | ❌ 无——打标产出只进卡片 `customTags` / 世界书 `wbTagMap`，**不回填候选池** |
| LLM 打标链路 | ✅ 单套提示词链路（System/User/预填充）+ 打包 + 分段 + 续跑 + 三层降级解析（本日刚完成 AI-10 根治） |

### 1.4 界面与交互参照物

- **卡片自动分组**：`useAutoGroup.js` + `AutoGroupModal.vue` + `autoGroupPresets`（分组声明收纳条件 → 预览 → 执行 → 回滚）——世界书自动分组**对齐此范式**（详见卡片侧方案 v2.0）。
- **世界书右键菜单** `WbContextMenu.vue`：打开文件夹 / 重命名 / 复制副本 / 移动分组 / 删除——**无标签、无自动分组、无打标**（三个新功能的天然入口）。

## 二、设计

### A. 标签显示位 + 编辑入口（S1）

| 项 | 设计 |
| --- | --- |
| **A1 列表显示** | 列表项名字行下补一行标签 chips（沿用卡片列表「🏷️ 最多 N 个 + `+X`」的既有范式）；空间不足时可点击展开 |
| **A2 单本编辑** | ① 右键菜单加「🏷️ 编辑标签」；② 操作按钮区（📂✏️📋🗑️ 行）加 🏷️ 按钮。弹出小面板：显示现标签（✕ 可删）+ 输入框（回车添加）+ **`wbAllTags` 建议**（点击即加）——复用 `toggleWbTagOn` / `setWbTags`（**纯 UI 接线，不改数据层**） |
| **A3 批量贴标签**（可选，S5） | `BatchTagModal.vue` 世界书化（A2 文件 §④ 已给方案：props/emits + 调用侧；世界书用 `worldbooks` + 选择集，不复用卡片 `selectedIds`） |
| **A4 打标产出** | 打标结果直接写 `wbTagMap`（与手动编辑同源，天然一致） |

### B. AI 打标 · **LLM 大模型模式**（角色卡 + 世界书，S3）

> ⚠️ 定位（用户 2026-09-25 明确）：「LLM 打标」**不是世界书专属** —— 这是**一套**打标能力，
> **角色卡与独立世界书两个资产都走同一套引擎**（材料构建与落盘各自适配）。世界书只是新增的**第二个接入端**。

| 项 | 设计 |
| --- | --- |
| **B0 模式锚点（✅Q1 已拍板）** | 候选池开关可用性 = Q1 真值表：**可用 ⟺ `(① ≡ ②) && ③`**；两资产同口径 |
| **B1 角色卡侧（现状+小补）** | 引擎已完备（单套提示词链路 / 打包 / 续跑 / 预填充拼接根治）；本方案**只补**：候选池开关联动（S2）+ 产出回池（S2） |
| **B2 入口（✅Q5 已拍板：二合一）** | **统一打标入口，按当前视图（侧边栏选项卡）自动分发**——与「🎯 智能查重统一入口（按当前视图自动分发）」同款：角色卡视图 → 打角色卡；世界书视图 → 打世界书；预设视图 → 不适用（置灰） |
| **B3 材料构建（✅Q3 已拍板：角色卡同口径）** | 角色卡 = 描述/性格/首句；世界书 = `书名` + 词条（key/content）——**同款工程待遇：不截断，超长走分段**（复用 `processSegmentedCard` 机制，不对世界书做摘要截断） |
| **B4 引擎（✅Q4 已拍板：公用一条系统）** | **三层管线全共用**（①规则②向量③LLM——与角色卡同一系统，非世界书简化版）；规则/向量的文本源按世界书形态适配（书名/词条文本）；提示词链路/候选池/预填充拼接/打包/续跑/降级解析/日志全套直接复用 |
| **B5 落盘（两套适配）** | 角色卡 → `customTags` + 配置覆盖层（现状）；世界书 → `setWbTags`/`addWbTagsBatch` → `wbTagMap`（配置层，不写文件） |
| **B6 弹窗形态（✅Q5：二合一）** | 弹窗组件改造为**双资产支持**（共享候选池/日志/续跑/链路 UI）；打开时的「操作对象」由当前视图决定（世界书视图可对选中的书批量） |

### C. 候选池增强（打标系统通用，S2——先于 S3）

| 项 | 设计 |
| --- | --- |
| **C1 池开关** | 新增 `useCandidatePool`（默认**开**）：<br>· 关 → `buildPromptHead()` **不输出**候选池段落（也不输出「从池中选」规则）→ LLM 完全自由打标；<br>· 开 → 现状（池 + 规则文本） |
| **C2 与「自由提取」联动矩阵** | \| 池 \| 自由提取 \| 行为 \|<br>\| 关 \| （禁用/灰） \| 全靠 LLM 自行打标 \|<br>\| 开 \| 开 \| 优先池 + 可自创（现状默认） \|<br>\| 开 \| 关 \| **严格只从池中选**（现状） |
| **C3 产出回池（✅Q2 已拍板：二选一）** | 打标完成后，把「本次新产出且不在池中」的标签汇总 → 弹选择：「**加入候选池**」/「**放弃**」（整批二选一，不自动、不逐条）；入池走 `addAICandidateTag` 去重；超上限 300 提示精简 |
| **C4 可用条件（✅已拍板 2026-09-25）** | **仅当「①与②同态 且 ③开」时可切换**（即：**仅 LLM** 或 **三层全开**；真值表见 §四 Q1）；其他组合一律**禁用**（保留可见 + tooltip 说明，避免「功能突然消失」） |

### D. 自动分组（文件级移动，S4）

| 项 | 设计 |
| --- | --- |
| **D1 范式（✅Q7：与分组窗口对齐）** | ① **入口二合一**：与「智能查重统一入口」同款——按当前视图自动分发（角色卡视图=卡片自动分组；世界书视图=世界书自动分组）；② **窗口形态对齐 `AutoGroupModal`**（双选项卡：📋 收纳规则 / 🔍 预览与执行）；③ 流程：分组声明收纳条件 → 判定（规则/LLM）→ 预览 → 执行 → 可回滚 |
| **D2 物理操作** | `fs:createGroupFolder`（建夹）→ `wb:rename`（移动，`{oldPath,newPath}`）；**只动文件位置、不动文件内容**（与「不写文件」的 A2 决策不冲突） |
| **D3 分组模型（✅Q6 拍板：甲）** | **物理文件夹为唯一标准**：扫描时由相对路径推导分组（子文件夹名 = 分组名；根目录 = 默认）；分组筛选/统计改由文件夹推导；`wbCategoryMap` 走**一次性迁移**——提供「把现有虚拟分组物理化」动作（按 map 把书移进对应文件夹，再退役该 map）；迁移完成前保留兼容读取 |
| **D4 键迁移（铁律 6）** | 移动世界书后必须同步迁移：`wbTagMap` 键（保留）、`wbCategoryMap` 键（迁移期间）、`currentWbTags` 等按 path 派生的会话态；快照/引用需核对 |
| **D5 判定引擎（✅Q7）** | 与卡片侧同构：关键词收纳条件 + LLM 兜底（同一 API 通道）；`autoGroupPresets` 形态迁移为世界书版（条件字段 = 书名/词条关键词） |

### E. 不做的事（避免越界）

- ❌ 不改世界书文件内容（标签不写进 JSON——沿用 A2 决策 A）；
- ❌ 不新建打标引擎（一切复用 `useAITools`）；不重造自动分组（对齐卡片范式）；
- ❌ 不动角色卡侧既有行为（候选池增强是「加开关」，默认值 = 现状、可用性按 Q1 真值表）。

### F. ⚠️ 质量红线——两方向模式隔离（用户强调，2026-09-25）

**所有新入口（标签编辑 / 打标 / 自动分组）必须严格随当前视图（`appMode`）作用**：

- **世界书视图下不得出现/触发任何角色卡操作**（不显示卡片按钮、不误调卡片选择集/覆盖层）；
- **角色卡视图下不得出现/触发任何世界书操作**（反向同样）；
- 每个新按钮/新命令都要写清「**哪个模式可见 / 点击作用于谁**」。

> 历史教训：侧边栏为双模式共用组件，同类「跨模式误操作」缺陷已多次出现（AR-13 / AR-32 家族）——
> 实施时逐入口核对，验收时**双向**遍历（见 §五）。

## 五、验收要点（初拟，待实施前细化）
