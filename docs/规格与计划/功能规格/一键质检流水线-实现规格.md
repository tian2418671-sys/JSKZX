# 一键质检流水线 — 实现规格

> 本文件是什么：**下一版本待做功能**「一键质检」的实现规格——把散落的只读检查能力串成一条流水线，出一份综合报告。

## 一、目标

单入口（维护菜单「🧪 一键质检…」）→ 勾选步骤 → 依次执行 → **综合报告**（可折叠浏览、逐项定位、复制/导出）。

设计原则：**流水线只做「编排 + 汇总」，每个步骤复用现有能力**（不复制实现、不引入第二套口径）；全流程**只读**（不动库、不删文件）。

## 二、步骤定义（v1）

| 步 | 名称 | 实现来源 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| S1 | 重新扫描 | `rescanLibrary`（现有） | ☑ | 保证数据新鲜 |
| S2 | 查重扫描 | `startSmartDedupe`（按库分发，现有） | ☑ | 结果可「打开查重弹窗」查看；耗时随库大小 |
| S3 | 标签分析 | **新增纯函数** `computeTagStats` | ☑ | 无标签卡数 / 覆盖率% / 单标签卡 / 标签总数 / Top 标签榜 |
| S4 | 卡片质量巡检 | **新增纯函数** `auditCards`（`js/utils/cardAudit.js`） | ☑ | v1 四条规则：`description` 为空、无标签、`first_mes` 为空、Token 超阈值（默认 8k，可调） |
| S5 | 世界书词条体检 | 复用 `entryHealthReport`（`useWorldbookEntries.js`，现有） | 世界书模式 ☑ | **范围 = 当前打开的书**（跨书批量属二期）；未打开书时该步「跳过（未打开世界书）」 |

> 与「冷备」联动：报告尾部提示「建议先做整库冷备再动手清理」（**不自动执行**）。

## 三、架构与落点

### 3.1 编排：新 `js/composables/useQualityCheck.js`

```text
状态：{ running, cancelRequested, currentStep, steps: [{id,title,status:pending|running|done|skipped|failed,summary,items,error}] , report }
run(stepsEnabled) → 串行执行 → 每步 try/catch（失败记录后继续）→ 汇总
cancel() → 置标志（在步骤间与长循环内检查；S2 复用查重自身取消）
```

- 依赖注入（ctx 风格）：`rescanLibrary` / `startSmartDedupe` / `library` / `worldbooks` / `entryHealthReport` / `addLog` / `showToast` —— App.vue 接线时两处同改（解构 + ctx 对象，项目既有坑）；
- 大库让出：S3/S4 对 `library` 分片遍历（每 200 项 `await` 一次微任务），不阻塞渲染。

### 3.2 纯函数（可单测）

- `js/utils/tagStats.js`：`computeTagStats(items) → { total, untagged, coveragePct, singleTag, tagCounts: Map, topTags: [] }`；
- `js/utils/cardAudit.js`：`auditCards(items, opts) → { rules: [{id, title, hits: [path…] }], total }`。

### 3.3 报告 UI：新 `js/components/QualityCheckModal.vue`

- 上半：步骤勾选 + 「▶ 开始质检」/「中止」+ 进度（第 n/5 步）；
- 下半：结果分区（每步一节，可折叠）——数值摘要 + 问题清单（前 50 条 + 共 N 条）；每项右侧「定位」按钮：
  - 卡片类 → 打开该卡（选中 + 编辑区）；
  - 查重 → 打开对应查重弹窗；
- 底部：「📋 复制报告」「💾 导出 Markdown」（复用 [`测试会话导出-实现规格.md`](../测卡工作区/测试会话导出-实现规格.md) 的 `file:saveTextFile`）× `「建议先冷备」提示行`。

### 3.4 入口

- `useCommands.js` 维护菜单加「🧪 一键质检…」（`menu: 'maintenance', section: 1`，order 排在冷备之后）；
- 命令面板自动收录（注册表唯一真相源，无需额外接线）。

## 四、验收口径

1. **真实库**：全流程（除 S2 按库耗时）**60 秒内**出报告；报告数字与手工抽查一致（无标签数、超长卡数）；
2. 各步失败不阻断：模拟 S5「未打开世界书」→ 状态 skipped、其余正常；
3. 「定位」跳转可用（卡片打开、查重弹窗打开）；
4. 中止：中途 cancel → 已完成的步骤结果保留、后续标记 cancelled；
5. 单测：`computeTagStats` / `auditCards` 边界（空库、全无标签、超长判定阈值）；
6. 大库（11k 只读）：S3/S4 不卡 UI（帧内可交互）。

## 五、风险与注意事项

- **只读承诺**：全流水线不得调用任何写操作（不删、不改、不保存）；S2 查重自身已有的「清理」按钮不在流水线内触发；
- S2 与手动查重互斥：运行中禁用重复启动（复用查重运行标志）；
- 报告口径即活文档：`computeTagStats` / `auditCards` 的字段命名与 `dedupeView` 的 `VIEW_FIELDS` 守卫精神一致——新增字段补单测；
- 「卡片质量巡检」规则 v1 刻意保守（只报事实，不给删改建议），避免误报引发误删。
