## 二、数据模型与落盘（`app_config.json` 顶层）

```js
autoGroupProfiles: [            // 声明式分组档案（可序列化；老配置无此键 → 空 = 零迁移）
  {
    id: 'gp_xxx',               // 稳定 id（缺失时归一化补 `gp_restored_<idx>`）
    group: '纯爱',              // 目标分组名 = 物理文件夹名（净化规则与主进程逐字一致）
    enabled: true,
    match: { type: 'tag', pattern: '纯爱' },   // 5 种类型；布尔型（hasLorebook/hasRegex）**无 pattern**
    note: '…'                   // 可选说明（UI 展示）
  }
],
autoGroupLastRun: {             // 最近移动日志（回滚依据）；未解决项为空时置 null
  at: 1690000000000,
  entries: [{ cardName, fromGroup, toGroup, movedAt }],   // ⚠️ 按卡名+分组记，**不记绝对路径**
  lastRollback: { at, rolled, failed: [{ cardName, reason }] }  // 仅"部分未处理"时保留
}
```

- 归一化：`normalizeGroupProfiles`（过滤非法项 / 去重 / enabled 默认 true / 布尔条件去 pattern）与
  `normalizeAutoGroupLastRun`（清洗条目）在**落盘与恢复两端**都跑（`useConfigPersistence` + App.vue 启动恢复）。
- 条件类型与标签：`tag`（精确，走 `extractCardTags`，大小写不敏感）/ `name-keyword`（包含）/
  `name-regex`（名称正则，**非法只跳过该条**）/ `hasLorebook` / `hasRegex`（与搜索过滤视图同口径）。

## 三、判定语义（`buildAutoGroupPlan`，只读）

| 规则 | 说明 |
|---|---|
| **顺序 = 优先级** | 档案按「侧边栏分组顺序」排序（不在表中的排最后）；一卡多命中取首个，并记入 `conflicts`（含全部命中组） |
| **安全默认** | `includeGrouped=false` 时**只处理「未分类」**；已手动分组的卡跳过并给出原因（勾选后才参与） |
| 已在目标分组 | 跳过（不重复移动） |
| 库外卡片 | 预览阶段即标记「不在库目录内，请先收编」 |
| 同名冲突预警 | 目标分组内将出现同 basename 的卡 → `duplicateWarnings`（执行时由主进程追加时间戳，不覆盖） |
| 名称净化预览 | `C++:基础` → `C++_基础` 等，`targetGroups[].renamed` 显式提示 |
| 将新建文件夹 | `targetGroups[].isNew`（已知分组 = 配置分组 ∪ 卡片实际 subFolder） |
| 性能 | 纯函数、单次遍历；11k 卡库可重复扫描（只读） |

## 四、执行与回滚（`useAutoGroup`）

### 执行
1. 「没有扫描结果不许执行」；执行前**原生二次确认**（列出张数 + 将新建的文件夹）。
2. 逐张调用 **`useCardGroups.moveCardToGroup`**（唯一合法原语：迁移覆盖层 / 测卡会话与变量树 / 记忆三类 path 派生键）。
   每 10 张让出主线程一次；支持**中止**（已完成的不回退，剩余项保留在预览里）。
3. 成功写日志（与**上一次日志合并**——否则更早的自动分组将永久失去回滚能力）；失败项保留 `cardId` 供「🔁 重试失败项」。
4. 空分组清理（方案 §4.3）：仅当来源分组是自定义分组且已无卡片 → 确认后走 `deleteEmptyGroupFolder`（主进程只删空目录）。

### 回滚
1. 二次确认；**逆序**处理日志（多轮移动时先还原最近一次，`fromGroup` 才正确）。
2. 定位：`resolveRollbackCard` **按卡名 + 当前分组**在当前库定位（不死守路径），五种状态：
   `ok`（在 toGroup → 回移）/ `already`（已回 fromGroup → 计已还原）/ `missing`（已删/改名）/ `changed`（被手动移到别处）/
   `ambiguous`（多张同名，无法消歧）。
3. `missing / changed / ambiguous` **单独列出**（不静默跳过、不中断整批）；`changed / ambiguous` 保留在日志里可人工处理后重试。
4. 全部解决 → 日志置 null；部分未解决 → 保留剩余条目 + `lastRollback` 记录。

### 测试缝（重要）
`executeAutoGroup(ids, { skipConfirm })` / `rollbackAutoGroup({ skipConfirm })`：**仅 dev 诊断钩子（`__jskDiag.autoGroup`）传 true**，
用于 CDP 端到端（contextBridge 暴露的 `electronAPI` 是冻结对象，**无法在页面里劫持原生对话框**）。
产品路径（UI 按钮）永远走确认框——默认参数不变。

## 五、推荐模板（真实库命名整理）

- 来源：2026-09-20 实测采集 `I:\03\角色色卡` 的 **53 个分组文件夹名**与卡名命名习惯（关键词堆叠 / `#标签` 式 / 长句标题）。
- `AUTO_GROUP_PROFILE_PRESETS`（27 条）覆盖：NTR / NTRS，NTL / 纯爱 / 催眠 / 调教 / 人外 / 伪娘 / 扶他 /
  百合，百破，扶她 / 病娇 / 后宫 / 开大车 / 乱伦 / 校园 / 修仙 / 系统 / 超能力者 / RPG跑团 / 萝莉 / 熟女 /
  御姐，人妻 / 男同 / 重口注意！/ 假小子 / 古风 / 女性向 / 英文卡。
- `#标签` 命名（如 `…#媚黑.png`）由 `name-regex` 覆盖（示例见 NTR 模式）；组名含全角标点（`百合，百破，扶她` 等）**逐字一致**。
- **只绑定已存在的分组**（`buildPresetProfiles(existingGroups)`）：一个分组都没有 → 不载入任何模板（防凭空造文件夹）。
- ⚠️ **口径说明**：这里的「已存在」指**当前分组列表**（`customCategories` + 内置预设），而非「当前库磁盘上的文件夹」——
  账号配置会保留跨库的历史分组，因此模板可全部匹配；对「列表里有、磁盘上还没文件夹」的分组，预览会标 **「将新建文件夹」**（执行时才 mkdir）。
- ⚠️ **功能归档组不做名称模板**：`剧情卡` / `工具` / `世界卡` / `整活` 这类按**用途**归档的分组，成员可能是**工具卡**
  （实测反例：`旅程建筑师1.4` 放在「剧情卡」里，但它是生成旅程的工具卡、`tags` 为空）——
  名称关键词对它**既会误吸工具卡、也召不回无关键词的新卡**，因此**不生成模板**（27 条里没有这些组）。
  这类组保持人工归位；要自动化请先给卡打**标签**，再用 `tag` 条件建规则（现成能力）。

## 六、静态防线（`scripts/pychecks/auto_group_safety.py`）

1. **物理移动唯一原语**（blocker）：除 `js/composables/useCardGroups.js` 外，
   全 `js/**` 不得出现 `electronAPI.moveCardToGroup` 调用 —— **范围覆盖自动分组与回滚代码路径**（方案 §4.2）。
2. **判定层纯函数性**（warn）：`js/utils/autoGroup.js` 不得出现 `window.` / `electronAPI` / `fs` 引用。
3. （配套卫生检查，在 `core_project.py`）**js 源码无本机绝对路径**（blocker）：
   任何 `盘符:\...` 形式的开发机路径（含注释）都会随构建进入产物，甚至有概率直接出现在用户可见文案里
   —— 本功能评审期实测踩过（推荐模板「来源」文案曾写死开发机样本库路径，已改为中性描述）。

## 十、🤖 LLM 判定层（S-LLM，2026-09-20 落地）

**用户拍板的三条口径**：① AI 建议**默认不勾选**（人工确认后才执行）② 卡信息 = **名称 + 标签 + 描述前 200 字** ③「判定标准」入口 = **收纳规则页逐组编辑**。

| 层 | 文件 | 职责 |
|---|---|---|
| 判定纯函数 | `js/utils/autoGroupLLM.js` | 规格提取（`buildLlmGroupSpecs`）/ 候选收集（`collectLlmCandidates`）/ 提示词构造（`buildLlmMessages`）/ 容错解析（`parseLlmJudgement`）/ 卡匹配（`assignJudgements`） |
| 编排 | `js/composables/useAutoGroup.js` | `runLlmJudge`：分批（默认 20 张/批）+ 会话级缓存 + 批次节流（250ms）+ 失败重试（×2）+ 建议合并进计划 |
| UI | `AutoGroupModal.vue` | 规则行「🤖 判定标准」输入；预览页「🤖 AI 分辨」按钮 + 进度/异常；建议行 🤖 徽标 + 置信度；默认不勾选 |
| 静态防线 | `scripts/pychecks/auto_group_safety.py` | 判定层纯函数性（含 LLM 文件）；**LLM 调用须走 `sendChatMessage` 统一 IPC 通道**（渲染层直接 fetch 会被 CORS 拦） |

**关键设计**：
- 「判定标准」= 每条收纳规则上的自然语言文本框（≤300 字）；**留空 = 该组不参与 AI 判定**；同组多规则标准自动拼接。
- **只喂「未命中规则 / 冲突」的卡**（`plan.skipped` reason 前缀「未命中」+ `plan.conflicts`）；规则已命中的卡不浪费 API 额度。
- 系统提示词在模块内**写死契约**：只输出 `{"assignments":[{card,group,confidence,reason}]}`，group 必须在清单内；解析端过滤未知组/未知卡、置信度夹紧 [0,1]、同卡取最高、容忍 ```json 代码块与夹带废话。
- 缓存 key = `卡片路径 + 规格签名`（改分组/改标准 → 签名变化 → 旧缓存自动失效）；重扫/重开弹窗时缓存建议自动并回计划。
- 建议合并进计划后：`source:'llm'`，原因带「🤖 AI 判定（置信度 x%）」；**默认不勾选**，可「勾选全部建议 / 全部取消」。
- 执行/回滚完全复用既有链路（唯一原语 `moveCardToGroup`），不新增任何移动逻辑。

**验收**：`test/autoGroupLlm.test.mjs`（13 例：规格/候选/提示词/解析/卡匹配）+ 隔离库端到端步骤 10（本地 mock 服务：1 批请求 → 建议入计划 → 二次运行全缓存 0 请求 → DOM 验证默认不勾 → 真实移动 + 回滚）。
