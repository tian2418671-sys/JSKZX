# 独立前端角色卡（重型卡）· 完整方案

> 版本：v2（2026-10-18）
> 状态：**待评估**
> 定位：**A（启动器）+ B（保险柜）+ C（统一入口）+ D（展示游玩）**
> 边界：**只碰壳，不碰芯** —— 不做解析、不做数据编辑、不注入 AI
> 备份粒度：**一卡一备份**，支持自动备份 + 手动备份

---

## 一、定位与边界（定稿）

### 1.1 一句话定位

**重型卡是"能玩的收藏品"，软件是它的展柜兼管理员 —— 不碰内容，只管摆放和保管。**

### 1.2 软件的四项职责

| 职责 | 具体表现 | 用户得到的价值 |
| --- | --- | --- |
| **A 启动器** | 侧边栏入口、列表选卡、一键打开 | 不用记网址、不用翻书签 |
| **B 保险柜** | 一卡一存档、自动备份、手动备份、恢复、迁移、删除 | 玩几十小时的存档不会因为清缓存/换电脑而丢 |
| **C 统一入口** | 多卡统一列表：名称/图标/备注/上次玩/占用/备份状态 | 几十张卡也不会乱 |
| **D 展示游玩** | 整块渲染、可交互、切走再回来状态还在 | 在软件里真的能玩 |

### 1.3 明确不做（红线）

| 不做 | 原因 |
| --- | --- |
| 解析卡内存档（剧情/变量/角色/时间线） | 属于"碰芯"，格式由作者随时改，逆向维护成本极高 |
| 编辑卡内任何数据 | 只做整包/目录级操作 |
| 向卡内注入 API Key / 接管 AI 推理 | 密钥风险 + 逻辑耦合 + 随版本失效 |
| 修改/镜像站点源码 | 产物 hash 化、持续更新、授权问题 |
| 让卡调用软件的文件系统（不注入 preload） | 一旦注入，卡内脚本可读写磁盘，安全红线 |

### 1.4 与现有功能的边界

| 现有功能 | 关系 |
| --- | --- |
| 测卡工作区（`chatEngine`） | **完全独立**。重型卡不走我们的对话引擎 |
| 插件工作区（`usePlugins`） | 完全独立。插件是本地脚本，重型卡是远程 SPA |
| 卡内插件页签 | 无关 |
| 整库冷备（`fullBackup`） | 可复用其目录打包思路，但**重型卡备份是独立通道**（见 §六） |

## 二、样例站点实测画像

抓取线上产物（2026-10-18）得到的事实，作为所有性能与安全设计的依据：

| 项 | 实测值 | 设计影响 |
| --- | --- | --- |
| `index.html` | **828 字节**，仅 `<div id="root">` | 纯 SPA，运行时渲染，宿主看不到结构 |
| 主脚本 | **2,143,202 字节**（2.04 MB，单文件，已混淆） | 首次加载有等待；必须依赖 HTTP 磁盘缓存 |
| 样式 | **489,674 字节**（478 KB） | 同上 |
| 框架 | React | 与主界面 Vue 无冲突（不同 document） |
| `localStorage` | **29 处** | 需要独立 partition，避免与主界面 `jsTavern_*` 撞键 |
| `indexedDB` | **36 处** | 存档主要载体；备份必须覆盖 IndexedDB 目录 |
| `fetch(` | **11 处** | 会有网络请求；离线模式需拦截 |
| 硬编码地址 | `jfdk.xxbjf.com/preset-nodes.json`、`/wjhl.json`、`/v1/`、`api.openai.com/v1`、`api.example.com/v1` | 用户可自填 API；离线时这些会失效 |
| 外链 | `ifdian.net/a/_ydrs`、`qm.qq.com/q/...` | 需要外链兜底，否则点了没反应 |
| 混淆 | 有字符串解码函数 | **不逆向**，按黑盒处理 |
| 版本 | 页面内标 v2.1.5 | 版本由卡自管，软件不代管 |

## 三、总体架构

```text
┌──────────────────────────── 主进程 (main.js) ────────────────────────────┐
│  · 新增 app://heavycard/* 路由（中转页，跳过 CSP 注入）                    │
│  · 新增 IPC：heavycard:*（备份/恢复/删除/数据目录/清缓存/外链）             │
│  · 按 partition 判定外链 → shell.openExternal                            │
│  · session.fromPartition('persist:heavycard-<id>') 管理                   │
│  · 备份引擎：目录快照 + zip + 保留份数（复用 fullBackup 思路）             │
│  · 自动备份调度：启动后 / 退出前 / 定时（可配）                            │
└──────────────────────────────────────────────────────────────────────────┘
                                   ↕ IPC (preload.js 白名单包装)
┌──────────────────────────── 渲染进程 (Vue 3) ────────────────────────────┐
│  SidebarPanel ── Dock 第 5 按钮 🎬                                       │
│       └─ 面板列：搜索 / 添加 / 列表 / 分页 / 右键菜单                     │
│  HeavyCardWorkspace ── 顶部工具条 + iframe                               │
│  useHeavyCards.js ── 列表 CRUD / 备份编排 / 离线开关 / 持久化             │
│  useConfigPersistence ── ui.heavyCards 落盘 app_config.json             │
└──────────────────────────────────────────────────────────────────────────┘
                                   ↕
                       <iframe sandbox="..."> 加载远程站点
```

**进程模型**：一张重型卡 = 一个独立的 Electron 渲染进程（Chromium 自动分配）。同时只保留 **1 个** iframe，切卡即销毁旧的。

## 四、数据模型与存储

### 4.1 卡清单（`app_config.json` → `ui.heavyCards`）

```js
{
  id: 'hc_7f3a2b',                  // 稳定 id（nanoid 或 URL+时间哈希）
  name: '云端人生',                  // 显示名（可改）
  url: 'https://jfdk.xxbjf.com/yd_rsdtq/index.html',
  icon: '🎬',                       // emoji；也可选本地图片 → local-file://
  note: '',                         // 用户备注
  partition: 'persist:heavycard-hc_7f3a2b',  // 一卡一 partition
  createdAt: 1730000000000,
  lastOpenedAt: 0,
  totalPlayMs: 0,                   // 累计游玩时长（可选统计）
  settings: {
    offline: false,                 // 离线模式
    zoom: 1,                        // 0.5 ~ 2.0
    allowExternal: true,            // 允许外链打开系统浏览器
    autoBackup: {
      enabled: true,                // 自动备份开关（默认开）
      onExit: true,                 // 关闭软件前备份
      onOpen: false,                // 打开前备份（防"误开覆盖"）
      intervalMin: 30,              // 游戏期间定时备份，0=关闭
      keep: 5                       // 保留份数
    }
  },
  backupStats: {                    // 只读展示，实际以磁盘扫描为准
    lastBackupAt: 0,
    lastSize: 0,
    count: 0
  }
}
```

**落盘原则**：

- 清单只进 `app_config.json`（项目铁律：它是最高权威），走既有 `useConfigPersistence` 防抖/加密落盘
- **存档本体绝不进配置**（可能几十 MB）
- 启动时若 `ui.heavyCards` 缺失 → 自动补一个**预置的「云端人生」**条目（开箱即用）

### 4.2 磁盘布局

```text
%APPDATA%\sillytavern-card-manager\
├── app_config.json                       # 卡清单（ui.heavyCards）
├── heavycard-backups\                    # 默认自动备份根目录（可在设置改）
│   ├── hc_7f3a2b\
│   │   ├── 20261018-1420-auto.zip
│   │   ├── 20261018-1830-manual.zip
│   │   └── ...
│   └── hc_9c1d4e\...
└── Partitions\
    ├── heavycard-hc_7f3a2b\              # Chromium 存储（实际路径需 P0 实测确认）
    │   ├── Local Storage\leveldb\
    │   ├── IndexedDB\https_jfdk.xxbjf.com_0.indexeddb.leveldb\
    │   └── Cache\ / Code Cache\ / GPUCache\
    └── heavycard-hc_9c1d4e\...
```

> ⚠️ **P0 必须先实测** `Partitions\` 的真实路径与目录结构（不同 Electron 版本略有差异），**不能按猜测写死**。

### 4.3 一卡一 partition 的理由

| 共用 partition | 一卡一 partition（**采用**） |
| --- | --- |
| 同域名的两张卡会串存档 | 各卡目录独立，互不影响 |
| 备份/删除只能整包 | 按卡精确备份/删除 |
| 一张卡数据损坏会影响全部 | 故障隔离 |
| 节省少量缓存 | 每卡多几十 MB 基础缓存（可接受） |

### 5.4 iframe 属性（定稿）

```html
<iframe
  :key="activeCardId"
  :src="frameUrl"
  sandbox="allow-scripts allow-same-origin allow-forms allow-downloads"
  allow="clipboard-write"
  referrerpolicy="no-referrer"
  class="w-full h-full border-0 bg-black"
/>
```

| 属性 | 加/不加 | 原因 |
| --- | --- | --- |
| `allow-scripts` | ✅ | 站点是 SPA，必须执行 JS |
| `allow-same-origin` | ✅ | 站点要读写自己的 `localStorage`/`IndexedDB` |
| `allow-forms` | ✅ | 站点有输入表单 |
| `allow-downloads` | ✅ | 站点支持导出存档（JSON/ZIP） |
| `allow-popups` | ❌ | 否则 `window.open` 绕过 `setWindowOpenHandler` |
| `allow-top-navigation` | ❌ | 防止卡把整个软件导航走 |
| `allow-modals` | ❌（待实测） | 避免 `alert` 阻塞主渲染；若卡依赖再加 |

> `allow-scripts + allow-same-origin` 的组合意味着 iframe 内脚本可操作自己的存储。**这是预期行为** —— 它的源是独立 partition，够不到主界面。

## 六、备份系统（核心功能）

### 6.1 三种备份触发

| 类型 | 触发时机 | 默认 | 说明 |
| --- | --- | --- | --- |
| **自动 · 退出前** | 软件关闭时（`before-quit`） | ✅ 开 | 最重要，防止关软件丢进度 |
| **自动 · 定时** | 游玩期间每 N 分钟 | ✅ 30 分钟 | N 可调（5/10/30/60/关闭） |
| **手动** | 工具条「📦 备份」/ 右键菜单 | — | 立即执行，命名 `manual` |

> 另有可选「打开前备份」（默认关）：防止某些卡一打开就覆盖旧档。

### 6.2 备份内容

```text
zip 根
├── manifest.json          # { cardId, name, url, createdAt, appVersion, electronVersion, kind }
├── Local Storage/         # 该 partition 的 localStorage
├── IndexedDB/             # 该 partition 的 IndexedDB
└── meta.json              # 目录树 + 文件数 + 大小（校验用）
```

- **只打包存储目录**（`Local Storage` / `IndexedDB` / `Session Storage`），**不打包** `Cache` / `Code Cache` / `GPUCache`（那是缓存，恢复它没意义且体积大）
- 打包前**先让 iframe 空闲**（`about:blank` 卸载，等待 300ms），避免 leveldb 正在写入时复制出损坏文件
- 压缩用 `archiver` 或 Node 内置 `zlib`（**需先确认 package.json 是否已有依赖，没有则用 Node 原生方案，避免新增包**）

### 6.3 备份的两种实现路径（P0 必须实测选一）

| 路径 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| **① 直接复制 partition 目录** | 复制 `Partitions/heavycard-<id>/Local Storage` 等 | 不依赖 iframe 内容 | leveldb 写入中复制可能损坏 |
| **② 通过 `webContents` 执行导出** | `executeJavaScript` 读 `localStorage` | 数据一致 | **跨域：主框架拿不到 iframe 的存储** ❌ |

**结论：只能走 ①**，并用「先卸载 iframe 再复制」解决一致性问题。

### 6.4 恢复

```text
用户点「恢复」→ 列出备份列表（时间/类型/大小）
  → 选择一份 → 二次确认（会覆盖当前存档）
  → iframe 卸载 → 解压覆盖存储目录 → 重载 iframe
  → 提示"已恢复到 10-18 14:20 的存档"
```

**恢复前自动做一次「恢复前快照」**（`pre-restore`），万一恢复错了还能回去。

### 6.5 保留策略

- 每卡保留最近 **N 份**（默认 5，可调 3~20）
- 超出时删除最旧的，但**永不删除最后一份 `manual`**（用户手动备份视为"锚点"）
- 面板显示：`备份 5 份 · 最近 14:20 · 共 128 MB`

## 七、安全设计

| 风险 | 措施 |
| --- | --- |
| 卡内脚本读写软件文件 | ❌ 不注入 preload，`nodeIntegration: false`，`contextIsolation: true` |
| 卡把整个软件导航走 | iframe 不加 `allow-top-navigation`；主进程 `will-navigate` 只放行 `app://` |
| 卡弹窗绕过限制 | 不加 `allow-popups`；外链走主进程 `shell.openExternal`（仅 `http(s)` + 用户允许） |
| 卡偷偷发数据 | 在线模式不拦（用户已主动打开该站点）；离线模式 `webRequest` 拦截非白名单域名。**状态条显示"拦截 N 个请求"可点开明细** |
| CSP 豁免范围过宽 | 只对 `app://heavycard/` 前缀跳过 CSP，该路由只提供**主进程内置**的中转页（不接受用户内容） |
| 路径穿越（本地目录模式，P2） | 协议 handler 强制 `startsWith(cardLocalDir)` 校验 |

**外链实现**（需改主进程）：

```js
win.webContents.setWindowOpenHandler(({ url, frameName }) => {
  // 仅重型卡 partition 的 frame 放行 → 系统浏览器
  // 其余保持 deny
});
```

> 现有代码是无条件 `deny`，改动后必须回归测试「主界面点外链仍被拦」。

## 八、性能与内存

| 项 | 数值 / 策略 |
| --- | --- |
| 首次加载 | 2.04 MB JS + 478 KB CSS，首次 3~8 秒（中转页给进度提示） |
| 二次加载 | partition 自带 HTTP 磁盘缓存，通常 < 1 秒 |
| 单卡内存 | 约 100~300 MB（独立渲染进程） |
| 同时打开 | **只保留 1 个**，切卡销毁旧的 |
| 切模式（去别的库） | `v-show` 不销毁，状态保持；超过 10 分钟未回 → 可选卸载释放（P2） |
| 备份耗时 | 只打包存储目录（不含缓存），通常几秒~十几秒，给进度条 |
| 缓存清理 | 面板右键「清理该卡缓存」：只清 `Cache/Code Cache/GPUCache`，**不动存储** |

## 附录 A：关键技术决策速查

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 承载方式 | 现有窗口内 iframe | 体验一体；Chromium 天然进程隔离 |
| 排除 `<webview>` | 不用它 | 需开 `webviewTag: true`，削弱全局安全基线，Electron 官方劝退 |
| 排除 `BrowserWindow` | 不用它 | 变成"另一个软件"，失去软件内管理的意义 |
| 排除 `BrowserView` | 不用它 | 需按坐标跟随 Vue 布局，缩放/拖宽都要同步 |
| 排除本地镜像 | 不镜像 | 产物 hash 化、持续更新、授权问题 |
| 存储隔离 | 一卡一 `persist:heavycard-<id>` | 按 origin 隔离仍会串同域名卡，按 partition 才彻底 |
| CSP 处理 | `app://heavycard/` 前缀跳过注入 | 与现有 `PREVIEW_PATH_PREFIX` 同款先例 |
| 外链 | 主进程按 frame 判定 → `shell.openExternal` | 全局 `deny` 不能整体放开 |
| 备份路径 | 直接复制 partition 存储目录 | 跨域导致无法通过 `executeJavaScript` 读取 |
| 同时打开 | 1 张 | 每张 100~300 MB 渲染进程，与项目内存守门原则一致 |

## 附录 B：与项目既有规范的对应

| 项目规范 | 本方案落实 |
