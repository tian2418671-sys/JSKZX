## 一、现象（用户视角）

用户在「⚡ API 引擎与模型设置」里**手填了一个可用的模型名**，然后点「拉取模型列表」——若上游接口返回的列表里不含该模型（或返回的是垃圾串），**用户填好的模型名会被静默改掉，并且立刻落盘**。

后果：

- 之后所有打标 / 测卡请求全部失败，但界面看不出原因（模型名已被换成垃圾值）；
- 重启后仍是脏值（已写入 `app_config.json`）；
- 用户不会想到「是刚才点了拉取列表导致的」。

> **定级理由**：这不是「不便」，是**用户配置被静默破坏且持久化** ⇒ P0。

## 二、根因（代码事实）

`js/composables/useChat.js` 第 84~99 行：

```js
let modelList = [];
if (Array.isArray(raw.data)) {
    modelList = raw.data.map(m => (typeof m === 'string' ? m : (m && (m.id || m.name)))).filter(Boolean);
} else if (Array.isArray(raw)) {
    modelList = raw.map(m => (typeof m === 'string' ? m : (m && (m.id || m.name)))).filter(Boolean);
}
if (modelList.length > 0) {
    availableModels.value = modelList;
    fetchModelStatus.value = `✅ 成功获取 ${modelList.length} 个模型！`;
    if (!modelList.includes(apiModel.value)) {
        apiModel.value = modelList[0];   // ← 病灶
    }
}
```

**三个独立缺陷**（缺一都不会出事，三个叠加才导致数据丢失）：

| # | 缺陷 | 说明 |
| --- | --- | --- |
| 1 | **零合法性校验** | 只做了 `.filter(Boolean)`，`"当前无可用模型"` 这类垃圾串能通过（实测来源：`gcli.ggchan.dev` 的 `/v1/models` 返回 `{id:"当前无可用模型"}`） |
| 2 | **静默覆盖** | 覆盖时不提示、不确认，`fetchModelStatus` 还显示「✅ 成功获取 N 个模型」，给人「一切正常」的错觉 |
| 3 | **落盘传播** | 覆盖后经 `syncConfigToDisk()` 写入 `app_config.json`，重启仍在 |

## 三、修复方案（按上游终审参数）

### 3.1 核心防线（比正则过滤更根本）

> **原 `apiModel.value` 非空 ⇒ 拉取成功后只更新候选列表 `availableModels`，绝不改写 `apiModel`。**
> **仅当 `apiModel.value` 为空字符串时，才自动填入 `modelList[0]`。**

这条是**根因级修复**：即使列表全是合法模型，也不该替用户改选择。

### 3.2 合法性过滤（上游修正后的参数）

| 项 | 参数 | 理由 |
| --- | --- | --- |
| 长度 | **2 ~ 128** | 上游指出：HuggingFace 完整路径（`organization/model-name-finetuned-xxxx-gguf`）可达 80~100 字符，原 64 会误杀 |
| 字符集 | `^[a-zA-Z0-9._\-:/@+]+$` | 上游指出：Vertex AI 格式含 `@`（`claude-3-5-sonnet@20240620`），部分中转含 `+` |
| 拦截目标 | 空格 / 换行 / 中文提示语 / HTML 标签（如 `<!DOCTYPE`） | 这些必然不是模型 ID |

**额外排除**（我方补充，写死在过滤函数里）：

- 与「无可用 / 不可用 / 暂无 / 未找到 / not available」等提示语同名或包含者；
- 纯数字串（模型 ID 极少纯数字，而错误码常见）。

### 3.3 修改后的完整逻辑（伪代码）

```js
const MODEL_ID_RE = /^[a-zA-Z0-9._\-:/@+]{2,128}$/;
const JUNK_HINTS = /无可用|不可用|暂无|未找到|not\s*available|no\s*model/i;

const isLikelyModelId = (s) =>
    typeof s === 'string' &&
    MODEL_ID_RE.test(s) &&
    !JUNK_HINTS.test(s) &&
    !/^\d+$/.test(s);

// ……解析出原始 modelList 后：
const rawList = modelList;                       // 保留原始，用于判断「是否全部被过滤」
modelList = rawList.filter(isLikelyModelId);

if (modelList.length === 0) {
    // ① 原 model 保留（已在 ref 里，什么都不做）
    // ② 明确告知，不再显示「✅ 成功」
    fetchModelStatus.value = rawList.length
        ? `⚠️ 接口返回的 ${rawList.length} 项均不像是模型名（示例：${String(rawList[0]).slice(0, 20)}），已保留当前模型「${apiModel.value || '（空）'}」`
        : '⚠️ 接口已响应，但未抓取到有效模型列表';
    availableModels.value = [];                  // 不把垃圾塞进下拉
    return;
}

availableModels.value = modelList;
const prev = (apiModel.value || '').trim();

if (!prev) {
    // 仅此一种情况允许自动填
    apiModel.value = modelList[0];
    fetchModelStatus.value = `✅ 成功获取 ${modelList.length} 个模型（原模型为空，已自动选中「${modelList[0]}」）`;
} else if (modelList.includes(prev)) {
    fetchModelStatus.value = `✅ 成功获取 ${modelList.length} 个模型（当前模型「${prev}」在列表中）`;
} else {
    // 原模型不在列表中，但**不改**，只提示
    fetchModelStatus.value = `✅ 成功获取 ${modelList.length} 个模型；当前模型「${prev}」不在列表中（已保留，未改动）`;
}
```

### 3.4 明确不做的

| 项 | 不做理由 |
| --- | --- |
| 弹确认框问「是否切换到某模型」 | 用户只是想看列表，弹框打断；状态栏文案已足够 |
| 自动改写 `apiConfig` 里其它字段（endpoint / type） | 与本缺陷无关，扩大改动面 |
| 在 `syncConfigToDisk` 加全局闸门 | 那是另一层保护，本缺陷应在源头修（见 §七 风险 R2） |
