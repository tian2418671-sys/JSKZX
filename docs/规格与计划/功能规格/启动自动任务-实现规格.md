# 启动自动任务 — 实现规格

> 本文件是什么：**下一版本待做功能**「启动自动任务」的实现规格——可选地在应用启动后自动执行轻量巡检 / 冷备 / 查重。
> 与相邻文档的分工：冷备见 [`整库冷备-实现规格.md`](整库冷备-实现规格.md)；质检统计见 [`一键质检流水线-实现规格.md`](一键质检流水线-实现规格.md)；总排期见 [`../计划与记录/下次更新计划-五功能升级.md`](../计划与记录/下次更新计划-五功能升级.md)。
> 最后更新：2026-10-03 ｜ 状态：✅ **已落地（2026-10-03）**（落地记录见文末）

## 一、目标

让「启动后要做的事」可配置、可关闭、不打扰：

- **轻量质检**（默认关）：启动后静默跑 S3+S4 统计（无标签 / 超长 / 空描述等），一行 toast 摘要 + 日志，点击可打开质检弹窗；
- **自动冷备**（默认关）：启动后触发整库冷备（快速模式，用已配置的冷备目录与保留份数）；
- **自动查重**（默认关，重操作）：启动后触发查重扫描（按当前库分发）。

> 扫描/加载本身已是启动既有行为，不在本功能范围内；本功能**只新增「启动后附加任务」**。

## 二、现状

- `App.vue::onMounted` 启动链：`loadAppConfig` 恢复（`isRestoringConfig` 守卫）→ … → 首个库加载/扫描（现有逻辑）；
- 无任何「启动后任务」配置项。

## 三、设计

### 3.1 配置（`ui.startupTasks`，走 `useConfigPersistence` 收集/恢复）

```json
{
  "enabled": true,
  "autoAudit": false,
  "autoBackup": false,
  "autoDedupe": false,
  "delayMs": 3000
}
```

- 全默认关（保护性默认），`delayMs` 默认 3000ms（等首屏稳定后再跑）；
- 老配置无此键 → 取默认（全关）——行为与现状完全一致。

### 3.2 执行器：新 `js/composables/useStartupTasks.js`

```text
scheduleStartupTasks(ctx) →
  等待条件：配置恢复完成（isRestoringConfig=false）且首个库扫描完成
  → setTimeout(delayMs)
  → 串行执行已启用任务（每项 try/catch，失败仅日志）
  任务实现：
    autoAudit  → 复用 tagStats/cardAudit 纯函数（不弹窗）：addLog 摘要 + toast「启动体检：无标签 X 张 · 疑似超长 Y 张（点击查看）」
    autoBackup → 调 backup:full:create（冷备目录未配置时跳过并日志提示）
    autoDedupe → 调 startSmartDedupe（若查重已在运行则跳过）
```

- **互斥与防呆**：进程内标志防重入；冷备通道自带「同一时刻一个任务」约束；查重运行中跳过；
- **不打扰**：全部结果合并为**一条** toast（避免轰炸）；noise 只进日志；
- 用户可在启动后手动取消未开始的后续任务？——v1 不做（任务轻，delayMs + 串行已足够）。

### 3.3 UI（设置入口）

- 「设置」菜单（`useCommands.js`，category '设置'）加「🚀 启动任务…」→ 新 `StartupTasksModal.vue`：
  - 总开关 + 三个任务开关（autoAudit / autoBackup / autoDedupe）+ 延迟毫秒输入（1000~10000）；
  - 每项附一句说明与代价提示（查重：大库耗时较长；冷备：需要先配置冷备目录）；
  - 保存即写 `ui.startupTasks`（`syncConfigToDisk` 防抖）。

## 四、验收口径

1. 全关（默认）：冷启动行为与 v2.3.5 **完全一致**（日志无新增、无 toast）；
2. 开 autoAudit：重启 → 首屏稳定后出现一条摘要 toast + 日志；点击 toast 打开质检弹窗；UI 无卡顿；
3. 开 autoBackup（已配置冷备目录）：重启 → 自动生成一份冷备；未配置目录 → 日志跳过提示，不报错；
4. 开 autoDedupe（副本库）：重启 → 自动发起查重；与手动查重互斥正常；
5. 配置持久化：重启后开关状态恢复；老配置（无 startupTasks 键）→ 全关。

## 五、风险与注意事项

- **启动竞态**：必须等「配置恢复 + 首次扫描完成」双条件（`isRestoringConfig` 与扫描标志），否则 task 可能对空库执行；
- 不在启动早期（onMounted 前段）执行任何重任务——避免拖慢首屏（项目对启动耗时有 `[startup]` 日志打点，回归时对比）；
- 自动任务的**外部副作用**（冷备写外部盘）必须在日志中留痕：时间 / 目标目录 / 结果；
- 与「一键质检」共享统计纯函数——**不得**为启动任务另写一套统计口径。
