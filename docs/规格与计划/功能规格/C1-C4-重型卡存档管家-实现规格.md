## 一、定位与边界

### 1.1 定位

在**不解析卡内内容**的前提下，让用户看得懂自己的存档：有多少份、占多大、多久没备份、换地址后还能不能用。

### 1.2 边界（沿用 v3 红线 · 只碰壳不碰芯）

| # | 约束 |
| --- | --- |
| 1 | **只读 manifest 元数据**，不读 leveldb 内容、不解析卡数据、不注入 AI |
| 2 | **零主进程改动、零新增 IPC**（C1~C4 全部复用现有 `heavycard:listBackups` / `heavycard:storageInfo` / `heavycard:restore`） |
| 3 | **C5 不做**（`.ldb` 因 Compaction 频繁变动，普通用户无可读性） |
| 4 | 不改备份格式、不改 `manifest` schema（`schema:1` 保持） |

## 二、四项能力

### 2.1 C1 存档时间线（按天折叠）

| 项 | 内容 |
| --- | --- |
| 数据 | `heavycard:listBackups` 返回的 `{name, kind, createdAt, gen, fileCount, totalBytes, url}` |
| 展示 | 按 `createdAt` 的**日期**分组（折叠），每天内按时间倒序 |
| 每行 | `HH:mm` · 类型徽标（手动 / 自动 / 退出） · `formatBytes(totalBytes)` · `gen` |
| 折叠规则 | 默认只展开**最近 3 天**，更早的折叠为「更早（N 份）」 |
| 空态 | 「还没有备份 —— 点 📦 备份 创建第一份」 |

**为什么不全部平铺**：自动备份默认每 30 分钟一次，连续玩几小时就有十几份，全平铺会把面板拉爆。

### 2.2 C2 空间占用榜

| 项 | 内容 |
| --- | --- |
| 数据 | 各备份 `totalBytes` + 当前分区 `heavycard:storageInfo.bytes` |
| 展示 | ① 合计（备份总和 + 当前占用）② 按大小降序的前 N 份 ③ 每份占比条 |
| 校验 | **合计 === 各份之和 + 当前占用**（验收断言，差值须可解释） |

### 2.3 C3 换址沿用旧档（**含 Origin 校验 · 上游加固**）

#### 2.3.1 为什么必须校验 Origin

重型卡存档落在 `userData/Partitions/heavycard-<id>_g<gen>/`，**与 Origin（协议 + 域名 + 端口）强绑定**。
Chromium 的 LocalStorage / IndexedDB 按 Origin 隔离 ⇒ **跨 Origin 复制备份目录，LevelDB 读不出旧数据**。

> **代码事实**：`main/heavyCards/backup.js` 的 `buildManifest` 只记录 `url` 字符串，**恢复流程零 Origin 比对** ⇒ 隐患真实存在。

#### 2.3.2 判定矩阵（三方分支）

| 情况 | 判定条件 | 处理 |
| --- | --- | --- |
| **同源** | 两个 url 都能 `new URL()` 解析，且 `.origin` 相同且 **不为 `'null'`** | ✅ 允许沿用，提示「网址路径已变化，存档可继续使用」 |
| **跨源（http/https）** | 两者都能解析，`.origin` 不同 | ⛔ **默认不恢复** + 明确警告「跨域名/端口换址，浏览器内部存储可能无法读取」；用户可手动确认后仍继续 |
| **本地文件夹** | `origin === 'null'`（`file://`） | ⚠️ 文案改为「本地文件夹路径已变更，是否尝试沿用旧存档？」（上游微调指令） |
| **无法判定** | 任一 url 为空或解析失败 | ⛔ 按**保守**处理（要求用户确认），**禁止**两个 `'null'` 判为同源 |

#### 2.3.3 `file://` 陷阱（我方补充 1 · 上游已批准）

```js
new URL('file:///E:/card/a/index.html').origin   // === 'null'（字符串！）
new URL('file:///D:/other/index.html').origin    // === 'null'（同样是字符串）
// 若直接比对 ⇒ 'null' === 'null' ⇒ 误判同源
```

**实现要求**：`origin === 'null'` 时**不走同源分支**，走「本地文件夹」分支（提示文案不同，且需用户确认）。

#### 2.3.4 实现位置

纯前端判定（**不改主进程**）：读取 `listBackups()[0].url`（最新备份的 manifest url）与当前条目 `url` 比对；判定通过后，仅当用户点「沿用」时调用**现有** `heavycard:restore`。

### 2.4 C4 今日游玩推荐

| 项 | 数据 | 展示 |
| --- | --- | --- |
| 最近游玩 | `lastOpenedAt` | 「今天玩过」/「3 天前」/「从未」 |
| 累计时长 | `totalPlayMs` | 「累计 12 小时 30 分」 |
| 备份新鲜度 | `backupStats.lastBackupAt` | **「已 N 天未备份」告警**（上游 D-C4：这是存档管家最核心的价值信号） |
| 排序 | 按 `lastOpenedAt` 降序 | 前 5 张显示在面板顶部「继续游玩」区 |

## 五、历史 BUG 规避清单（**必读**）

| 历史缺陷 | 教训 | 本次规避 |
| --- | --- | --- |
| **AR-58**（浅拷贝只一层 ⇒ `settings.autoBackup` 仍是 Proxy ⇒ structured clone 抛错 ⇒ 点卡无反应） | 传给 IPC 前必须**逐字段深转** plain | 本次调用 `heavyCard.listBackups` / `storageInfo` 时**复用现有 `toPlainCard()`**，不自己构造对象 |
| **AR-60**（WebContentsView 在 OS 合成层，CSS `z-index` 无效 ⇒ 菜单被盖住） | 重型卡视图上方的任何浮层都必须通知主进程 `setVisible(false)` | 新增的**折叠/展开不产生浮层**（纯 DOM 内联），不触发遮挡；若将来加浮层，必须走 `anyModalOpen` |
| **AR-59**（布局上报 0×0 覆盖有效 rect ⇒ 视图永久压扁） | 0 值必须被闸门拦掉 | 本次不改布局上报；面板展开/收起会改变容器高度 ⇒ **需确认 `reportRect` 会被触发**（实施时验证视图跟随） |
| **AR-01 / AR-58**（Vue Proxy 无法 clone） | 同 AR-58 | 同上，复用 `toPlainCard()` |
| **CT-02 / AI-16**（computed 缺响应式依赖 ⇒ 永久旧值） | 依赖必须显式 | 时间线 computed 必须依赖 `heavyCardBackups.value`；验收含「备份后时间线立即多一条」 |
| **PK-31 / AI-17**（把「没读进来」演成「真的空」） | 未加载 ≠ 空 | `storageInfo` 失败时显示「无法读取」，**不显示 0 字节** |
| **DF-17**（两套字段口径） | 同一概念两个名字 | 大小一律用 manifest 的 `totalBytes`，不自行 `stat` 求和（`storageInfo.bytes` 是另一概念：当前分区占用） |
