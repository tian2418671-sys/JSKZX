## 一、定位与边界

### 1.1 定位

把打标产出的高频标签，转成「自动分组规则草稿」，让用户**先预览再决定**是否归位。

### 1.2 边界（硬约束）

| # | 约束 | 依据 |

| 5 | **B2 不做** | 上游永久否决（LLM 打标无确定性基线） |

### 2.2 Q5 双闸门（上游终审定锤）

#### 闸门一：`minCards`（单标签最低卡数门槛）

```js
const effectiveMinCards = clamp(
    Number.isFinite(Number(opts.minCards))
        ? Number(opts.minCards)
        : Math.floor(Number(opts.total) * 0.02),
    5, 50
);
```

| 库规模 | `floor(total*0.02)` | 门槛 | 实际含义 |
| --- | --- | --- | --- |
| 89 张（真库） | 1 | **5** | 某标签至少命中 5 张卡 |
| 1,000 张 | 20 | **20** | 至少 20 张 |
| 11,849 张（压测库） | 236 | **50** | 至少 50 张 |
| 20,000 张 | 400 | **50** | 至少 50 张 |

> ⚠️ **口径纠正（Round 2 曾误解）**：`minCards` 是**「单个标签至少要命中多少张卡」**，**不是**「最多生成多少条草稿」。
> 因此 11k 库 `minCards=50` 意味着**长尾标签根本进不来**，上游判断正确。

#### 闸门二：`maxDrafts`（最多输出条数）

```js
const effectiveMaxDrafts = clamp(Number(opts.maxDrafts) || 20, 1, 100);
```

先按 `count` 降序排序，再截断到 `effectiveMaxDrafts`。

> **为什么需要第二道闸门**：`minCards` 保证「不进来垃圾」，`maxDrafts` 保证「UI 不被刷屏」。两者缺一不可。

### 2.3 三重过滤（顺序不可调换）

| 顺序 | 过滤 | 判据 | 上游依据 |
| --- | --- | --- | --- |
| **1** | **在标签池内 ⇒ 跳过** | `commonTags.includes(tag)` | 上游 §1.5「天然黑名单」：`Male` / `Female` / `Furry` / `NSFW` 等 63 个基础维度标签不生成分组草稿 |
| **2** | **卡数不足 ⇒ 跳过** | `count < effectiveMinCards` | Q5 闸门一 |
| **3** | **已有同档案 ⇒ 跳过** | `${group}\u0000tag\u0000${pattern.toLowerCase()}` 命中已有 `dedupeKey` | Q4 |

#### 标签池为空时的兜底（我方补充 2 · 上游已批准）

```js
const poolEmpty = !Array.isArray(opts.commonTags) || opts.commonTags.length === 0;
// poolEmpty ⇒ 跳过第 1 重过滤，并在返回值里置 poolEmpty:true 让 UI 提示
```

> **必须尊重项目铁律**：`systemCommonTags` 是用户可清空的（`App.vue:3233` 注释：「含空数组 = 用户主动清空，一律尊重，绝不自动回填默认」）。
> 池空时 UI 提示「标签池为空（你曾主动清空），建议在预览中手动筛选」。

### 2.4 标签归一化

| 项 | 处理 |
| --- | --- |
| trim | 比对前统一 `String(tag).trim()` |
| 大小写 | **不做大小写合并**（酒馆标签大小写有语义，合并会造成两个不同分组被误判重复） |
| 空标签 | 直接丢弃（`tagCounts` 理论上不含，但需防御） |
| 分组名 | 直接用标签原文（可含中文、括号、斜杠）；落盘前由 `sanitizeFolderName` 处理（**不在本函数内做**，保持一致口径） |

### 2.5 输出示例

输入：`tagCounts = Map{ '病娇':120, 'Female (女性)':200, '傲娇':80, '冷门标签':3 }`，`total=11849`，`commonTags` 含 `Female (女性)`

```js
{
  drafts: [
    { group:'病娇', match:{type:'tag',pattern:'病娇'}, count:120, note:'', reason:'命中 120 张卡 ≥ 门槛 50' },
    { group:'傲娇', match:{type:'tag',pattern:'傲娇'}, count: 80, note:'', reason:'命中 80 张卡 ≥ 门槛 50' }
  ],
  filtered: { inPool:[{tag:'Female (女性)',count:200}], belowMinCards:1, duplicate:0 },
  effectiveMinCards: 50,
  effectiveMaxDrafts: 20
}
```

## 三、B1 交互流程

```text
AutoGroupModal（现有）
└─ 「📋 收纳规则」页签内新增按钮：🏷 从高频标签生成草稿
     ├─ 点击 → 用当前 tagCounts 生成草稿（纯函数，毫秒级）
     ├─ 弹出预览面板（可折叠）：
     │    ├─ 头部：「已过滤：池内基础标签 N 个 / 卡数不足 M 个 / 已存在 K 条」
     │    ├─ 参数微调：门槛 [minCards] 条数上限 [maxDrafts]  ← 均可手改，改后立即重算
     │    ├─ 列表：每条一行（☑ 勾选 / 分组名 / 命中 N 张）
     │    └─ 工具：全选 / 反选 / 只看前 10
     ├─ 点「加入规则表」→ 仅追加到弹窗内的规则表（内存态）
     └─ 之后仍需走现有流程：💾 保存 → 🔍 预览与执行 → ▶️ 执行选中
```

> **硬约束**：在用户点 `▶️ 执行选中` 之前，**库文件零变化**。

### 5.1 B3 走 emit 还是注入（AR-54 教训）

`QualityCheckModal` 是纯展示组件，**不应直接持有 `openAITagModal` 引用**。两条路径：

| 方案 | 评估 |
| --- | --- |
| **推荐**：Modal `$emit('open-ai-tag')` / `$emit('open-auto-group')`，`App.vue` 接住 | 符合既有架构；但**必须同时在 setup 返回对象与 `ctx` 里加**（AR-54 型陷阱） |
| 备选：把按钮放在 `useQualityCheck` 生成的报告文案里 | ❌ 报告是纯文本，不可点击 |

> **采用推荐方案**，并在验收中**专门测「点这两个按钮」**（AR-54 教训：新增 `@事件` 必须核对 ctx）。

## 六、历史 BUG 规避清单（**必读**）

| 历史缺陷 | 教训 | 本次规避 |
| --- | --- | --- |
| **AR-54**（ctx 漏暴露 ⇒ 按钮点了没反应） | 新增 `@事件` 必须核对 setup 返回对象 **和** `ctx`；验收必须真实点按 | B3 新增 2 个 emit ⇒ **两处都要加**；验收含真实点按 |
| **AR-53**（闭包内未定义引用，守卫报 0 违规） | 传给 composable 的箭头函数用了未导入的符号 | `draftProfilesFromTags` **按名 import 到 `AutoGroupModal.vue`**（AR-11：Options API 模板不能用模块级 import ⇒ 必须在 `methods` 里包一层） |
| **AR-11**（纯 Options API 组件模板直接用模块级 import 函数） | `GraphModal` 同族坑 | 模板里调用 `methods.draftFromTags()`，不直接在模板引用 import 的函数 |
| **AR-56**（`data` 键与 `methods` 同名） | 同名覆盖 ⇒ 静默空串 | 新 `data` 键 `draftPreview` / `draftOpts`，`methods` 用 `draftFromTags` / `applyDrafts`，**无重名** |
| **AR-55**（插入锚点撞错函数 ⇒ TDZ 白屏） | 加参数加错位置 | `draftProfilesFromTags` **追加在 `autoGroup.js` 文件末尾**，不插入现有函数之间 |
| **PK-29**（Union-Find 传递链误聚） | 相似性传导会误聚 | 本方案**不做任何聚类**（一标签一分组，无传导） |
| **AI-08**（同毫秒 id 碰撞） | 生成 id 需稳定唯一 | 草稿**不预生成 `id`**，交由 `normalizeGroupProfiles` 补（其内部已有稳定兜底） |
| **DF-17**（两套字段口径） | 同一概念两个名字 | 档案结构严格复用现有 schema（`group` / `match.type` / `match.pattern`），**不新增字段** |
| **AR-50 / AR-51**（两套口径数字打架） | 展示与判定同源 | `count` 直接用 `tagCounts` 原值，**不重算** |

## 八、风险

| 编号 | 风险 | 严重度 | 缓解 |
| --- | --- | --- | --- |
| RB1 | 生成的草稿过多淹没用户 | 中 | **双闸门**（`minCards` + `maxDrafts=20`）+ 默认只勾前 10 |
