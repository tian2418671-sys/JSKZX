## 零、 v2 → v2.1 核心修正说明（致下游开发）

结合现有代码库（`main.js` / `package.json` / `main/fullBackup.js`） 与 Electron 29 底层机制，原 v2 方案存在 4 处会导致 P0/P1 卡死的技术冲突，v2.1 已做如下修正：

1. **容器由 `<iframe>` 改为受控 `<webview>`（或 `WebContentsView`）**：
* **原因**：标准 HTML `<iframe>` 不支持 `partition` 属性，强制共用主窗口 `defaultSession`（会导致重型卡与主界面串档、且被 `main.js` 的全局 `CSP_HEADER` 拦截 `https://` 资源导致白屏）。


* **修正**：采用 `<webview partition="persist:heavycard-..." allowfullscreen>`，并在主进程 `will-attach-webview` 中**强制剥离 `preload`、强制开启 `sandbox: true`、强制校验 `partition` 前缀**，兼顾 DOM 排版便利性、物理 Session 隔离与最高安全基线。




2. **解决 LevelDB 运行时文件锁与恢复损坏问题**：
* **原因**：Windows 下 Chromium 一旦挂载过某 `partition`，后台 Storage Service 会持续锁死 LevelDB 的 `LOCK` 文件并在内存缓存状态，仅卸载 DOM 无法释放锁，直接覆盖磁盘会导致数据库损坏（Corruption）被清空。
* **修正**：**备份时**先卸载容器并调用 `await session.fromPartition(p).flushStorageData()` 刷盘，拷贝时过滤 `LOCK` 文件；**恢复时**采用「Partition 世代号轮换（Generation Switching）」**——将备份解压到全新目录 `Partitions/heavycard-<id>_g<N+1>`，更新该卡的 `partition` 字段后直接挂载新 Partition，实现**免重启、零锁冲突、秒级无损恢复，旧目录在下次启动时静默清理。


3. **修复 `before-quit` 异步备份被强杀问题**：
* **原因**：Electron 的 `before-quit` 是同步事件，直接跑异步备份会被进程强行中断。


* **修正**：增加 `isQuittingAfterBackup` 状态锁，首次触发 `e.preventDefault()` 拦截退出，限时（如 5 秒）执行完 `flushStorageData` 与目录拷贝后再调用 `app.quit()`。


4. **备份格式对齐 `main/fullBackup.js`（目录快照代替 zip）**：
* **原因**：项目 `package.json` 无 `archiver`/`adm-zip` 依赖，Node 原生 `zlib` 不支持多文件目录打包。


* **修正**：完全复用 `main/fullBackup.js` 的 `fs.cpSync` 目录快照模式（几十毫秒极速完成，零外部依赖）；仅在 P2「导出单文件迁移」时调用系统内置 `tar -a -c -f xxx.zip` 生成压缩包。

## 一、定位与边界（定稿）

### 1.1 一句话定位

**重型卡是"能玩的收藏品"，软件是它的展柜兼管理员 —— 不碰内容，只管摆放和保管。**

### 1.2 软件的四项职责

| 职责 | 具体表现 | 用户得到的价值 |
| --- | --- | --- |
| **A 启动器** | 侧边栏入口、列表选卡、一键打开 | 不用记网址、不用翻书签

 |
| **B 保险柜** | 一卡一存档、自动备份、手动备份、免重启恢复、迁移、删除 | 玩几十小时的存档不会因为清缓存/换电脑而丢

 |
| **C 统一入口** | 多卡统一列表：名称/图标/备注/上次玩/占用/备份状态 | 几十张卡也不会乱

 |
| **D 展示游玩** | 整块渲染、可交互、切走再回来状态还在 | 在软件里真的能玩

 |

### 1.3 明确不做（红线）

| 不做 | 原因 |
| --- | --- |
| 解析卡内存档（剧情/变量/角色/时间线） | 属于"碰芯"，格式由作者随时改，逆向维护成本极高

 |
| 编辑卡内任何数据 | 只做整包/目录级操作

 |
| 向卡内注入 API Key / 接管 AI 推理 | 密钥风险 + 逻辑耦合 + 随版本失效

 |
| 修改/镜像站点源码 | 产物 hash 化、持续更新、授权问题

 |
| 让卡调用软件的文件系统（不注入 preload） | 一旦注入，卡内脚本可读写磁盘，安全红线

 |

### 1.4 与现有功能的边界

| 现有功能 | 关系 |
| --- | --- |
| 测卡工作区（`chatEngine`） | **完全独立**。重型卡不走我们的对话引擎

| 插件工作区（`usePlugins`） | 完全独立。插件是本地脚本，重型卡是远程 SPA

### 5.3 受控 `<webview>` 属性与主进程安全守门（定稿）

**前端模板 (`HeavyCardWorkspace.vue`)**：

```html
<webview
  v-if="activeCard && isWebviewMounted"
  :key="activeCard.partition"
  ref="webviewRef"
  :src="activeCard.url"
  :partition="activeCard.partition"
  allowpopups="false"
  webpreferences="contextIsolation=yes, nodeIntegration=no, sandbox=yes"
  class="w-full h-full border-0 bg-black"
/>

```

**主进程安全守门 (`main.js`)**：
在 `createWindow` 的 `webPreferences` 中开启 `webviewTag: true`，但紧跟以下铁律守门逻辑，确保安全基线不降级：

```js
app.on('web-contents-created', (_event, contents) => {
  // 1. 拦截所有 webview 挂载，强制剥离 preload 与 Node 权限，限制 partition 命名空间
  contents.on('will-attach-webview', (waEvent, webPreferences, params) => {
    delete webPreferences.preload;
    delete webPreferences.preloadURL;
    webPreferences.nodeIntegration = false;
    webPreferences.contextIsolation = true;
    webPreferences.sandbox = true;

    const part = String(params.partition || '');
    if (!part.startsWith('persist:heavycard-')) {
      waEvent.preventDefault(); // 非重型卡专用 partition 一律拒绝挂载
      return;
    }
    if (!/^https?:\/\//i.test(params.src || '')) {
      waEvent.preventDefault(); // 仅允许加载 http/https
    }
  });

  // 2. 针对重型卡獨立 webContents 的外链与导航管控
  if (contents.getType() === 'webview') {
    contents.setWindowOpenHandler(({ url }) => {
      if (/^https?:\/\//i.test(url)) {
        shell.openExternal(url).catch(() => {});
      }
      return { action: 'deny' };
    });
  }
});

```

> **优势**：主窗口原有的 `win.webContents.setWindowOpenHandler`（全局 `deny`）和 `defaultSession` 的 CSP 注入代码**一行都不用改**，完全零回归风险！

## 六、备份与恢复系统（v2.1 核心重构）

### 6.1 为什么不能直接覆盖当前 Partition 目录？

Chromium 的 Storage Service 一旦初始化了某个 `persist:heavycard-xxx` 的 IndexedDB，就会在本次应用生命周期内一直持有 LevelDB 文件句柄与内存状态。直接覆盖磁盘文件会导致新旧 Manifest 冲突，重载后存档直接被 Chromium 判定损坏并清空。

### 6.2 备份流程（`flushStorageData` + 过滤锁文件）

```text
触发备份（手动 / 定时 / 退出前）
  → 1. 若为手动备份：前端先设 isWebviewMounted = false 销毁 <webview>，等待 200ms
  → 2. 主进程调用：
       const ses = session.fromPartition(card.partition);
       await ses.flushStorageData(); // 强制将内存 MemTable 刷入磁盘 SSTable
  → 3. 复制该 Partition 下的 ['Local Storage', 'IndexedDB', 'Session Storage']
       到 heavycard-backups/<cardId>/<timestamp>_<kind>/
       （使用 fs.cpSync，filter 跳过文件名为 'LOCK' 的锁文件，并捕获单文件 EBUSY）
  → 4. 写入 manifest.json，执行保留策略（清理超额的旧 auto 备份，永留最后一份 manual）
  → 5. 前端重新设 isWebviewMounted = true 恢复显示

```

### 6.3 恢复流程（Partition 世代号轮换，免重启无损恢复）

```text
用户点「恢复」→ 选择一份历史快照 → 二次确认
  → 1. 先对当前状态执行一次 kind='pre-restore' 的自动快照（防呆兜底）
  → 2. 前端设 isWebviewMounted = false 卸载当前 <webview>
  → 3. 主进程计算下一世代号：nextGen = (card.gen || 1) + 1
       新 Partition 名称：nextPartition = `persist:heavycard-${card.id}_g${nextGen}`
       新 Partition 磁盘路径：targetDir = getPartitionDiskPath(nextPartition)
  → 4. 由于 nextPartition 从未被 Chromium 加载过，没有任何文件锁！
       直接将备份快照中的 Local Storage / IndexedDB 完整拷贝至 targetDir
  → 5. 将旧 Partition 路径记入待清理队列，更新 card.gen = nextGen, card.partition = nextPartition
  → 6. 前端挂载 <webview :key="card.partition" :partition="card.partition">
       Chromium 全新读取 targetDir 中的 LevelDB，存档 100% 完美恢复，无需重启软件！

```

> **旧世代目录清理**：软件每次启动（`app.whenReady()` 早期，任何 `<webview>` 尚未挂载前），扫描 `Partitions/` 目录，删除所有不在当前 `ui.heavyCards` 活跃 `partition` 列表中的旧世代目录（`_g1` 等）。

### 6.4 退出前自动备份（`before-quit` 异步拦截锁）

在 `main.js` 中：

```js
let isQuittingAfterHeavyBackup = false;
app.on('before-quit', (event) => {
  if (isQuittingAfterHeavyBackup) return;
  const cardsToBackup = getHeavyCardsNeedingExitBackup();
  if (cardsToBackup.length === 0) return;

  event.preventDefault(); // 必须阻止同步退出
  Promise.race([
    runExitBackupsForHeavyCards(cardsToBackup),
    new Promise((resolve) => setTimeout(resolve, 5000)) // 5秒超时保护，绝不卡死退出
  ]).finally(() => {
    isQuittingAfterHeavyBackup = true;
    app.quit();
  });
});

```

> **发给下游的沟通话术：**
> 辛苦评估一下上面这份 **v2.1 架构修正版方案**。为了避免 P0/P1 踩 Electron 的底层坑，我们针对原 v2 方案做了 4 处关键修正，请确认以下改动是否全部清晰可行：
> 1. **容器切换确认**：原方案的 `<iframe>` 无法设置独立 `partition` 且会被主窗口 `defaultSession` 的 CSP 拦截 `https` 请求。v2.1 改为 **开启 `webviewTag: true` + 主进程 `will-attach-webview` 强校验守门（禁 preload、强开 sandbox、限定 `persist:heavycard-*`）**。这块实现是否有异议？
> 2. **LevelDB 锁与恢复机制确认**：Windows 下直接覆盖正在使用的 Partition 目录会导致 IndexedDB 损坏。v2.1 改为 **备份前调用 `session.flushStorageData()` 并跳过 `LOCK` 文件**，**恢复时解压到新世代目录（`persist:heavycard-<id>_g<N+1>`）并切换挂载，旧目录在下次启动早期清理**。请确认该世代轮换逻辑在 `useHeavyCards.js` 和 `heavyCardBackup.js` 中是否好写？
> 3. **备份格式确认**：鉴于项目无第三方 zip 依赖，P1 阶段完全对齐现有的 `main/fullBackup.js`，采用 **文件夹直接拷贝（`fs.cpSync`）** 作为备份快照格式，P2 做跨机迁移时再用系统 `tar` 导出单文件。是否同意？
> 4. **退出前备份拦截确认**：`main.js` 的 `before-quit` 需使用 `event.preventDefault()` + 5 秒超时保护执行异步备份，完成后再重新 `app.quit()`。请确认与现有退出逻辑无冲突。
