### 🔴 P0 · 真实数据污染缺口（最重要的一条）

**卡片保存路径不剔除 `uid` / `_` 前缀 UI 字段 → 污染写进 PNG / 整合包**

对比三条写盘路径（我已逐条核对源码）：

| 写盘路径 | 是否清洗 |
|---|---|
| 世界书保存 `wb:save`（`main.js:2593`）+ 世界书导出 | ✅ `JSON.stringify(data, (k,v) => k.startsWith('_') \|\| k==='uid' ? undefined : v)` |
| **卡片保存** `file:saveCard`（`main.js:2391`） | ❌ `JSON.stringify(updatedJson, null, 2)` —— **无 replacer** |
| **PNG 卡写盘** `writeTavernPNGChunk`（`main.js:339`） | ❌ `JSON.stringify(updatedJson)` —— **无 replacer** |

**污染源**（`App.vue:3639-3642`）：

```js
const clean = JSON.parse(JSON.stringify(c, (k, v) => k.startsWith('_') ? undefined : v)); // 剔了 _
clean.uid = `${Date.now()}_...`;   // ← 又写回 uid
clean._collapsed = false;          // ← 又写回 _collapsed
```

**用户可见症状**：导出的卡 JSON 里混入酒馆原生没有的 `uid` / `_collapsed` 字段（DF-03 同类现象）。

### 🔴 P0 · 脚本自身在 PS 5.1 下乱码（我已实测复现）

`scripts/tools/dev-run.ps1`（169 个中文字符）与 `scripts/tools/capacity-check.ps1`（128 个）
**均无 UTF-8 BOM** → Windows PowerShell 5.1 按 GBK 解码，脚本自身文案乱码。
AR-24 的 `chcp 65001` 只修**输出**编码，不修**输入**解码。

```
用 PS 5.1 的默认解码（GBK/codepage 936）读取：
  dev-run.ps1        UTF-8: # dev 模式一键热启动（修复终端中文乱码）
                     GBK  : # dev 妯″紡涓€閿儹鍚姩锛堜慨澶嶇粓绔腑鏂囦贡鐮侊級        ❌ 乱码
  capacity-check.ps1                                                            ❌ 乱码
```

> 修法：给两个脚本**加 UTF-8 BOM**（PS 5.1 与 pwsh 7 都认）。
> ⚠️ 反向做法（改成纯 ASCII）会丢失中文注释可读性，不推荐。
> 附带纠正：子代理曾判定 `capacity-check.ps1` 是"纯 ASCII 且写明该陷阱"——
> 实测它有 128 个中文字符，该判定有误。
