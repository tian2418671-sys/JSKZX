# 🧩 角色卡「插件」页签 · 实现规格

> 定位：**已落地的实现规格**（2026-09-19）。记录「角色卡工作区里新增的『插件』页签」要做什么、按什么形态读数据、怎么编辑保存、验收标准与踩到的坑。
> 相关代码：`js/utils/cardPlugins.js`、`js/composables/useCardPlugins.js`、`js/components/EditorPanel.vue`（`currentTab === 'plugins'`）、`js/components/CardPluginModal.vue`、`App.vue`（tabs / ctx）。
> 相关单测：`test/cardPlugins.test.mjs`（11 例，解析与形态兼容）、`test/cardPluginsPanel.test.mjs`（10 例，组合式函数链路：编辑/新增/删除/展开）。

---

## 一、目标与边界

**目标**：打开某张角色卡后，能在卡片编辑器里直接看到并修改「这张卡自带的酒馆插件」（主要是酒馆助手脚本），随「保存卡片」一起写回卡片文件。

**与项目既有「插件」概念的分工**（避免出现「第 N 套插件」）：

| 概念 | 位置 | 数据来源 | 本页签的关系 |
|---|---|---|---|
| 插件工作区 | `usePlugins.js` / `PluginWorkspace.vue` / `pluginScanner.js`，`appMode === 'plugins'` | **磁盘目录**里的酒馆助手脚本 / 散落 JS / 扩展工程 | 完全独立，本页签不改动它 |
| 卡内「正则脚本」页签 | `App.vue` 的 `regexScripts` + `useStatusbarPreview.js` | `data.extensions.regex_scripts` | 本页签**只统计条数**并提供跳转按钮，不重复实现编辑器 |
| 测卡引擎的 `useChatPlugins` | `js/composables/chat/` | 引擎内部 JSON 扩展（localStorage） | 无关 |
| **本体：卡内插件页签** | 本规格 | **卡片文件内嵌**：`extensions.tavern_helper.*` 等 | 跟随卡片保存 |

**不做**：不新增 IPC / 不改 `preload.js` / 不动磁盘插件体系 / 不聚合全库（只针对**当前打开这张卡**）。

## 二、真实数据形态（实测，不是猜的）

扫描方式：只在 `%TEMP%` 写临时脚本，解析 PNG 的 `tEXt`/`iTXt` 块（`chara` = V2、`ccv3` = V3），对 `E:\AI\酒馆工具\角色卡` 的 **83 个文件 / 76 张可解析卡**做字段统计（只读，不改卡）。

| 路径 | 命中卡数 | 形态（必须兼容） |
|---|---|---|
| `data.extensions.tavern_helper` | 25 | ① `{ scripts: [...], variables: {...} }`（主流）；② **键值对数组** `[["scripts",[...]],["variables",{...}]]`（同字段另一种导出形态） |
| `data.extensions.TavernHelper_scripts` | 4 | 旧版：`[{ type:'script', value:{ id, name, content } }]` —— **脚本字段外层多包一层 `value`** |
| `data.extensions.regex_scripts` | 38 | 内嵌正则（归「正则脚本」页签） |
| `data.extensions.cfMvuVarGroups` / `mvu_worldbook_name` | 1 | MVU 变量组定义 / 绑定世界书 |
| `data.extensions.xiaobaix-tasks` / `xiaobaix-template` | 3 / 1 | 小白X 写卡工作台数据 |
| `data.extensions.chub` / `aifuck_metadata` | 1 / 1 | 第三方站点元数据 |
| `data.extensions.depth_prompt` / `world` / `talkativeness` / `fav` | 66+ | ST 原生字段（不算插件，进不了「未识别」列表） |

脚本条目真实字段：`{ type:'script', enabled, name, id, content, info, button, data }`；正文可能是几千行 JS（悬浮窗 / 防奶人那类）。

> 历史教训：旧版只认**路径式键名** `extensions["tavern_helper/scripts"]` 与少数顶层键 → 永远匹配不到 → 用户看到「没有脚本」。本页签的解析器按「**先列容器候选、命中即用**」实现，且**容器存在即为命中**（空容器也出分组）。

## 三、数据层（`js/utils/cardPlugins.js`）

纯函数、零 Vue / 零 Electron 依赖，可 `node --test` 直接测。

| 导出 | 作用 |
|---|---|
| `harvestCardPlugins(data)` | 采集全卡插件：`{ groups, foreignKeys, total, enabled, chars, containerPath, diagnostics }` |
| `resolveScriptContainer(data, {create})` | 定位脚本容器，返回 `{ list, sourcePath, legacy, pendingShape, shapeWarning }`；`create=true` 时**按既有形态**补容器 |
| `resolveVariablesContainer(data)` | 定位 `tavern_helper.variables`（兼容键值对数组） |
| `buildScriptItem(entry, index, sourcePath)` | 单条脚本 → 可编辑模型（含 `host` = **真实落点**、`contentKey/nameKey/enabledKey`、`legacy`） |
| `writeScriptField(item, field, value)` | 写回（`name` / `enabled` / `content`），旧版形态**写内层 `value`** 并镜像外层 |
| `createScriptEntry({legacy})` | 新建条目：主流形态 `{type,enabled,name,id,content,info,button,data}`；旧版形态保持 `value` 包装 |

三条硬约束（写代码时别破坏）：

1. **容器存在就出分组**（`empty: true` 也要出）——不许静默显示「没有」；
2. **编辑落在原对象上**（`item.host`），否则 `shallowRef` 卡片数据感知不到、也写不回文件；
3. **新增跟随既有形态**，绝不把键值对数组 / `value` 包装结构改坏。

分组产出：`tavern-helper`（可编辑）、`tavern-variables`、`mvu-var-groups`、`mvu-worldbook-name`、`ext-<第三方键>`（均只读）。

## 四、交互层（`js/composables/useCardPlugins.js` + 界面）

页签入口：`App.vue` 的 `tabs` computed 增 `{ id:'plugins', name:'插件', icon:'🧩', badge: cardPluginCount }`，受 `viewOptions.showPlugins` 控制（顶部视图菜单可开关）。

页签内容（`EditorPanel.vue`）：

- **标题栏**：脚本条数徽标 + 容器来源路径 + 「⚡ 正则 N 条」跳转 + 「➕ 添加脚本」；
- **脚本条目**：名称输入框 / 类型徽标 / 「旧版结构」标记 / 行数·字符数 / 启用勾选 / `▼ 展开编辑` / `⛶ 放大` / `🗑️ 删除`；
- **展开编辑**：内嵌 `CodeEditor.vue`（项目已有 CodeMirror 封装：语法高亮 / 行号 / 查找 / ✨ 格式化），高度 420px，**点了才挂载**；
- **⛶ 放大**：`CardPluginModal.vue` 全屏（`fixed inset-0`）承载同一个 `CodeEditor`，支持 Esc 关闭、显示行数与字符数、可改名称/启用；
- **空态**：分两种文案 —— 「识别到容器但是 0 条」与「没有发现容器（可以新建）」，并列出**本卡 extensions 现有键**的诊断标签 + 未识别扩展键提醒；
- **只读分组**（变量 / MVU 变量组 / 第三方扩展）：点「▼ 查看」用**只读** `CodeEditor`（JSON）展示，避免误改结构。

保存链路：编辑 → 内存中的卡片数据 → 既有「保存卡片」按钮写回文件（**不需要新 IPC**）。

响应式与性能决策：

| 决策 | 原因 |
|---|---|
| 名称/启用改动 → 立即 `refreshCardData()` | 与「正则脚本」页签的 `syncRegexScriptField` 一致，保证勾选/徽标即时刷新 |
| 正文改动 → **400ms 防抖**后再 `refreshCardData()`，收起/关弹窗时立即 flush | CodeMirror 每次按键回传全文；逐键刷新会反复失效该卡 Token 缓存（侧栏徽标重算） |
| 脚本「行数」**惰性计算** | 解析函数在每次 `refreshCardData()`（如描述框逐键输入）都会重跑，而最重的一张卡脚本正文 ~2MB，逐键 `split('\n')` 白花约 1ms；惰性后实测 0.95ms → **0.012ms**（全库平均 0.023 → 0.003ms） |
| 只读 JSON 文本 → `WeakMap` 懒 stringify + 缓存 | `variables` 可能有上万行，不能每次渲染都 `JSON.stringify` |
| 切卡时清空展开态 | 防止上一张卡的 uid 悬空 |

## 五、踩坑记录（重要）

1. **弹窗不能放在页签容器里**：项目全局样式给 `.border/.border-b/.border-r/.border-t` 加了 `transform: translateZ(0)`（DPI 锐化），**带这些类的祖先会成为 `position: fixed` 的包含块** → 页签内部的 `fixed inset-0` 会跑偏。因此 `CardPluginModal` 挂在 `App.vue` 顶层（与 `TextModal` 等一致，也符合「弹窗必须在 `#app` 内」的既有约束）。
2. **ctx 四步暴露一个都不能漏**：`定义（组合式函数）` + `App.vue 解构` + `ctx 暴露` + `子组件 return 解构`。本次新增 15 个绑定时逐条核对（历史缺陷 AR-13 就是漏暴露导致模板静默失效）。
3. **`tabs` 里引用后置声明的 computed 是安全的**（`renderableScripts` 已有先例：`tabs` 定义在前、组合式函数在后，computed 惰性求值）；但**带 `immediate` 的 watch 不行**（会 TDZ 崩溃）。
4. **搜索栏探针要过滤行**：侧栏里 `div.cursor-pointer + select-none` 不只有卡片行（标签面板 / 控制台也是），用 CDP 做端到端时须再要求「行内含 `img`（头像）」。
5. **`confirmDialog` 只接受一个字符串参数**（底层是 Electron `dialog.showMessageBox` 的 `message`）——传第二个参数会被**静默丢弃**，明细必须自己拼进同一个字符串；受影响写法参考 `deleteRegexScript`。
6. **原生确认框在自动化验证里点不到**：`dialog.showMessageBox` 是系统对话框，CDP 点不到，且 `window.electronAPI`（contextBridge 对象）**无法被劫持**（赋值静默失败）→ 删除/清空这类带确认的链路要写成组合式函数单测验证（见 `test/cardPluginsPanel.test.mjs`）。
