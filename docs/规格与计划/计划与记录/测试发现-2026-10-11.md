## 阶段 B：导入 —— 见下（含真 bug）

### #bug-1 头部「导入角色卡」的 accept 属性丢失（DF-22 回归）
- 现象：`#app input[type=file]` 的 `accept` 属性为 **null**（应为 `.png,.webp,.json`）
- 根因：`appCtx.importAccept` 运行时为 **undefined**（`typeof === 'undefined'`）
  - 绑定本身在（App.vue:6769 `importAccept: cardFormats.IMPORT_ACCEPT`；HeaderBar.vue:432 `importAccept: ctx.importAccept`）
  - 但 `cardFormats` 变量在该作用域取不到 ⇒ 或 provide 的 ctx 未含该键 / 解构丢失
- 影响：文件选择框退化为「所有文件」；声明与扫描白名单脱钩（DF-22 原始病根）
- **根因确证**：App.vue:796 `import cardFormats from '../../main/cardFormats.json'` 导入的是 **JSON 文件本体**，
  而该 JSON 只有 `scannable/savable/image`（**无 `IMPORT_ACCEPT`**）⇒ `cardFormats.IMPORT_ACCEPT === undefined`。
  派生常量 `IMPORT_ACCEPT` 在 `js/utils/cardFormats.js`（App.vue:797 只导入了 `isPathSavable/unsavableReason`，**未导入 IMPORT_ACCEPT**）。
- **修复方向**：App.vue 改为 `import { IMPORT_ACCEPT } from '../utils/cardFormats.js'`（或由 JSON 的 `scannable` 派生），两处 provide 同步。


### #bug-2 世界书 .json 走 JSONL 入口解析不到词条 —— ⚠️ 澄清为「探针用错入口」（非 bug）
- 现象：把 `.json` 世界书注入到 `accept=".json"` 的 input（`importWbFromJsonl`），计数不涨
- 澄清：`importWbFromJsonl` **只做 JSONL/Rentry 逐行解析**，标准 `.json` 世界书不走此入口
  - 标准 `.json` 世界书的应用内入口是**全局世界书目录自动扫描**（`scanWorldbookDir`）
- 结论：**非 bug**（入口用错）
