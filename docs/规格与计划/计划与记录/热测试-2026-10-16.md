**修复**（`js/components/App.vue` Esc 分支前置，2026-10-16）：
```js
const cardMenuOpen = !!(contextMenu.value && contextMenu.value.visible);
const wbMenuOpen = !!(wbContextMenu.value && wbContextMenu.value.show);
if (cardMenuOpen || wbMenuOpen) {
    if (cardMenuOpen) closeContextMenu();
    if (wbMenuOpen && typeof closeWbContextMenu === 'function') closeWbContextMenu();
    return;   // 菜单是最表层浮层，优先关闭并结束
}
```
**复测**（纯 state 判定）：右键能开 ✅｜**按 1 次 Esc 即关** ✅｜点外部可关 ✅｜互斥 ✅
**回归**：`guard:scope` 0 未定义 ✅｜`npm test` **1026/0** ✅｜`build:web` ✅｜重启冒烟无 `[Vue 错误]` ✅

## 🐛 #hot-bug-1 【真 bug】拉取模型列表会把用户配置的模型**静默覆盖成垃圾值**

- **现象**：点「⚡ API 引擎与模型设置 → 拉取模型列表」后，`apiModel` 被改成 **`"当前无可用模型"`**
  （该中转站 `/v1/models` 返回的假模型 `{id:"当前无可用模型"}`）
- **根因**（源码确证）：`js/composables/useChat.js:96`
  ```js
  if (!modelList.includes(apiModel.value)) apiModel.value = modelList[0]; // ← 自动选中第一个
  ```
  未校验返回的模型名是否**像模型名**（无长度/字符/黑名单校验）；中转站返回垃圾时被**静默写入并落盘**。
- **影响**：用户点一下「拉取模型」就可能**丢失自己填好的模型名**（还已落盘），之后打标/测卡全部失败却看不出原因。
- **修复方向**：
  1. 拉取到列表后**不要静默覆盖** —— 至少 `nativeAlert` 提示「已拉取 N 个模型，是否切换？」或仅在用户显式选择时才改；
  2. 对返回项做**基本合法性过滤**（长度 2~64、不含空格 / 中文「无可用」类字样、匹配 `^[\w.\-:/]+$`）；
  3. 过滤后为空 ⇒ **保留原模型名**，只提示「接口返回的列表不可用」。
- **本轮处置**：已把 `apiModel` **恢复为** `假流式-gemini-3-flash-preview`（并 `saveApiConfig()` 落盘）✅
