### 2.2 数据流（旧实现全链路）

```text
[数据源]
  角色卡：内存 library（大库 ≥3000 张走 slimCard 瘦身态：清空内嵌世界书正文+备用开场白）
  世界书：L0 元数据 + L1 摘要（keyHashes/exactContentHash/simhash，主进程扫描时顺带产出）
  预设：  内存 presets（prompts 数组/对象两形态）

[指纹]
  角色卡：5 字段（description/personality/scenario/first_mes/mes_example）
          + 全字段（+character_book 词条/alternate_greetings/creator_notes/system_prompt/post_history_instructions）
          + 内嵌世界书触发词 keys（转 32 位 hash 精确 Jaccard）
  世界书：keys 的 keyHashes（bottom-k 截断 2000，双指针 Jaccard）+ 全文字符 4-gram simhash + MinHash(96 维)
  预设：  identifier 结构指纹 + 内容/顺序/启用状态/参数五维

[候选与闸门]
  同名：  精确同名即候选
  内容：  LSH 8 band 分桶（角色卡：全字段桶 + 5 字段桶）→ 两两 OR 闸门
          gate = （全字段 ≥0.85 或 5 字段 ≥0.85） 且 通过若干「否决」
[否决族]
  ① 世界书触发词矛盾否决（两侧 ≥2 键且 Jaccard < 0.05）
  ② 全字段分歧否决（仅一侧 0 词条时，全字段÷5字段 < 0.4）
  ③ 不同角色·共用世界书否决（keys ≥0.5 且 5 字段 <0.15 且 卡名相似 <0.3）
  ④ 模板剥离（DF）：同一字段值被 ≥5 张卡整段照抄且 ≥60 字 → 算指纹前整段剔除
[分组]
  union-find + **簇心校验**（合并前双方都要与对方簇心过闸门）；代表元取较长文本
[展示]
  类型分类（只产标签，绝不参与分组）+ 综合分排序（0.75×内容 + 0.25×keys × 长度惩罚）
[清理]
  trashFiles（进回收站）；风险项（仅同名/设定冲突）→ 按钮降级 + 确认框列文件名（`confirmCleanupWithRisk`）
```

## 三、算法与阈值总表（旧实现定稿值，**不要照抄，供分析**）

### 3.1 指纹

| 项 | 实现 | 备注 |
|---|---|---|
| simhash | 64 位 = number 双 32 位；**char 4-gram**；**step=4 采样**；FNV-1a 零分配 charCode 哈希 | BigInt 版 1387ms/本 → number 版 **173ms/本** |
| MinHash | 96 维 / 8 band × 12 行；FNV-1a **异或 + 雪崩混合**（PK-30 修） | 只作**复核**与展示值 |
| keyHashes | 触发词去重 + 小写 + NFC → `Uint32Array`（升序，bottom-k 截断 2000） | 原串 67.1KB/本 → hash **4.44KB/本**（15.1×） |
| exactContentHash | 排序后 entries 的 SHA-256（canonical JSON，键递归排序） | 「完全相同」的确定性判定（顺序不同 → hash 不同） |
| 归一化 | `trim().toLowerCase().normalize('NFC')`；文本另加「去空白/标点」 | 必须全库同一函数 |

### 3.2 阈值与常量（含标定依据）

| 常量 | 值 | 依据（真实库实测） |
|---|---|---|
| `SIMHASH_THRESHOLD` | **16**（曾 19） | 真实库无关对距离**低至 17**；T≤16 零误报零漏报，T=19 误报 10/18 对 |
| `CONTENT_SIMILARITY_THRESHOLD` | **0.85** | MinHash 复核闸门（仅复核，不参与分组决策） |
| `NAME_ONLY_MAX_DIST` | **24** | 同名卡：同源 p50=0 ｜ 无关 p50=31（间隙极大）；成本 4547 张 ≈ 2.0s |
| 触发词矛盾否决 | 两侧键数 **≥2** 且 Jaccard **< 0.05** | 无关 ≤0.15% ｜ 真同源最近 12.5% |
| 全字段分歧否决 | 比值 **< 0.4** | 假同源 0.19 ｜ 真同源 0.53~0.99（仅一侧 0 词条时启用） |
| 不同角色判定 | keys ≥ **0.5** 且 5 字段 < **0.15** 且 卡名相似 < **0.3** | 名似阈值落在实测空档 [0.22, 0.50] |
| 模板剥离（DF） | 同一字段值 **≥5 张**卡照抄且长度 **≥60** | 分享页 `first_mes` 1730 字 × **2107 张**；版权声明 185 字 × **1381 张** |
| 预设阈值（保守档） | 结构 **0.95** / 内容高 **0.90** / 内容低 **0.70** | 合成样本标定 TP=11/FN=0/FP=0/TN=3（⚠️ 真实库待扩样重标） |
| 长度惩罚 | `0.7 + 0.3 × min/max` | 世界书查重方案「第 2 步」 |
| 综合分 | `长度惩罚 × (0.75×内容 + 0.25×keys)` | **仅排序用**，未标定权重（真实库只有 8 对真重复，拟合=过拟合） |

### 3.3 相似类型分类（只产标签，**绝不决定分组**）

| 类型 | 判据 | 建议 |
|---|---|---|
| 🔁 完全重复 | `exactContentHash` 一致 | 可安全清理 |
| 🔑 触发重复 | keys 高 + content 低 + 长度相近 | 合并 keys 或改写，**别直接删** |
| 🔀 内容可合并 | content 高 + keys 低 | 合并为一本 |
| 🚨 设定冲突 | keys 高 + content 低 + 长度悬殊 | **人工裁决**（按钮降级） |
| 🔍 高度相似 | 其余 | 逐条对比 |
| ⚠️ 仅名称相同 | 两侧都低 | **勿清理**（按钮降级） |

## 七、设计教训与红线（重构必须继承）

1. **阈值必须在真实库扫**——合成样本的「负样本 min 31」被真实库「低至 17」推翻（T=19 → 误报 10/18）。
2. **探针要断言「结论正确」，不是「有输出」**——只采宽度不采数字 = 假绿（AR-46）；只断言「有分组」不校验「分组正确」= 假绿（PK-29）。
3. **「看起来随机」≠ 随机**——MinHash 哈希族必须单独验证函数间独立性（PK-30）。
4. **静默算出 0 比崩溃更坏**——用户会据此**删掉正确的书**（PK-26）；「静默长耗时」同理（PK-27）。
5. **按需/懒加载改造必须 grep 全部消费者**再逐个决定（PK-26 三轮修复的教训）。
6. **口径必须单一**：同一数字只有一条来源（宽度/数字两条路径 → AR-43/46）；跨轮口径要**显式统一**（瘦身态 vs 全量：1783/14 vs 1788/8）。
7. **判定只产标签，不决定分组**（类型分类契约）——否则重演 PK-29 / AR-48 式误删。
8. **清理动作不可逆 ⇒ 风险项必须降级 + 列文件名**（AR-48 / AR-52：四条清理路都要走统一 `confirmCleanupWithRisk`）。
9. **禁止「头疼捂嘴」**：报错是排查线索（DF-20），`silent` 只能用于批量场景且必须汇总真因。
10. **每个"修好 A 就看见 B"**（AR-50 第四形态）说明：**口径修好只是暴露问题的开始**，不是结束。

#### 11.4.2 「3 字 vs 4 字」问题（用户点名）——三选一【待填】

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A 严格同名 | 只按规范化后完全同名成组 | 零误报 | 用户报的场景**永远漏报** |
| B 包含关系放宽 | 一侧是另一侧子串（`林雨` ⊂ `林雨汐`）→ 视为**候选**（不直接成组） | 覆盖版本家族 | 「同名不同角色」也会进候选 → 必须再过内容/keys 闸门 |
| **C 相似度阈值 + 白名单**（推荐） | 名字相似 ≥ 阈值 **且** 至少一条独立正证据（keys ≥＿＿ / 内容 ≥＿＿ / 精确相同）才成组 | 兼顾召回与安全 | 需真实库标定名字阈值 |

**统一要求**：名字**只能做候选生成与「不同角色」否决**，**不得单独决定清理**（AR-48 教训）。

### 11.5 分组算法 ⭐

| 项 | 设计【待填】 | 硬要求 |
|---|---|---|
| 候选生成 | 例：规范化名桶 + keys 倒排共现 | 高频桶（>＿＿）必须跳过或降权，防桶爆炸（PK-25） |
| 合并闸门 | 例：`keys ≥0.5 && 内容 ≥0.85` 且通过全部否决 | **至少一条独立正证据**；不满足即不同组 |
| 否决族 | 例：模板剥离 / 一侧无书比值 / 不同角色 / 触发词矛盾 | 每条否决都要有**真实库标定的阈值**与反例样本 |
| 传递性 | **必须簇心校验**（合并前双方都与对方簇心过闸门） | 禁用朴素连通分量（PK-29 病根） |
| 代表元 | 例：取内容最长 / 最新 | 与「推荐保留」语义一致，且要在 UI 里写明 |
| 组上限 | 超过 ＿＿ 张的组强制标注「需人工复核」 | 防「一键清理其余」误删 |

| 5 | 否决②入口 `keys≥0.50 && nameSim<0.30` + `coreDist>24`（L380-386） | 24 出自「同名+5 字段」口径（NAME_ONLY），此处前提不同；**精确同名对永不进否决②** → “同名不同角色”零保护 | 前提/阈值重新标定；增设“同名家族”独立通道（展示 + 禁清理），保 AR-48 语义 |

#### 12.2.4 交付缺口（3 条）

1. **`nameNormalizer.js` 未交付**：测试 import `extractNameStem/isCandidateFamily`，方案正文无实现；v3.0 版实现含 `T_TO_S` 7 字繁简表、`VERSION_REGEX` 含 `状态栏版?|终极版?` 案例字面量、前缀 `slice(0,2/3)`（v3.0 存档 L142-143）——**若沿用即违反 G1/G2**。实测（复刻 v3.0 实现）：`唐清露 2.2版 → stem=唐清露版`，`TC-POS-01` 断言 `唐清露` **必挂**。
2. **`candidateBucketer.js` 未交付**：`executeDedupePipeline` import `generateCandidatePairs`（§五），实现只在 v3.0 里且**无内容轨**（只有名字桶 + keys 倒排）——“改名同源”召回无保障；且 `item.degradedReason` 与 v3.1 契约的 `degraded` 字段名不一致。
3. **降级不上报**：`if (n && !n.degraded) normalized.push(n)` 无 else——降级条目**无声消失**（违反“跳过/降级必须上报”）。

#### 12.2.5 性能与语义补充（3 条）

1. `computeMinHash96`（§一）无去重/无采样：每字符位置 × 96 维；真实库 11k 卡成本远超旧基线（旧实现有 `getShingles()` 去重先例）。
2. `compareKeyHashes`（§一）与 `useWorldbooks.js:123-142` **同名异义**：权威版返回 `{jaccard,inter,union} | null`（缺索引 = null）；v3.1 版返回 number、空数组返回 0——违反“同一数字单一来源”。
3. 展示层失真：`minScore` 建簇后不更新（L465）；`_simType` 用 `EXACT_DUPLICATE/MERGEABLE_VARIANT/…` 而弹窗 `isRisky` 认 `conflict/different/sampler/reorder/flipped/reskin`（如 `ContentDedupeModal.vue:168`）→ 风险降级失效；`_legacyPct/_fullPct/_keysSimPct` 三口径同值（L579-581）；`openDiffDetailModal`（§五）不算 `diffFieldResults` → DiffModal 空数据。

### 12.3 通用算法硬约束（P0 门禁：不满足即不通过）

> 出处：用户明确要求「不要一对一的补丁式修复，要更智能的算法」（§六）。以下 8 条对**所有后续方案**生效。

| # | 约束 | 一句话判据 |
|---|---|---|
| G1 | **零案例字面量** | 代码/规格中不得出现具体卡名/书名/预设名或由此反推的词表（`状态栏版`、`终极版` 之类）；允许“形状”（版本号形状 / 副本形状 / 时间戳形状） |
| G2 | 名字层 = 形状规则 + 语料挖掘 | 版本/副本/时间戳用**形状正则**；修饰词用**全库片段频次统计**自动发现；繁简要么全量映射数据、要么不做 |
| G3 | 候选 = 三轨（内容 / keys / 名字） | 内容轨（MinHash→LSH）**必须有**；每轨桶深上限 + 超限**抽样降级 + 上报**（禁止静默丢弃） |
| G4 | 判定 = 证据分级（L0→L3）、分数与判定同源 | L0 canonical hash 完全相同；L1 keys 精确 Jaccard；L2 MinHash；L3 simhash **仅预筛**（永不单独定夺） |
| G5 | DF = 片段级 + 全字段池 + 统计上报 | 按行/段落片段统计；字段池覆盖全部文本字段（含 `creator_notes`/`alternate_greetings`/`system_prompt`…）；剥离后上报受影响条目数 |
| G6 | 阈值 = 标定表（值 + 样本 + 日期 + 适用实现版本） | 未标定值必须显式标注“启发式”；实现一改（含归一化）即重标 |
| G7 | “同名家族”独立通道 | 同名 + 无内容证据 → 只展示、禁清理（保 AR-48）；不得丢弃 |
| G8 | 复用既有 L1 资产 | 世界书侧统一用 `keyHashes`/`simhash`/`exactContentHash`（main.js 权威口径）；不重新发明指纹 |

### 12.4 LSH + 图聚类方案单评审

**结论：方向可取（与 G3 内容轨一致），但作为“方案单”规格不足，且有 4 处红线级问题——不可直接落地。**

#### 12.4.1 可取之处

1. 内容轨（MinHash → LSH）正是 v3.0/v3.1 缺的那条腿——“改名同源”只能靠它召回。
2. 统计驱动、无名字词表（符合 G1 方向）。
3. 有“桶深上限”意识（虽处理方式错误，见 R1）。
4. 簇心选择 = 度中心性 × 长度——与项目“星型 + 簇心”思想同源。
5. 纯 JS、零原生依赖，与项目约束一致。

#### 12.4.2 红线级问题（4 条）

| # | 问题 | 依据（原文） | 红线对照 |
|---|---|---|---|
| R1 | 桶深 >100 **静默丢弃**（“自适应丢弃”） | `findCandidatePairs`：`if (bucket.length > 1 && bucket.length <= 100)` | 「静默算出 0 比崩溃更坏」——热门/模板污染场景**召回直接归零且无上报**；应改“抽样降级 + 上报” |
| R2 | 聚类 = **连通分量**复活 + 新阈值（0.6 / 0.75）无标定；`confidence` 无边时返回 **0.8 硬编码**；BFS 顺序敏感 | `resolveClusters` / `computeClusterConfidence` | PK-29 病根形态（旧实现因连通分量误聚 236 张组被否）+「阈值必须真实库标定」；须给真实库回归与“与星型机制的关系”说明 |
| R3 | 阈值全表无来源：128 维 / 16×8 band / 0.75 建边 / 60% 校验 / 0.5% IDF / 100 桶深 / “8 秒” | 全文 | 「阈值必须真实库标定」；0.5%（11k 库 ≈ 55 张）与既有 DF 标定（≥5 张、≥60 字）差 10 倍 |
| R4 | “读全文算签名”与项目三层模型冲突 | `extractMinHashSignature(text)` 直接吃全文 | PK-27 事故路径（全量读 34.8GB）；应复用 L1 落盘摘要（G8），或明确“签名在扫描期顺带产出” |

#### 12.4.3 规格缺口（5 条）

1. **TF-IDF 段级降权只写在文字里、代码没实现**（`extractMinHashSignature` 无任何 IDF/段级逻辑）——描述 ≠ 交付。
2. **性能账本失真**：51.2MB 只算签名数组（LSH 表 16×N 键、邻接表、节点元数据全未计）；“签名提取 5s / 10 万卡”按其代码估算（3 万字 × 128 维 ≈ 384 万次内循环/卡，10 万卡 ≈ 3.8×10¹¹ 次）不可能，且未算 I/O；真实库规模是 **11,186 张**（不是 10 万）。
3. 无**数据契约层**（三库形态、瘦身态 `ensureFullBody`、DF-17 层级）——直接吃 raw 数据会重演 A1 类缺陷。
4. 无 **UI/接线**：28 符号、四弹窗字段契约、进度、清理安全（`trashFiles`/`confirmDialog`）——“完全兼容 useDedupe 视图接口”无实现支撑。
5. 无**验收**：负样本、标定、双口径、两轮一致、探针口径（§七 全缺）。

### 12.5 复评流程与通过标准（对后续所有方案生效）
