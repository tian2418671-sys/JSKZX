## 一、目标与现状

**现状（已有能力，勿重复实现）**：

- 「🔗 多本世界书智能合并」入口已存在：`WbMergeModal.vue`（勾选 ≥2 本）+ `App.vue::executeWorldbookMerge`；
- 其行为：逐本 `ensureWorldbookLoaded`（PK-26 懒加载守卫）→ **指纹去重**（`key.join(',') 归一 + content 归一`）→ 生成**一本新书**「合并世界书_N本」（`path:''` 交由智能落盘分配）→ **源书全部保留**；
- 查重侧（v4）已有：level 0/1/2 判定、`_nameOnly` 警示、差异窗口、「清理（移回收站）」。

**缺口（本规格补齐）**：

1. 查重发现「A/B 高度相似」后，用户要**手动**记住书、再切到合并入口勾选——链路断开；
2. 合并**无预览**（直接执行 + 事后 alert）；
3. 合并算法内嵌在 `App.vue`，不可测试、不可复用；去重键 `key.join(',')` **顺序敏感**（`["A","B"]` 与 `["B","A"]` 判为不同）；
4. 合并后源书清理全靠手动。

**目标**：查重弹窗（`WbDedupeModal`）组卡片新增「🔀 合并此组」——**一键**把该组并成一本（默认以推荐版为主书语义的新书）、**执行前预览**、可选**合并后清理源书**。

## 二、设计

### 2.1 算法提取与增强（`js/utils/wbMerge.js`，纯函数、可单测）

```text
mergeWorldbookEntries(sources: Array<{ name, entries }>) → { entries, stats }
  stats = { total, added, skippedDup, bySource: [{name, total, added, skipped}] }
```

- **去重键（增强）**：`normKeys = key 数组逐项 String+trim+小写 → 排序 → join('\u0001')`；`normContent = content String+trim+小写`；签名 = `normKeys :: normContent`。**排序归一 = 对顺序不敏感**（比现有实现更严谨，属修复级增强）；
- **非字符串防御**：沿用现有加固（key/content 可能是数字/对象——不得直接 `.trim()`）；
- **uid**：沿用「全重生成」（`时间戳_随机`）——合并产出的是新书，与源书 uid 无关联语义；
- **内部字段**：沿用 `dropInternalFields`（**不得**递归剔 `_` 前缀——DF-14 教训：会误删 `extensions._filename`）；
- **冲突检测（新增，仅统计）**：`normKeys` 相同但 `normContent` 不同 → 计入 `stats.keyConflicts[]`（**不自动取舍**，两个词条都保留；预览里提示）；
- `App.vue::executeWorldbookMerge` **改为调用本模块**（行为等价或更准；删除内嵌实现，单一事实源）。

### 2.2 预览（新增 `WbMergePreviewModal.vue`）

执行前展示（防误操作）：

- 来源书清单（N 本，各自词条数与将并入数）；
- 汇总：产出词条总数 / 跳过重复 / 键冲突组数（可展开看前 20 条：哪些键、各书内容摘要）；
- 选项：**☐ 合并后把源书移入回收站**（默认**不勾**——保守；勾选时在确认文案中写明「将移入回收站，可从回收站取回」）；
- 按钮：「取消」「🚀 执行合并」。

### 2.3 两个入口

| 入口 | 触发 | 行为 |
| --- | --- | --- |
| 手动（已有，保留） | 维护/世界书命令「🔗 多本世界书智能合并」 | 勾选 ≥2 本 → **新增**：先预览再执行（替换现有「直接执行」） |
| 查重组（新增） | `WbDedupeModal` 组卡片「🔀 合并此组」 | 自动取该组成员（**含正文懒加载读取**，走 `consumeWorldbookBodies` 守卫）→ 预览 → 执行 |

- 查重入口**显示条件**：组非 `_nameOnly`（「仅名称相同」**禁止合并**——内容不同源）；成员 ≥2；
- 执行完成：新书 unshift + 激活（沿用现有）；若勾选清理 → `trashFiles(源书 paths)` → `worldbooks` / `wbDuplicateGroups` 内存同步（组剔除已并入成员）；
- 结果写入日志（`addLog`）+ toast：「已合并 N 本 → 产出 M 条（跳过重复 K）」。

## 三、验收口径

1. **单测**（构造数据）：顺序敏感键（`["A","B"]` vs `["B","A"]`）判重复；非字符串 key/content 不崩；键冲突统计正确；空书/单书边界；`dropInternalFields` 保 `extensions._filename`；
2. **隔离副本库**：造 3 本（含重复词条 / 独有词条 / 键冲突）→ 查重组按钮 → 预览数字与单测一致 → 执行 → 新书词条 = 并集（无重复、uid 唯一）→ 勾选清理时源书进回收站；
3. **真实世界书库（只读）**：对真实查重结果组打开预览，数字合理（不执行合并）；
4. 6MB+ 大书组合并可用、不 OOM（依赖既有 L1/正文守卫）。

## 四、风险与注意事项

- **误合并防护三层**：预览 → 源书默认保留 → 回收站可回退；`_nameOnly` 组硬禁用合并；
- 查重入口读取正文必须走 `consumeWorldbookBodies`（批量读守卫，历史事故防线），**不得**直接调单本载入函数；
- 合并出的新书是「未落盘」状态（`path:''`），依赖 `syncWorldbooksToDisk` 的智能落盘——预览弹窗文案要提示「合并后将立即保存到世界书目录」；
- 不改变源书文件格式（新书由归一化后的词条生成，字段整条照搬）。
