### 2.4 ⚠️ 瘦身态：附加问候语与卡内词条正文**可能不在内存里** ★★

大库（≥ 3000 张）会执行**正文懒加载**（`js/utils/cardSlim.js` `slimCard` L102-142），
它对本次要加的两项**正好各砍一刀**：

```js
for (const e of entries) e.content = '';        // ① 卡内世界书词条正文 → 清空
d.alternate_greetings = undefined;              // ② 附加问候语 → 置空
```

⇒ **读这两项必须走统一入口 `ensureFullBody(items)`**（PK-31/PK-32 定下的规矩：
「任何直接读 `character_book` / `alternate_greetings` 的消费点，必须在 `npm run guard:card-body` 白名单里登记处理方式」）。
**教训直引**：PK-31 —— 「读侧没有入口 ⇒ 把瘦身态当真的空，输出空结论」，
所以**预览里不许显示成空**，必须显示「正文未载入 · 发送时按需读取」。

其它连带约束（都是项目已踩过的坑）：

| 约束 | 依据 |
| --- | --- |
| **不许全量 `Promise.all` 读回** —— 分批（滑动窗口 50~100 张），读回 → 用 → 立即交还 | 查重 v4 规格（11k 库 9k 张瘦身态，全量并发 → 1GB+ 堆警告） |

## 三、⚠️ 「占比率」到底指什么（三种解读，必须先确认）

> 用户原话只有一句「占比率用滑块来控制」，代码里没有任何「占比」概念，**无法从现状反推**。三种最可能的解读：

| 解读 | 含义 | UI 形态 | 适用场景 | 评价 |
| --- | --- | --- | --- | --- |
| **A · 预算配额**（我倾向） | 顶部一个**总预算**（token），每个已勾选材料一个**占比滑块**；预算按占比分给各材料，超配额才截断 | 1 个预算滑块 + N 个占比滑块 | 治「描述几万字把性格挤没了」 | 最通用，能覆盖 B/C，但概念稍多 |
| **B · 组间混比** | 只有**一个**滑块：卡片字段 : 卡内世界书 = x% : (100-x)% | 1 个滑块 | 混合模式下调两类材料的比重 | 最贴合「混合 + 占比」字面，但**同类内部仍无控制** |
| **C · 采样率** | 每个材料一个「取前 N%」滑块（或按段落均匀采样 N%） | N 个滑块 | 只想去掉冗余、不想设总量 | 语义简单，但「不限总量时 50% 是多少」也说不清 |

**推荐 = A 为主 + B 作为它的「组级」一层**（层级化，一个概念树，不是三套机制）：

```text
总预算（token，默认「不限」= 全文送，占比滑块只影响超预算时的分配）
  ├ 卡片字段组      占比 [====o----] 60%
  │    ├ 详细设定    占比 [======o--] 30%
  │    ├ 性格特征    占比 [===o-----] 15%
  │    └ …
  └ 卡内世界书组    占比 [====o----] 40%
       └ 词条按（常驻优先 / 出现顺序）取用
```

> 📌 **与 v1 的一个真实冲突**：v1 主张「世界书打标**送全不截断**（超长走分段）」，
> 而占比的本质是**截断**。调和方案：**占比只作用于卡片材料（含卡内世界书）**；
> **独立世界书打标仍维持「送全 + 分段」**（Q9 待确认）。

## 四、方案设计

### 4.1 字段勾选（要求 ①）

- 一个「📦 卡片材料构建」区块，**8 项打勾**（+ 建议补「对话示例」）；每项右侧显示**该项实际字数**与**占比滑块**。
- 勾选状态**全局持久化**（`ui.tagCardMaterialFields`），跨卡复用；默认值 = **今天的 4 项**（卡名 / 描述 / 性格 / 首句）⇒ 老用户零变化。
- **卡名**：现在固定送 ⇒ 建议改成**可取消**（有些卡名就是角色名，重复无意义），但默认勾上（Q7）。
- 空字段自动标注「（本卡为空）」并**不计入占比分配**（避免配额被空字段吃掉）。
- 每项在材料里的排版沿用现有风格（`【角色设定提取】` 段内按 `字段名：正文` 排列），保证与今天的材料可读性一致。

### 4.2 卡内世界书内容选择（要求 ②）

三级控制（由粗到细，默认最保守）：

| 级别 | 控件 | 默认 | 说明 |
| --- | --- | --- | --- |
| ① 开关 | ☑ 送卡内世界书 | **关**（= 现状，也是 2026-09-25 的口径） | 关掉时与今天逐字一致 |
| ② 规则 | 范围：全部启用 / **仅常驻** / 前 N 条 | 全部启用（`enabled !== false`） | 强制跳过 `enabled: false` 的禁用词条 |
| ③ 逐条 | 预览里逐条「排除」 | 空 | **稀疏排除集**（只记被排除的），落盘键 `card:<id>` |

**词条文本形态**（与 v1 §4.3 的独立世界书格式对齐，但字段口径按 §2.3）：

```text
【<comment 或 keys[0] 或无标题>】
触发词：a、b · 次级：c · 常驻
<content>
```

**为什么逐条只做「排除」而不是「勾选集」**：打标窗口是多卡批量（实测有 700 张全选的场景），
逐卡维护「包含清单」既写不完也不好落盘；而个别卡里确实有跑题词条时，用户只需要**点掉那一条**。
（Q5 待确认是否要落盘、还是会话级。）

### 4.3 混合模式（要求 ③）

三选一单选圈：`○ 仅卡片字段 · ○ 仅卡内世界书 · ● 混合（字段 + 卡内世界书）`。
"仅卡内世界书"档要有**红色警告**（与 v1 §4.2 的「目标材料被关」同一套防呆）：
没勾任何字段又不开卡内世界书 ⇒ 材料为空，打标准定失败。

### 4.4 占比与预算（要求 ④，按 §三 的解读 A+B）

**算法（纯函数，可单测）**：

```text
1. 收集已勾选材料的实际 token（estimateTokens）与占比权重 w_i（组级 w_g × 组内 w_i）
2. 若 预算 = 不限  或  Σ实际 ≤ 预算  →  全部原文送出（占比只用于预览显示）
3. 否则：配额 q_i = 预算 × w_i / Σw          （组级先分、组内再分）
4. 实际 ≤ 配额的材料全额送出，节余按权重**回流**（最多 2 轮）
5. 仍超配额的材料按截断策略处理：
   · 段落均匀采样（**推荐**：按段落取，保留首段与末段）
   · 开头截断（最省事，但会丢结尾的世界观/收束信息）
   · 只取首段 + 各段首句（信息密度最高，但改写原文）
6. 预览里每项显示：`实际 3,120 / 配额 2,400 token · 占比 30% · 已采样`
```

**单位与默认**：默认「不限」⇒ **不设预算时行为与今天一致**（这点很关键，避免一上来就悄悄丢内容）。

### 4.5 材料构建异步化（**本方案最大的技术约束**）

```text
现状：materialPreview（同步 computed） → buildCardMaterial（内存直读）
改成：卡内词条正文 / 附加问候语 需要 ensureFullBody（读盘）
      ⇒ ① 新增「卡片正文预取 watch」（异步、分批、可取消）
         ② computed 照旧同步，读不到时**显式标注**（不装成空）
         ③ 发送时逐张（或逐包）按需读回 → 用完交还 slimCard
```

| 项 | 设计 |
| --- | --- |
| 预取范围 | 预览用：默认**前 50 张**（可调）；超出提示「其余 N 张发送时逐张读取」 |
| 预取节奏 | 滑动窗口，每批 50 张 → 让出主线程 → 下一批（**禁止** `Promise.all` 全量） |
| 取消 | 目标集 / 勾选项变化时**令牌作废**（抄世界书预览的 `wbPreviewLoadToken` 写法） |
| 交还 | 预览关闭 / 打标结束后对「本来是瘦身态」的卡补跑 `slimCard` |
| 守卫 | 新增读点登记进 `guard:card-body` 白名单（`ensure` 模式），否则守卫会红 |
| 无加载器时 | **告警不静默**（`cardSlim.hasCardBodyLoader()`；PK-31 明确要求） |

### 4.7 与 v1 占位符的接口

| v1 的占位符 | v2 给它什么 |
| --- | --- |
| `{{材料}}` / `{{卡片}}` | **按 §4.1-4.4 组装后的整块卡片材料**（勾选 + 混合 + 占比截断之后） |
| （可选，Q8）`{{性格特征}}` / `{{详细设定}}` / `{{卡内世界书}}`… | **单个字段**的材料 —— 让用户把不同字段放进不同段 / 不同角色 |

⇒ 也就是说：**v2 决定"内容"，v1 决定"位置"**，两者叠加不需要新的抽象。

## 八、风险与防线

| 风险 | 防线 |
| --- | --- |
| **瘦身态被当成"真的空"**（PK-31 原病） | 读点走 `ensureFullBody`；读不到时预览**显式标注**而非留白；守卫白名单登记 |
| **读回把整库正文常驻内存**（PK-20/27 原病） | 分批滑动窗口 + 用后交还 + 预览预取上限（默认 50 张） |
| **空正文写回文件**（PK-32 原病） | 落盘链路既有闸门 + 前端 `persistCardUpdate` 的 `ensureFullBody` 双保险；本方案**不改落盘语义** |
| 一次勾太多字段 ⇒ 材料暴涨（附加问候语可达数千字 × N 条） | 每项显示字数 + 总预算 + 占比；预览实时显示总 token |
| 占比滑块语义被误解（用户以为是 A、实现是 B） | **先把 §三 问清楚再写代码**；UI 上把「占比」写成「占比（超预算时生效）」 |
| 逐条排除的键不稳定（词条被改名/增删） | 键用 `comment` → `keys[0]` → 下标 三级回退（与 `cardSlim` 的 `sig()`、`entryAlign` 同口径）；配不上时**忽略该排除项并在日志提示** |
| 内嵌词条口径写错（`keys` 写成 `key`） | §2.3 对照表 + 单测用真实卡样例（V1 数组形态 / V2 字典形态各一） |
| 预览 computed 变慢（多卡 × 多字段 × 多词条） | 沿用两级折叠的**惰性渲染**；材料组装结果**按卡缓存**（WeakMap），勾选项变化才失效 |

## 九、验收标准（可测）
