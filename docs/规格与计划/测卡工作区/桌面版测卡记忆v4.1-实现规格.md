## 一、桌面 vs 移动版的关键差异（决定了实现的简化）

| 项 | 移动版 v4.1 | 桌面版本实现 |
|---|---|---|
| 存储 | SQLite（`memory_items` 表 + schema v3 迁移 + `onUpgrade`） | `memory_store.json`（数据形态 `v:1 → v:2`，启动懒迁移，无需 schema 版本机） |
| D4 覆盖/单卡上限 | 原生 `MemoryPlugin.add` 内做 | 全部在 `main/memoryStore.js`（渲染层零感知） |
| B1 批量抑制 | 批量测卡模式进入时关记忆 + 崩溃恢复标记 | **省略**（桌面无「批量测卡」场景；移动端特有） |
| P3 模型检索 | 需预研 ONNX.js/TFLite spike | 后置（桌面已有 onnxruntime-node + vectorManager，届时成本更低，另行立项） |
| `useChatFactExtractor.js` / `useChatMemoryStore.js` / `useChatMemoryConfig.js`（未提交的新文件） | 7 领域置信度规则 / MemoryStore 类 / 模型开关框架 | **不搬**：置信度规则与现有 `extractFacts` 是两套并行体系；桌面沿用 v4.1 评审定案的 **D3 收紧版 `extractFacts`**（单一事实源），MemoryStore 类与 JSON 存储层职责重复 |

## 二、数据形态（memory_store.json v2）

```
{ v: 2, items: [{ id, type, content, key, cardName, cardPath, confirmed, ts, updatedAt }] }
```

- `cardPath`：卡唯一标识（`item.path`），分桶主键；迁移前的旧数据为 `''`（遗留桶）
- `cardName`：降级为纯展示（迁移时保留原值）
- `confirmed`：`1` 注入 / `0` 待确认 / `-1` 软删。**P0 恒写 1**（对齐移动版决策 2），本期不收紧为 0，但通道先建好
- `ts`：首次创建（D4 覆盖保留）；`updatedAt`：覆盖/编辑时刷新（降级排序依据 = `updatedAt DESC`）
- 读入 `v:1` 旧文件：缺省字段补默认（`cardPath:'' / confirmed:1 / updatedAt:ts`），首次落盘即为 v2

## 三、存储层行为（main/memoryStore.js）

1. **D1 按卡过滤**：`list({ cardName })` / `search({ cardName })` —— 参数名沿用移动版桥接契约（`cardName` 携带的是 cardPath），非空时强制 `it.cardPath === 该值`。
2. **D2 检索治理**（渲染层 `memoryRules.js`）：停用词表 + 有效词 <2 → 降级「本卡最近 N 条（updatedAt DESC）」；存储层 `search` 空 query 且无 cardName 过滤 → 只返回最近 N 条（现状行为，保留）。
3. **D4 同 key 覆盖**：`add({ type:'fact', key 非空 })` 时查同 `(type, key, cardPath)` 冲突 → UPDATE content + updatedAt（保留 ts）；无冲突 → 插入。message/summary 维持原「同内容去重」。
4. **单卡 fact 上限**：50 条（`FACT_KEEP`），超出按 `updatedAt ASC` 删最旧（移动版 §7.1 定案：保护被频繁覆盖的新值）。
5. **迁移（一次性、幂等、可重跑）**：
   - `migrateData(mappings)`：`[[显示名, path|null]]` —— 唯一匹配 → `cardPath=path`；多卡同名/无匹配 → 保持 `''`（遗留桶，不丢数据）
   - `migrateCard({ from, to })`：路径变更跟随；同 `key+type` 冲突**目标优先删源**（移动版 §7.2 定案），事务语义 = 单文件快照写天然成立
   - `clearByCard(cardPath)`：删卡时清记忆（移动版 D1a remove 语义；桌面删卡是移入回收站，path 已不可逆，保留即成永孤儿）
   - `confirm(id, confirmed)`：P1 预留
   - `stats()` 增加 `orphans`（`cardPath === ''` 条数，供查看器遗留桶提示）

## 四、渲染层（js/composables/chat/）

- **新文件 `memoryRules.js`（零依赖纯函数，可单测）**：`STOP_WORDS` / `FACT_KEYS` / `VAGUE_KEYS` / `isExcluded` / `extractFacts`（D3 收紧版：疑问句/否定假设/引用排除 + 空泛键跳过 + 值截断 30/80） / `tokenizeQuery`。从移动版 v4.1 `useChatMemory.js` 对齐移植。
- **`useChatMemory.js` 重写**（对齐移动版 v4.1 同名文件，差异：`localStorage → chatStorage`、`api ← chatBridge`、去 B1）：
  - `recordMessage/recordFact` 第三参支持 `string | { path, name }`
  - `searchMemory(query, limit, cardPath)` / `listMemory(type, limit, cardPath)` / `clearMemoryByCard` / `migrateMemoryCard` / `migrateMemoryToV2(cardList)`
  - `getMemoryInjectTokens`（默认 200 / 硬上限 400）、`getMemoryFormat`（'C' = XML / 'markdown'）、`isMemoryV2`（默认开）
  - `buildMemoryContext(query, cardPath) → { text, meta }`：条数 + token 双预算截断、I4 XML 格式 C、meta = `{ injectedCount, cardPath, isDegraded, estimatedTokens }`（灰度关时 meta=null）
- **`useChatEngine.js` 接线**：
  - 两处 `buildMemoryContext` 适配 `{ text, meta }`（注入 `memCtx.text`）
  - R1：`recordMessage('user', 原始输入, { path, name })`（不再记 processedText）；`extractFacts` 同样吃原始输入
  - R2：发送后记录返回的 `id` 存 `lastAssistantMemId`；`nextSwipe/prevSwipe` 翻到最后一条 assistant 消息时 `memoryUpdate(id, { content })` 回写实际候选（update 回写而非 remove+add，移动版 §7.4 定案）

## 五、路径钩子（铁律：path 变 → 派生键全迁）

| 接线点 | 动作 |
|---|---|
| `useCardGroups.js` `renameCurrentCategory`（目录前缀迁移处） | `migrateChatKeys` 旁加 `migrateMemoryCard(oldPrefix, newPrefix)` |
| `useCardGroups.js` `moveCardToGroup` | 同上（单卡 path） |
| `useCardCrud.js` `deleteCard` / `deleteCardItem` | 成功后 `clearMemoryByCard(path)` |

## 六、启动迁移

App.vue 库就绪后（首次 `library` 非空）跑一次 `migrateMemoryToV2(library.map(i => ({ name, path })))`；幂等可重跑；`isMemoryV2()` 关闭时不跑（回滚 = 行为回到旧分桶/旧格式/旧条数）。

## 七、侧栏记忆查看器（ChatTestSidebar 设置分区）

- 现有「已存 N 条 + 清空」块保留，追加：注入条数 / token 预算 / 格式 三个设置项（对齐引擎消费的同一 chatStorage 键）
- 记忆列表：默认「只看本卡」（按 props.cardPath 过滤）+ 「全部」切换；每行 `键：值` + 🗑 删除（`removeMemory`）；顶部 chip 显示当前卡名；遗留桶提示「N 条未归属任何卡的旧记忆」（`stats().orphans`）

## 九、明确不做（本期）

- confirmed 收紧为 0 + 确认 UI（移动版 P1；通道已备，UI 另期）
- L2 摘要自动生成（移动版 P2）
- 向量检索（移动版 P3；桌面另行立项，见 §一）
- 删卡清理测卡会话/变量树键（另一独立问题，不混入本方案）
