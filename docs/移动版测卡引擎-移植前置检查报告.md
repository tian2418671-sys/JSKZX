## 四、🟡 需拍板的取舍（不是 bug，是设计决策）

### 取舍 A · `useChatPlugins.js` 是第 5 套「插件」概念

`js/composables/chat/useChatPlugins.js` 定义的是「可导入的 JSON 扩展」= `{systemPrompts, macros, regexScripts, worldbookTriggers}`，存 `localStorage['jsmobile-chat-plugins']`，与桌面现有体系**完全无关**。

桌面**已经有两套**插件概念：
1. **插件工作区**（`usePlugins.js` + `PluginWorkspace.vue` + `pluginScanner.js`）= 真实的 JS-Slash-Runner 脚本插件；
2. **预设内嵌插件**（`useChatPresets.extractPluginsFromPreset`）。

直接搬进来就会出现「第 5 套插件」，用户侧概念混乱。

**建议**：引擎层保留（`collectPluginSystemPrompts` / `mergePluginMacros` / `collectPluginRegex` 是编排要用的纯函数），但**侧栏 UI 不新开「插件」Tab**，改为复用桌面已有的插件工作区；或者本期先不接插件注入，留待二期。

### 取舍 B · 7 个文件用 `localStorage`，桌面 `app://` 下**不持久**

| 文件 | 存储键 | 后果 |
|---|---|---|
| `useChatApiConfig.js` | `stc-api-key` | ⚠️ **与桌面已迁走的键同名**，桌面权威是 `app_config.json` 的 `api.key`，两套会打架 |
| `useChatSettings.js` | `jsmobile-chat-reply-count` / `-user-name` / `-persona` / `-max-floors` | 重启回默认（回复数/用户名/人设/隐藏楼层全丢） |
| `useChatMemory.js` | `jsmobile-memory-enabled` / `-limit` | 重启回默认 |
| `useChatPresets.js` | `jsmobile-active-preset` | 重启丢激活预设 |
| `useChatPlugins.js` | `jsmobile-chat-plugins` | 重启丢插件 |
| `useChatSessions.js` | `jsmobile-chat-sessions:<cardPath>` | 重启丢全部会话/聊天记录 |
| `useChatVariables.js` | `jsmobile-chat-vars:<card>:<session>` | 重启丢变量树（MVU 状态） |

项目内已有 17 处注释/文档确认该坑：`main.js:1199`「实测重启后丢失」、`useConfigPersistence.js:72`「改存 app_config.json」、`RELEASE_NOTES.md:567`「12 个 UI 字段统一收口」。

**建议方案（双轨，推荐）**：
- **引擎零改动、零分叉**：`useChatVariables` 的 `createVariableEngine({ storage })` **本来就支持注入 storage 适配器**，桌面侧传一个「内存缓存 + `syncConfigToDisk` 落盘」的适配器即可，引擎文件一行不改；
- `useChatSettings` / `useChatPresets` / `useChatSessions` / `useChatMemory` 这 4 个是模块级裸 `localStorage`，选项：
  - **A（推荐）**：新增 `js/composables/chat/chatStorage.js`（`get/set/remove` + `app_config.json` 镜像），把 4 个文件里的 `localStorage.xxx` 机械替换为 `chatStorage.xxx`，与引擎「纯函数 + 注入」风格一致，且将来移动版同步也不冲突；
  - **B**：把值并入 `useConfigPersistence` 的 `ui` 段（呼应计划待办 4），改动面最小但会让 `ui` 段塞进聊天记录大对象，`syncConfigToDisk` 是全量序列化 + 加密 IPC，每次发消息都落盘会写放大。
- `stc-api-key` **不要**用引擎这份，直接复用桌面 `apiKey` ref（已加密落 `app_config.json`）。

### 取舍 C · ChatPanelSeg 的 `renderText` 宿主注入

`ChatPanelSeg.vue` 的 `renderText` 是 **required 函数 prop**，注释写明「复用 CardDetailView.renderChatHtml，避免双份实现」。桌面没有等价物，需要按缺口 3 补出 `renderChatHtml`（Showdown 实例化 + `sanitizeStatusHtml` 清洗 + `mdCache`）。

### 🔑 P1-1 实现要点（接线时必读）

**为什么不让聊天数据走 `app_config.json`**：`sys:saveConfig`（`main.js:1258`）是**整份文件全量替换**语义，而 payload 由 `useConfigPersistence.syncConfigToDisk` 全量生成。任何第三方「部分写入」都会被下一次 `syncConfigToDisk` 抹掉，且会反过来覆盖掉别人的字段。故新增独立文件：

```
userData/chat_store.json          ← 测卡会话 / 变量树 / 聊天设置 / 激活预设 / 插件
userData/app_config.json          ← 全局 UI / API / 分类 / 标签（既有，不动）
```

**IPC**（`main.js` / `preload.js`）：

```js
window.electronAPI.loadChatStore()        // → { success, data: { [key]: string } | null }
window.electronAPI.saveChatStore(data)    // → { success }（主进程串行队列 + 原子写）
```

**适配层**（`js/composables/chat/chatStorage.js`）保持**同步语义**，因此引擎的同步 getter（`getReplyCount()` 等）**一行都不用改成 async**：

```js
chatStorage.get(key) / set(key, val) / remove(key)   // 同步，内存为权威
await chatStorage.hydrate()                          // 启动时调用一次（幂等）
chatStorage.flush()                                  // 关键操作后 / 关闭前冲刷
```

**⚠️ 接线时序（唯一需要注意的点）**：`hydrate()` 是异步且**磁盘优先于 localStorage**，所以挂载测卡 UI 前要先 await：

```js
await chatStorage.hydrate();
replyCount.value = getReplyCount();   // 此时才拿到恢复后的值
```

不 await 不会崩（读到 localStorage 旧值或默认值），但「重启恢复」这条验收会不通过。


### ⚠️ 接线时必踩的两个桌面架构约束

1. **新增 `ctx` 字段必须同时改两处** —— `App.vue` 的解构列表（约 4936 行）与 `ctx` 对象（约 4504/4810 行），缺一则拿到 `undefined`（项目铁律第 5 条）。
2. **`window.electronAPI` 被 `contextBridge` 冻结**（`configurable:false / writable:false`）——不能 mock、不能改写。`chatBridge.js` 已按「展开复制 + 逐方法兜底」处理；⚠️ 但它在**模块加载瞬间**就固化 `const real = window.electronAPI`，若将来有「先 import 后注入」的时序，会永久拿到 `null`。接线时确保 import 晚于 preload 注入（桌面正常流程天然满足）。

### 移动版编排层「总装清单」（接线时逐条对照，勿漏）

`CardDetailView.vue` 的测卡段实际串联了以下步骤，接桌面时按此顺序核对：

1. `fullMacros` = `mergePluginMacros(插件宏, buildMacroContext(卡, 用户名, 人设, 最后活动时刻))`
2. 用户输入 → `applyMacros` → `applyRegexScripts(…, 'USER', …)`
3. `collectActivatedWbText(最后一条用户消息)`：常驻/触发词命中 → EJS 渲染 → 宏替换 → 按 `position`/`insertion_order` 排序
4. `buildPayload`：预设模式（`buildPresetMessages` + `collectPluginSystemPrompts` + 记忆 + 人设，role 分组合并）／无预设兜底模式
5. 历史 assistant 消息走 `applyRegexScripts(…, 'AI', …, { promptOnlyExclusive: true })`（对 AI 隐藏状态栏）
6. `requestReply`：`sendChatMessage` → `replyToSwipe` → `⚠` 占位短路 → `processAiReplyVars`（MVU 应用+剔块）→ `applyRegexScripts(…, 'AI', …)`
7. 多候选循环 `replyCount` 次；**MVU 只对首条候选 `applyVars=true`**（防 add 双重累加）
8. 发送后 `recordMessage` + `extractFacts` → `recordFact`；`saveCurrentChat()` 落会话
9. Swipe：`nextSwipe` / `prevSwipe` / `moreSwipe`（追加候选，`applyVars=false`）/ `regenerateSwipe`（整组改写）/ `continueSwipe`（`[continue]` 续写）
10. 渲染：`segmentMessage` → `promoteHtmlSegments` → `ChatPanelSeg`（文本段 `renderChatHtml`，HTML 段 sandbox iframe + 高度 postMessage）
11. `{{idle_duration}}` 基准 = `lastUserActivity`（每次发用户消息刷新）
