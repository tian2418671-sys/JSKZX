# 发布一条龙 · 执行清单

> 适用：v2.2.7 起。目标：从「代码就绪」到「用户收到 OTA」，每步可核对、可回滚。
> 配套工具：`scripts/release-check.mjs`（自动可查项一条命令跑完）、`scripts/measure-startup.mjs`（启动性能验收）、
> `docs/自动更新说明与常见问题.md`（OTA 机制细节）。

---

## 0. 前置：一条命令自查（每次发版第一件事）

```powershell
node scripts/release-check.mjs                                  # 语法 + 单测 + 构建 + 文档一致性 + git 状态（约 30s）
node scripts/release-check.mjs --e2e dev  --port 9338           # 另加：大库重复卡 + 正则探针 + 测卡引擎（需 dev 实例）
node scripts/release-check.mjs --e2e prod --port 9333           # 另加：测卡侧栏端到端（需生产构建实例）
```

**判定**：必须看到 `✅ 无阻塞项，可进入打包` 才继续（⚠️ 只算提醒，例如工作区未提交、端到端数据条件跳过）。

### 端到端实例怎么起（隔离 profile，绝不碰你的真实配置）

```powershell
# ① dev 实例（大库，端口 9338）
npx vite --port 5173
$p="$env:TEMP\jsk-rel-profile"; Remove-Item $p -Recurse -Force -EA SilentlyContinue; New-Item -ItemType Directory -Force -Path $p | Out-Null
Copy-Item "$env:APPDATA\sillytavern-card-manager\app_config.json","$env:APPDATA\sillytavern-card-manager\tavern_manager_config.json" $p
# 把 lastFolder 改成 I:\03\角色色卡（或用你当前库）
$env:VITE_DEV_SERVER_URL='http://localhost:5173'
.\node_modules\electron\dist\electron.exe . --disable-gpu --remote-debugging-port=9338 --user-data-dir=$p

# ② 生产构建实例（端口 9333）：去掉 $env:VITE_DEV_SERVER_URL，改用 npm run build:web 的产物
```

> 端到端脚本对**数据有依赖**，属正常：
> - 库里有带世界书徽标（🌍）的卡才会跑世界书注入断言；卡本身没有 `character_book` 时会打印
>   「世界书注入断言无对象，已跳过」而**不算失败**；
> - 卡片内容里的外链图片会被应用 CSP 拦截（`img-src` 不放行 http(s)，防追踪像素）——脚本单列为
>   `cspImgBlocked`，不计入错误。

## 1. 打包

```powershell
npm run build          # = npm run build:web && electron-builder -w
```

产物在 `dist_new/`：

| 文件 | 用途 | 核对点 |
|---|---|---|
| `sillytavern-card-manager-2.2.7.exe` | 安装包 | 大小与上一版接近（±10MB 正常） |
| `latest.yml` | **OTA 必需** | 里面 `version:` 必须是 `2.2.7`，`sha512`/`size` 与 exe 匹配 |
| `*.exe.blockmap` | 差分更新（可选） | 与 exe 同名同版本 |
| `win-unpacked/` | 中间产物，**不必上传**（本轮已清理过 652MB） | 可随时删 |

## 2. 装包自测（必做）

在**干净 profile**与**真实 profile**各试一次：

| 检查 | 期望 |
|---|---|
| 打开大库（11,186 卡） | 卡片数正确；首屏 16~31s（机器负载敏感）；无崩溃 |
| 升级场景（装过旧版） | 启动日志出现一次 `[embed-cache] 已回收遗留缓存 N 个文件 / X MB`（v2.2.3 遗留缓存的一次性迁移，属预期） |
| `%APPDATA%\sillytavern-card-manager\` | **无** `embed_cache_*`；用过测卡后有 `chat_store.json` / `memory_store.json` |
| 测卡 | 开卡 → 聊天测试：7 分区都能打开；「设置」分区记忆库显示条数（首装 0），可刷新/二次确认清空 |
| 正则/状态栏 | 新增一条 → 列表**立即** +1（无需切 Tab）；删除 → 弹出**原生**确认框，取消不删、确定立即消失 |
| 刷新/搜索 | 连点刷新 5~10 次：卡片数不变（11,186），列表与库层都不出现重复卡 |
| 内存 | 连点刷新后堆峰值 < 3.5GB（本次实测 2.7GB）；`crash.log` 无新增行 |

## 5. OTA 验证（发布完成的唯一判据）

1. 在一个**旧版本**客户端（如 2.2.6）点「检查更新」→ 应提示有新版本；
2. 走完下载/安装 → 版本号变为 2.2.7；
3. 若没提示：先看 `latest.yml` 是否上传、`version` 是否更大、release 是否为公开发布（非 draft/prerelease）。

## 6. 回滚

| 时机 | 做法 |
|---|---|
| 未推送 | `git reset --hard <上一提交>`（本轮为 `9ea6b34`，即 v2.2.6） |
| 已推送但未发 Release | `git push --force-with-lease origin master` + 删本地/远端 tag |
| 已发 Release | **不要重发同号**（OTA 按版本号比较）→ 修完发 2.2.8；必要时把旧版 exe 重新挂到 2.2.7 的 release 上 |

---

## 附：为什么是这个顺序

1. **先自查再打包**：包一旦打出来，改版本号/文档要重打（`build:web` + electron-builder 都跑一遍）；
2. **装包自测放在 tag 之前**：装包问题往往只能在真实安装环境暴露（asar、路径、CSP）；
3. **OTA 验证放在最后**：它同时检验「exe + latest.yml + release 状态」三件事，是发布成功的唯一判据；
4. **性能与端到端分开跑**：`release-check --e2e` 只做「是否回归」的判定；要**比较优化效果**必须用
   `scripts/measure-startup.mjs`（同会话交替 A/B，绝对值受机器负载影响可差 2 倍，见
   `docs/测试日志-2026-09-13.md` §3.2）。
