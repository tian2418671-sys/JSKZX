# 🧩 插件功能 · 格式说明

> 适用版本：v2.2.3+
> 本文档说明「插件」Tab 支持哪些插件形态、如何导入、以及「效果」预览的运行机制与限制。

---

## 一、支持的插件形态

插件扫描器（`js/utils/pluginScanner.js`）会识别以下四类来源，统一归一为插件模型：

| 形态 | 判定依据 | 示例 |
|------|----------|------|
| **A. 酒馆助手 JSON 脚本** | `.json` 文件含 `content` 字符串字段（注入 JS），且具备 `id`/`name`/`buttons` 之一 | `{ "id":"xxx", "name":"某助手", "info":"...", "content":"$('#chat').append(...)", "buttons":[...] }` |
| **B. userscript 头脚本** | 脚本内容含 `// ==UserScript==` 头 | 同样可出现在 JSON 的 `content` 或独立 `.js` 文件 |
| **C. SlashRunner 命令** | 脚本内容含 `SlashRunner.registerCommand(...)` | `statusSystem.js` 等依赖 JS-Slash-Runner 的脚本 |
| **D. 扩展工程** | 目录内含 `manifest.json`，且 `manifest_version` 或 `extensions` 数组命中 | SillyTavern 原生扩展、`st-yuzi-phone` 等 bundle 工程 |

> 排除规则：`spec === 'chara_card_v2/v3'`（角色卡）、含 `entries`（世界书）、含 `prompts`/`temperature` 等（预设）的 JSON 会被主动排除，避免误判。

## 二、接入方式

### 📂 本地目录扫描
点击侧边栏「打开插件目录」，选择酒馆的插件/扩展目录（或任意自建目录），扫描器递归识别上述形态。目录路径经主进程白名单校验，非白名单目录若不含有效插件指纹会被拒绝。

> 安全上限：单脚本/源码文件 ≤ 2MB，仅接受 `js/mjs/css/json/html/svg` 文本资源。
>
> ⚠️ 当前阶段插件仅支持 **JSON 格式**（本地目录扫描）。原「Git 仓库链接导入」功能已剥离封存，详见 `docs/技术支持/代码片段-Git导入封存.md`。

## 三、工作区「📄 代码 / ✨ 效果」双卡

选中插件后，右侧工作区提供两个选项卡：

### 📄 代码
- 散落脚本 / 酒馆助手：直接只读展示 `content` 源码
- 扩展工程：左侧文件树 + 右侧源码查看器，点击文件按需读取

### ✨ 效果（沙箱模拟酒馆）
「效果」页在 `iframe sandbox="allow-scripts"`（**无 `allow-same-origin`**）内加载一个**宿主桩**（`js/plugins/hostStub.js`），模拟酒馆运行环境，让插件脚本渲染出悬浮球/按钮/面板。

宿主桩提供：
- 迷你 jQuery 兼容层（`$`/`jQuery`：DOM 增删查改、事件、ajax stub）
- `eventSource` 事件发射器 stub
- `SlashRunner.registerCommand` / `extension_settings` / `saveSettingsDebounced` / `getRequestHeaders` 等全局 stub
- `GM_*` userscript 空实现
- 内存版 `localStorage`（data: URL 沙箱下原生 localStorage 会抛 SecurityError）
- 宿主 DOM 骨架（`#chat` / `#options` / `#right-nav-panel`）

## 四、效果预览的限制（诚实说明）

「效果」页是**尽力模拟**，不等同于真实酒馆：

1. **依赖真实酒馆内部 API 的插件可能无法完整运行**：宿主桩只覆盖常用表面，深度依赖酒馆内部对象（如聊天消息模型、角色数据总线、扩展加载器）的脚本可能报错或无输出。
2. **网络请求被阻断**：`sandbox` 无 `allow-same-origin`，且 `$.ajax` 为 stub，插件无法真正联网。
3. **仅预览 UI 层**：能真实反映「注入 DOM → 出现悬浮球/按钮 → 点击弹面板」的 UI 基线；复杂逻辑需在真实酒馆验证。

> 判据：以「点开悬浮球/按钮能出现面板」作为真度基线；超出该基线的深度交互需在真实 SillyTavern 中验证。

---

## 五、安全设计

- 所有插件脚本只在 `sandbox="allow-scripts"` 的 iframe 内运行，隔离 origin，无法触碰主应用
- 主进程 IPC 全部带路径白名单（`isPathAllowed`）校验
- Git 下载解压防路径穿越；源码读取仅限文本类型 + 体积上限
- 插件实体存放在用户自选目录，`app_config.json` 仅存目录路径与来源 URL
