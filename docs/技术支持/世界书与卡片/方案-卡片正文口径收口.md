## 一、既有承诺 vs 现状（三条全有缺口）

| # | 既有承诺 | 现状（2026-09-25 实测/源码） | 缺口性质 |
|---|---|---|---|
| 1 | 查重**差异比对**要用正文 ⇒ 不能被砍成静默变差 | 差异比对**读到空正文**：用户截图满屏「（无正文）」，匹配上的词条显示「一致」实为"两边都空"；查重收尾会把读回的正文**交还**（重新瘦身），而比对器只对**独立世界书**做了懒加载兜底，**对卡片没有** | **承诺未兑现**（AR-51 补充 / PK-31-①） |
| 2 | 保存**不得把卡写空** | 保护只在"打开卡"这一条路（`ensureCardFull` + 读失败拒开）；**批量贴标签 / AI 打标落盘**走 `persistCardUpdate` → `file:saveCard`，传的是**瘦身态 payload**：实测 `- juus - (2).png` = **54 条词条 / 非空 0 条**，`main.js` 侧**原样内嵌、不与磁盘比对** ⇒ 一次贴标签即抹掉整本书（抽样 163 张可解析卡：**目前 0 张中招**，路径已通） | **承诺只覆盖了一条路**（PK-32） |
| 3 | 「全局资产库是**唯一**需全库正文的面板」 | 「唯一」假设在**全库词条搜索**上线后失效：`useGlobalEntrySearch.refreshGlobalEntryIndex` 世界书侧调了 `ensureWorldbookLoaded`、**卡片侧没调** ⇒ 卡片词条正文**搜不到** | **假设失效 + 无守卫**（PK-31-②） |

**同一类病的第 4 处**（非懒加载专属，但同属"多处口径各自为政"）：
`ContentDedupeModal.vue:104` 的徽标**内联硬编码**（`_simPct >= 98 ? '几乎完全一致' : '高度相似，细节有差异'`
⇒ **9% 也显示"高度相似"**）；`resolveContentDedupeGroup` **没有** AR-48 那套风险防护（AR-52）。

## 二、收口：一条入口 · 一道出口闸门 · 一套守卫

### A. 读侧 —— **一条入口**（替代"各自注入 / 各自记得"）

`js/utils/cardSlim.js` 升级为**注册式**（与 `js/utils/dedupeBusy.js` 同款：模块级普通变量，**刻意不用 ref**，避免跨段落 TDZ）：

```js
setCardBodyLoader(fn)           // App.vue 启动时注册唯一加载器（原地替换现有逐处注入）
ensureFullBody(items, opts)     // 任何模块可调用；缺加载器 ⇒ 告警（绝不静默返回空）
                                //   opts.giveBack ⇒ 用完只把"我读回的"重新瘦身（交还内存）
hasCardBodyLoader()             // 供守卫/降级提示使用
```

- 迁移：`useDedupe`（改用统一入口，**差异比对前** `ensureFullBody([master, compare])`）、
  `App.vue` 全局资产库（改用统一入口）、**新增**全库词条搜索（打开→还原→索引；关闭→交还）。
- **同步路径的诚实降级**（`useSearch` 的 `wb:` 过滤 + `extractCardSearchableText` 兜底，不能 await）：
  走**索引文本**（PK-16 修好后索引保持完整态）；索引不可用时**显式提示"按触发词筛选"**，不假装按正文筛过。

### B. 写侧 —— **一道出口闸门**（不依赖前端记得，落在唯一落盘点）

`main.js file:saveCard` 保存前做**正文退化检测**：

```
读磁盘现有卡（PNG 内嵌块 / JSON）→ oldNonEmpty（有正文的词条数、alternate_greetings 条数）
传入 payload                      → newNonEmpty
if (oldNonEmpty > 0 && newNonEmpty === 0) ⇒ 拒绝写入 + 明确报错（原文件不动）
```

- 与既有风格一致：保存前快照失败已"中止保存"（`main.js` 现文），本闸门是同一思路的第二种退化。
- 覆盖 PNG / JSON / WebP 三条分支（都在同一个 handler 内）。
- **同时**在渲染层 `persistCardUpdate` 保存前 `ensureFullBody(cardItem)`（双保险：前端拿全、后端拒空）。

### C. CI —— **一套守卫**（防第四处、第五处）

1. **`scripts/check-card-body-guard.mjs`**（接 `npm run guard:card-body`）：
   凡源码出现 `character_book` / `alternate_greetings` 的文件**必须在白名单里并标注处理方式**
   （`ensure` / `current-card`（只读当前打开的卡）/ `index-earlier`（早于瘦身的索引期）/ `slimmer` / `save-guard`），
   新文件未登记 ⇒ **fail**。
2. **文案守卫**：用户可见的相似度文案必须来自同一模块；模板内联条件文案由断言拦下（并入 `test/similarityType.test.mjs`）。
3. **清理守卫**：四条 `resolve*Group` 必须走统一 `confirmCleanupWithRisk()`（源码断言）。

## 四、验收标准（可测；含接手 PK-16 的 ⬜ 项）

1. **写侧（隔离库，写操作必用隔离库）**：真·有正文的卡复制到临时库 → 用**瘦身态 payload** 调 `file:saveCard`
   ⇒ **必须被拒**（`success:false` + 明确原因），**磁盘文件 SHA-256 不变**；用**完整 payload** ⇒ 正常写入。
2. **读侧（真实 11k 库热测）**：秋青子那对 → 「查看内容差异」两侧**显示真实词条正文**（推荐版 12 条非空），
   不再出现「（无正文）」「本端无此词条」的空结论。
3. **接手 PK-16 的 ⬜**：瘦身库上**世界书词条正文关键词能被搜索命中**（全库词条搜索 + 主搜索 `wb:` 各测一次），
   并给出实测数字（命中条数）。
4. **守卫有正向对照**：故意去掉一处 `ensureFullBody` / 新增一个未登记文件 ⇒ `guard:card-body` **变红**；
   恢复后全绿。
5. **不变式**：徽标与百分比同档（9% 不得说"高度相似"）；`100%` 提醒不得含"无关/不同"；
   四条 `resolve*Group` 均调用 `confirmCleanupWithRisk`。
6. `npm test` 全绿 + `npm run build:web` + 真实启动冒烟（`npx electron . --disable-gpu --enable-logging`）。

## 五、为什么这次不是"许愿"（对照既有教训）

| 既有做法（许愿式） | 本方案 |
|---|---|
| 承诺"查重差异比对要用正文"，靠**注释**提醒 | **差异比对入口强制 `ensureFullBody`** + 守卫白名单登记 |
| 保护写空只做在**开卡**一条路（其余靠"记得"） | **主进程出口闸门**：正文集体变空**直接拒写**（前端漏了也拦得住） |
| 假设"全局资产库是**唯一**需全库正文的面板" | **注册式入口 + CI 守卫**：新面板不登记即红，假设失效不再靠人记 |
| 多处各写各的文案/防护 | **单一文案源 + 统一 `confirmCleanupWithRisk`**，断言锁死 |
