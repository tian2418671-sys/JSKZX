## 一、🎴 移动版「测卡」引擎移植到桌面版（P1 · 大工程）

### 目标
把移动版已经成熟的**测卡链路**（宏替换 / 变量 / EJS / 正则 / 预设装配 / 分段渲染 / 插件钩子 / Swipe / 会话管理）搬到桌面版，
替换桌面版现有的简陋实现 [`js/composables/useChat.js`](../js/composables/useChat.js)（仅 205 行）。

### ✅ 可行性结论（已完成调研）

| 层 | 移动版位置 | 规模 | 结论 |
|---|---|---|---|
| **引擎（逻辑）** | `js/mobile/useChat*.js`（12 个） | ≈ 2200 行 | ✅ 基本可原样搬 |
| **渲染组件** | `js/mobile/components/ChatPanelSeg.vue` | 106 行 | ✅ 纯 Vue + scoped CSS，可直搬 |
| **配置侧栏（UI）** | `js/mobile/components/TestSidebar.vue` | 819 行 | ⚠️ **必须重写**（全是 Vant 组件） |
| **编排（总装）** | `js/mobile/views/CardDetailView.vue` 测卡段 | ≈ 600 行 | ⚠️ 需按桌面架构改写接线 |

**三个关键发现（决定了迁移成本远低于预期）**

1. **12 个引擎文件里只有 2 个有 import** —— `useChatApiConfig.js`、`useChatMemory.js`，且都只依赖 `bridge/api.js`；
   其余 10 个是**纯函数**（`buildMacroContext` / `applyRegexScripts` / `renderEjs` / `getOrderedPrompts` …），零外部耦合。
2. **移动版桥接层本就是双端自适应** —— `js/bridge/api.js` 里 `export const api = isCapacitorNative ? androidImpl : electronImpl`，
   而 `bridge/electron.js` 只有 31 行，内容即 `export const electronImpl = window.electronAPI`
   → **桌面端天然就是它的原生实现**，这套代码当初就按「桌面也能跑」设计。
3. **两版已在共享代码** —— 移动版测卡已引用桌面版的 `composables/useStatusbarPreview.js`、`utils/tokenEstimate.js`、`utils/statusbarTemplates.js`，
   迁移不会遇到两套体系打架。

### 🚧 唯一真正的缺口

| 缺口 | 说明 | 处理方式 |
|---|---|---|
| `api.memoryAdd / memoryUpdate / memoryRemove / memoryClear / memoryList / memorySearch` | 移动版走 **Android 原生 SQLite（MemoryPlugin）**，桌面无对应实现 | ①桌面用本地 JSON 落盘实现一套（推荐，复用 `atomicWriteJson`）；②或先移植但**记忆 Tab 置灰**（代码内已有 try/catch 降级，不会崩） |
| Vant UI 组件库 | 移动端专属 | 用桌面端 Tailwind 三栏布局重写 |

### ⚠️ 技术风险与坑（提前记下）

- 桌面端 `window.electronAPI` **被 contextBridge 冻结**（`configurable:false / writable:false`），
  **不能 mock、不能改写**；`chatBridge.js` 已按「展开复制 + 逐方法兜底」处理。
- 桌面版是 **Vue 3 Options API + `provide('appCtx')`** 架构，移动版是 `<script setup>` + Vant，
  接线时要转成 ctx 注入风格，不要照抄移动版写法。
- 移动版引擎里用了 `localStorage`（如 `jsmobile-memory-enabled`）——桌面生产环境 `app://` 下 localStorage **不持久**，
  需改走 `app_config.json`（项目已有统一持久化中枢）。
- 引擎文件若引用了移动版专属工具（`utils/` 下），需逐个替换为桌面版同名实现或复制一份。

   - **现状体检**：渲染层 `js/**` 已被 Vite 压缩 + 变量名 mangle + 无 sourcemap（🟡 asar 可解包，格式化后仍可读）；
     但 **主进程 `main.js`（4025 行 / 196KB）、`preload.js`（207 行，89 个 IPC 通道名）、`main/*.js` 全是明文**（🔴 核心逻辑一览无余）；

   - ⚠️ **根本限制**：仓库为 **PUBLIC + MIT**，而 MIT 本就允许他人复制 / 修改 / 分发（只要保留版权声明）

     另需知：JS 无法绝对防护（asar 可解、内存可 dump、混淆可被反混淆），混淆的意义是「把 5 分钟变成几小时」。
   - **可选手段（本次未做）**：
     ① 主进程混淆（`javascript-obfuscator`）；⚠️ 必须保持**文件名与目录结构不变**——`preload.js` 与 `main.js` 同目录（`path.join(__dirname,'preload.js')`）、

        对象字面量键名与字符串通道名默认不被改动，IPC 不会失效；建议关掉控制流扁平化（主进程 4025 行，会明显拖慢启动）。
     ② 生产禁用 DevTools + 剔除 `console`；③ `signAndEditExecutable` 接证书做代码签名（当前为 `false`）；
