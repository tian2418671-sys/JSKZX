# 一键安装桌面版酒馆 · 实现方案（v1 · 待评审，暂不执行）

> 目标：让本软件从「管理已有资源」升级为「**也能把酒馆装起来、管起来、卸干净**」，名副其实地叫「管理器」。
>
> 本文只做方案设计，**不含任何代码改动**。评审通过后再分批施工。

---

## 一、需求原文与拆解

用户原话：

> 增加一个一键安装桌面版酒馆功能
>
> 1. 进行傻瓜式的安装操作到用户机器上，提供给本地酒馆升级/卸载/删除功能
> 2. 安装时自动安装配套的酒馆支持软件
> 3. 这个入口在工具菜单中增加一个入口，点击后弹出对话框界面，在界面里操作
> 先写个方案出来不执行
> 这样才能称之为管理器

拆成 4 件事：

| # | 需求 | 本质 |
| --- | --- | --- |
| R1 | 一键安装桌面版酒馆 | 下载 + 解压 + 装依赖 + 可选启动 |
| R2 | 本地酒馆的 升级 / 卸载 / 删除 | 生命周期管理（含数据保全） |
| R3 | 安装时自动装「配套支持软件」 | 运行时依赖（Node.js、Git、可选扩展） |
| R4 | 工具菜单入口 + 对话框界面 | 一套完整的 UI 流程 |

## 三、总体设计

### 3.1 安装产物布局

```text
<用户选择的安装目录，例如 D:\SillyTavern>
├── SillyTavern/              ← 酒馆本体（git 仓库或 zip 解包）
│   ├── server.js
│   ├── package.json
│   ├── node_modules/         ← npm install 产物
│   ├── data/                 ← 用户数据（角色卡/聊天/设置）
│   ├── public/
│   └── config.yaml
└── _jsk-runtime/             ← 本软件托管区（不侵入酒馆仓库）
    ├── runtime.json          ← 安装清单：版本、来源、时间、依赖状态
    ├── logs/                 ← npm install / server 输出日志
    └── backups/              ← 升级前自动快照（可选）
```

**为什么不直接把运行时文件塞进酒馆目录**：

- 酒馆有 `.git`，随意新增文件会污染工作区，用户 `git status` 会看到一堆无关文件
- 卸载时能**整体删除 `_jsk-runtime`**，干净利落

### 3.1.1 代码来源：官方 GitHub + 镜像

**决策**：主源官方 GitHub，失败自动切镜像。

| 优先级 | 来源 | 地址 | 说明 |
| --- | --- | --- | --- |
| **主** | 官方仓库 | `https://github.com/SillyTavern/SillyTavern` | 官方唯一权威源 |
| **备 1** | GitHub 镜像加速 | 如 `ghproxy` 类前缀服务 | 国内直连慢时使用 |
| **备 2** | 用户自定义 | 输入框填写 | 高级用户自备源 |

**下载地址**（与插件安装复用同一套逻辑）：

```text
主源 zip:  https://codeload.github.com/SillyTavern/SillyTavern/zip/refs/heads/release
           ↑ release 是酒馆的稳定分支（main 是开发分支，不建议给普通用户）
镜像 zip:  <镜像前缀> + 上述地址
```

**切换规则**：

1. 主源 30 秒内无响应或失败 → 自动切备 1
2. 备 1 仍失败 → 提示用户「可换镜像或稍后重试」
3. **绝不静默失败**，每次切换都要在日志里留痕

**版本选择**：

| 选项 | 分支 | 适用 |
| --- | --- | --- |
| **稳定版**（默认） | `release` | 绝大多数用户 |
| 开发版 | `main` | 想尝鲜的用户，需显式勾选并警告「可能不稳定」 |

### 3.1.2 安装路径：用户自定义

**决策**：首次安装让用户选目录，之后记住。

| 规则 | 说明 |
| --- | --- |
| 默认建议值 | `D:\SillyTavern`（若 D 盘存在）；否则 `%USERPROFILE%\SillyTavern` |
| 记住上次 | 写入本软件配置 `lastStInstallDir`，下次自动带出 |
| 可随时更换 | 弹窗里可改；改后重新检测该目录状态 |
| 路径校验 | 见下表 |
| 不推荐系统盘 | 若选 `C:\Program Files` 等受保护目录，提示「可能需要管理员权限」 |

**路径合法性校验**（安装前必做）：

| 检查 | 不通过时的处理 |
| --- | --- |
| 路径非空 | 拒绝 |
| 盘符存在 | 拒绝 |
| 目标目录为空 **或** 不存在 | 通过 |
| 目标目录非空但**不含酒馆特征** | 警告「目录非空，确定要装到这里吗？」 |
| 目标目录**已含酒馆** | 不安装，转为「已检测到酒馆」状态 |
| 路径深度 < 200 字符 | 警告 Windows 长路径限制 |
| 路径不含特殊字符（`&` `%` `!` 等） | 警告，可能影响 npm |
| 磁盘剩余空间 ≥ 5GB | 拒绝并提示所需空间 |

### 3.2 状态机（决定 UI 显示哪个按钮）

```text
        ┌──────────┐
        │ notFound │  所选目录没有酒馆
        └────┬─────┘
             │ 一键安装
             ▼
        ┌──────────┐
        │installing│  下载 → 解压 → 装依赖
        └────┬─────┘
             │ 成功            │ 失败
             ▼                 ▼
        ┌──────────┐      ┌────────┐
        │  ready   │◄─────│ failed │（可重试/回滚）
        └────┬─────┘      └────────┘
             │ 启动 / 停止        ▲
             ▼                    │
        ┌──────────┐              │
        │ running  │──────────────┘
        └────┬─────┘
             │ 检测到新版本
             ▼
        ┌──────────┐
        │updatable │──升级──┐
        └──────────┘        │
                            ▼
                       （回到 ready）
```

卸载/删除是独立动作，任何状态都可触发（但需二次确认）。

### 3.3 「两档卸载」——危险操作，必须极其谨慎

**决策（2026-11-15 用户拍板）**：卸载分**两档**。

| 档位 | 名称 | 删除范围 | 保留 |
| --- | --- | --- | --- |
| **① 只删酒馆** | 移除酒馆本体 | 酒馆目录（含 `data/`、`node_modules`） | 本软件自身 |
| **② 彻底删除** | 连软件一起清 | ① ＋ 本软件 userData ＋ 注册表项 ＋ 开始菜单快捷方式 ＋ 桌面图标 | **无** |

**关键：两档都要清理「酒馆目录以外」的残留**（用户明确要求）。

#### ① 只删酒馆 —— 清理范围清单

| # | 目标 | 路径 / 键 | 说明 |
| --- | --- | --- | --- |
| 1 | 酒馆程序 | `<安装目录>\SillyTavern\` | 含 `public` / `src` / `node_modules` |
| 2 | 酒馆数据 | `<安装目录>\SillyTavern\data\` | **角色卡/世界书/聊天**（本机 3.3GB、49 卡） |
| 3 | 酒馆配置 | `<安装目录>\SillyTavern\config.yaml` | |
| 4 | 托管区 | `<安装目录>\_jsk-runtime\` | 安装清单、日志、备份 |
| 5 | 注册表（若我们写过） | `HKCU\Software\SillyTavern` 等 | 仅删除**本软件创建**的键 |

#### ② 彻底删除 —— 在 ① 之上追加

| # | 目标 | 路径 / 键 | 说明 |
| --- | --- | --- | --- |
| 6 | 本软件数据 | `%APPDATA%\sillytavern-card-manager\` | 配置、缓存、记忆库（1.05GB） |
| 7 | 软件安装目录 | 本软件自身安装路径 | **无法自删**，需交给 NSIS 卸载程序（见 3.3.2） |
| 8 | 注册表卸载项 | `HKCU\...\Uninstall\<本软件>` | NSIS 卸载时会处理；若残留则补删 |
| 9 | 开始菜单 / 桌面快捷方式 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\` 等 | |
| 10 | 计划任务 / 开机自启 | 若有注册，一并移除 | |

#### 3.3.1 必须规避的误删（实测发现）

⚠️ **注册表里可能存在「由 Chrome 安装的 SillyTavern PWA」**：

```text
HKCU\...\Uninstall\990925d41f01490b5f394802c777ecfd
  DisplayName    = SillyTavern
  Publisher      = Google\Chrome      ← 不是酒馆本体！
  UninstallString= chrome.exe --uninstall-app-id=...
```

这是用户在 Chrome 里「安装应用」生成的**网页快捷方式**，与本地酒馆毫无关系。

**卸载逻辑必须校验 `Publisher` / `UninstallString`**：

- 只有 `Publisher` 含 `SillyTavern` 或 `UninstallString` 指向我们安装的酒馆路径，才允许删除
- 遇到 `Publisher = Google\Chrome` 一律**跳过并记录**，绝不触碰

#### 3.3.2 「删除自己」的正确做法

程序**无法删除自己正在运行的可执行文件**。两种可行方案：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 交给 NSIS**（推荐） | 清理外围数据后调 `Uninstall.exe /S` 并退出 | 官方机制，能删干净自身 | 需先清理数据 |
| **B. 延迟自删脚本** | 生成临时 `.bat`，等进程退出后删除目录 | 不依赖安装包结构 | 杀软可能拦截，可靠性较差 |

**采用 A**：`electron-builder` 的 NSIS 产物自带 `Uninstall <产品名>.exe`。

#### 3.3.3 二次确认（两档都强制）

卸载弹窗必须显示**具体数字**，而不是“确定要删除吗”这种空话：

```text
⚠️ 将删除以下内容（不可恢复）：

  酒馆目录    D:\SillyTavern\SillyTavern        2,341 MB
    ├─ 角色卡   49 张
    ├─ 世界书   12 本
    ├─ 聊天记录 47 个会话
    └─ 依赖     node_modules

  托管区      D:\SillyTavern\_jsk-runtime           18 MB
  [彻底删除时追加]
  软件数据    C:\Users\Tk\AppData\Roaming\...    1,049 MB
  软件本体    C:\Program Files\...                 320 MB

  合计                                    3,728 MB

☑ 先打包备份酒馆 data/ 到：
     D:\SillyTavern_Backup_20261115.zip（预估 1.2 GB）

请输入 DELETE 确认：__________

              [取消]  [确认卸载]
```

**设计要点**：

1. **每项都列绝对路径 + 实际体积**（安装时统计一次，卸载时再测一次）
2. **数据分类计数**（卡/书/聊天），让用户意识到“这里有 49 张卡”
3. **备份默认勾选**，且备份路径可见可改
4. **必须手输 `DELETE`**，不接受点一下按钮
5. 备份成功前**不执行任何删除**
6. 逐步删、每步报进度；某项失败**继续删其余项**并汇总报告

#### 3.3.4 删不掉的项要如实报告

卸载完成后给出结果清单，不能只说“完成”：

```text
✅ 已删除：酒馆目录（2,341 MB）
✅ 已删除：托管区（18 MB）
✅ 已备份：D:\SillyTavern_Backup_20261115.zip
⚠️ 跳过：注册表项 990925d4...（属于 Chrome PWA，非本软件创建）
❌ 失败：C:\...\logs\crash.log（文件被占用）
   → 请关闭程序后手动删除，或重启电脑再试
```

### 3.4 升级策略

| 方式 | 优点 | 缺点 | 采用 |
| --- | --- | --- | --- |
| `git pull` | 增量、快、有历史 | 要求装 Git；本地改动会冲突 | 有 `.git` 时优先 |
| zip 覆盖下载 | 无需 Git | 全量；需小心不覆盖 `data/` | 无 `.git` 时兜底 |

**统一前置动作**：升级前把 `data/` + `config.yaml` 复制到 `_jsk-runtime/backups/<时间戳>/`，失败可一键回滚。

### 3.5 配套支持软件（R3）

| 依赖 | 是否必需 | 处理方式 |
| --- | --- | --- |
| **Node.js 20+** | 必需 | **不内置**。检测系统 Node；缺失时一键 winget 安装 |
| **Git** | 可选 | 有则用 `git pull` 升级；无则用 zip 覆盖 |
| **Visual C++ 运行库** | 部分依赖需要（如 `sharp`） | 检测失败时提示手动安装 |
| **酒馆常用扩展** | 可选 | 安装完成后问「要不要顺手装 XX 扩展」 |

#### Node.js：不内置，用「检测 + 一键装」代替

**决策（2026-11-15 用户拍板）**：不内置 Node，避免安装包膨胀。
安装包体积维持在约 120MB，不上涨。

替代方案分三层，按顺序尝试：

| 层级 | 场景 | 动作 | 用户感知 |
| --- | --- | --- | --- |
| **L1 检测** | 系统已装 Node 20+ | 直接使用，路径记入 `runtime.json` | 无感 |
| **L2 winget** | 未装但有 `winget` | `winget install OpenJS.NodeJS.LTS` | 确认一次后自动 |
| **L3 引导** | 无 `winget`（老旧/精简系统） | 打开 Node.js 官网，显示图文步骤 | 需手动装一次 |

**为什么 winget 是最优解**：

- Windows 10 1809 起内置，Win11 全覆盖
- **不增加任何安装包体积**
- 官方源，安全可追溯，支持静默安装
- 装完自动配好 `PATH`

**版本检测规则**（必须严格，否则装完跑不起来）：

```text
node -v  →  v25.2.1
             ↓ 解析主版本号
          主版本 >= 20  →  ✅ 通过
          主版本 <  20  →  ⚠️ 版本过低，提示升级
          命令不存在    →  ❌ 未安装，走 L2
```

**必须注意的坑**：

- `winget` 装完 Node 后，**当前进程的 `PATH` 不会更新**。
  需重新读取系统环境变量，或直接用绝对路径 `C:\Program Files\nodejs\node.exe` 调用。
- `winget` 首次运行可能弹 UAC；用 `--accept-package-agreements` 可免协议交互，但权限弹窗无法绕过。
- 用户取消或失败时，**降级到 L3 引导，绝不假装成功**。

**要点**：

- 切换档位时，“合计”实时变化
- 备份仅针对酒馆 `data/`；本软件自身数据不备份（用户应已有配置）
- “彻底删除”需额外勾选「我已知悉，此操作不可恢复」

## 五、技术实现要点

### 5.1 主进程新增 IPC（草稿）

| IPC | 作用 | 关键校验 |
| --- | --- | --- |
| `st:detect` | 检测目录下是否已有酒馆、版本、依赖状态、是否运行中 | 目录必须存在 |
| `st:install` | 下载 + 解压 + 装依赖（流式进度） | zip 体积上限、路径白名单 |
| `st:update` | 升级（git pull 或 zip 覆盖） | 升级前自动备份 |
| `st:installDeps` | 仅重装依赖 | 用打包内置 Node |
| `st:start` / `st:stop` | 启停 server.js | 端口占用检测 |
| `st:uninstall` | 两档卸载（模式 1 / 2） | 显式传档位 + 确认串 + 注册表 Publisher 校验 |
| `st:addRemoveInventory` | 卸载前列出将删除的全部项与体积 | 只读，供弹窗展示 |

### 5.2 「傻瓜式」的几个细节（决定成败）

| 细节 | 处理 |
| --- | --- |
| **解压后多一层目录**（`SillyTavern-release`） | 复用 `pickPluginRoot()` 的思路：按内容找真正的根 |
| **npm install 很慢（3~10 分钟）** | 必须流式输出 npm 日志 + 进度条 + 可取消；不能做成"卡死" |
| **网络慢/失败** | 支持镜像源切换（淘宝源）；失败可重试 |
| **端口 8000 被占用** | 启动前检测，提示换端口 |
| **路径含中文/空格** | 全流程用 `spawn` + 参数数组，绝不拼接命令行字符串 |
| **Windows 长路径限制** | 提示用户不要装到超深目录 |
| **杀毒软件拦截** | 提示"若失败请检查杀软" |
| **安装中途关闭软件** | 留下 `_jsk-runtime/installing.flag`，下次启动提示"上次安装未完成" |

### 5.3 安全与边界

- 下载仅允许 `https`，来源限定 `github.com/SillyTavern/SillyTavern`（可配置镜像）
- 所有写操作限制在「用户已确认的安装目录」内
- `npm install` **不执行**任意脚本（`--ignore-scripts`），除非用户明示需要（部分依赖要编译）
- 卸载的路径校验：必须包含 `package.json` 且 `name === 'sillytavern'`，否则拒绝（防手滑删错目录）

## 七、分期实施建议

### 第一期：检测 + 安装 + 启动（核心闭环）

- 「检测」：识别已有酒馆（版本/依赖/运行状态）
- 「一键安装」：下载 → 解压 → 装依赖 → 进度条 → 完成
- 「启动/停止」
- 不做升级、不做卸载

**验收**：在一台**没装过酒馆**的机器上，从零到能打开 `http://localhost:8000`。

### 第二期：升级 + 卸载

- 「升级」：git pull / zip 覆盖 + 升级前备份
- 「卸载」：两档（只删酒馆 / 彻底删除）＋ 强制备份 ＋ 注册表校验
- 「重装依赖」

**验收**：装好 → 升级到新版本 → `data/` 完好；卸载后磁盘无残留。

### 第三期：配套软件与体验

- 内置/下载 Node
- 可选扩展一键装
- 日志导出、安装失败诊断

## 附：为什么这件事值得做

现在用户要装酒馆，得自己：

1. 找官网 / GitHub
2. 装 Node.js，配环境变量
3. 装 Git，clone 仓库
4. 命令行 `npm install`，看着几百行输出
5. 遇到报错自己查

**这五步劝退了绝大多数普通用户。**

做完这个功能，用户只需要：点「工具 → 酒馆安装与维护」→ 选目录 → 点「一键安装」→ 等进度条 → 点「启动」。
