## 一、 Q1 ~ Q7 逐条正式拍板

### Q1 · 真 jQuery 注入方式：选「单独打轻量包」还是「复用 `chat-host.js`」？
* **上游拍板**：**存在两种零副作用方案，优先推荐【方案 1（单独轻量包）】或【方案 2（同包去 Vue 污染）】**。
* **源码事实与落地建议**：
  查看 `js/chatHost/iframeGlobals.js` 可知，它总共只有 50 行代码：
  - **为什么有 559KB 且污染 `Vue`**：因为它第 5 行 `import * as Vue from 'vue'`，把整个 Vue 3 运行时打进去了。
  - **怎么处理（二选一，下游定）**：
    1. **新建 `js/chatHost/pluginHostGlobals.js`**（只 import `jquery` 和 `lodash`，挂 `window.$` / `window.jQuery` / `window._`，不挂 `Vue`，约 110KB），在 `package.json` 的 `build:chat-host` 旁加一条 esbuild 命令产出 `vendor/plugin-host.js`。
    2. **或者关于 `waitGlobalInitialized`（Q1-b）**：插件调 `waitGlobalInitialized('Mvu')` 本来就是为了等宿主全局变量就绪后继续跑初始化逻辑，在预览沙盒里**立即 resolve 是预期行为**（否则插件永远 await 卡死在第一步）。只要在它之前把 `TavernHelper` 桩挂好，立即 resolve 反而是让插件跑下去的关键！

### Q2 · 自动事件脉冲：是否只发「初始化三件套」，消息类事件改为手动触发？
* **上游拍板**：**完全同意！**
* **执行口径**：
  1. **载入后自动广播（仅初始化语义）**：只按序触发 `APP_READY` → `SETTINGS_LOADED` → `CHAT_CHANGED`。
  2. **手动按钮触发（消息/生成语义）**：`CHARACTER_MESSAGE_RENDERED` 与 `MESSAGE_RECEIVED` **绝不自动触发**，交由预览栏顶部的 `[💬 模拟收到 AI 消息]` 按钮手动触发。这样既消除了自动请求 LLM 的副作用，又能让用户清楚感知“点一下按钮 → 插件处理了一条消息”的动态过程。

### Q3 · 测卡工作区的桩复用：接受「共用字符串源、不做函数化重构」吗？
* **上游拍板**：**完全接受！千万不要做耗时 1~2 天的函数化重构。**
* **执行口径**：
  1. 直接把 `useChatSandbox.js` 里生成 `SillyTavern` / `TavernHelper` / `getvar` / `setvar` 的那段模板字符串提取为公共常量（例如放在 `js/utils/sandboxStubSource.js`）。
  2. 在插件预览环境注入前，在最前面垫一层默认的空壳底座：`window.__jskVars = { chat: {}, character: {}, global: {} }; window.__jskChatStore = [];`，让那段字符串代码在插件预览里也能零报错跑通，无需改动测卡工作区的既有逻辑。

### Q4 · 「一键带入测卡工作区」的挂载语义
* **上游拍板**：**完全同意下游方案——先只做「酒馆助手脚本 → 当前/新建测试会话（临时挂载）」这一条链路！**
* **执行口径**：
  1. **挂载生命周期**：**临时（Session 内存态）**，仅在当前测卡会话生效，顶部显示一条黄色提示条 `🧪 当前正在临时测试插件：[插件名]（关闭或切换会话后自动卸载）`，绝不静默污染用户的全局配置。
  2. **支持范围**：仅对「酒馆助手脚本 / JS 脚本」开放此按钮；扩展工程、UI 主题等其余类型置灰或提示「该类型不支持测卡沙盒挂载」。
  3. **无会话兜底**：若当前测卡工作区未打开任何角色卡，点击后弹出轻提示：「请先在角色卡库选择一张卡片进入测卡工作区，再挂载此插件」（或直接自动拿默认预置卡新建临时会话，哪个好写用哪个）。

### Q5 · 「静态能力透视卡」的展示前提
* **上游拍板**：**100% 确认「透视卡绝不阻止沙盒渲染尝试」！**
* **执行口径**：
  - 永远**先跑沙盒渲染**。
  - 只有在 **2 秒空白自检判定为“未产出可见 DOM 变化”** 时，才把原本干瘪的“空白诊断提示”升级为这张「静态能力透视卡」（展示它监听了哪些 `event_types`、调用了哪些 `TavernHelper` API、以及一键带入测卡按钮）。
  - 如果渲染出了可见界面，也可以在顶部工具栏放一个小图标 `[ℹ️ 透视]` 供用户随时点开看，做到零误杀。

### Q6 · 「自动聚焦非聊天挂载点」的实现方式
* **上游拍板**：**完全同意！用「顶部挂载点导航条 + 点击平滑滚动/高亮」代替移动 DOM。**
* **执行口径**：
  1. **绝不移动 DOM 节点顺序**，避免破坏插件依赖的父子层级 CSS 选择器。
  2. **怎么算有内容**：在插件脚本执行前记录各挂载点（`#chat`、`#extensions_settings`、`#extensions_settings2`、`#extensionsMenu`、`#leftSendForm`）的 `innerHTML.length` 与 `childElementCount`；执行后（含 500ms 延迟）对比，凡是**非空且发生变化**（或新增可见高度 `offsetHeight > 0`）的挂载点，在预览区顶部浮现导航胶囊：
     `📍 检测到插件界面已注入：[ 💬 聊天区 (1) ]  [ ⚙️ 扩展设置 (2) ]  [ 🪄 魔法棒菜单 (1) ]`
  3. 用户点击胶囊，直接 `scrollIntoView({ behavior: 'smooth' })` 并给对应容器加一个 1.5 秒的呼吸高亮外框。若 `#chat` 没变化而 `#extensions_settings` 有变化，自动滚到 `#extensions_settings`。
